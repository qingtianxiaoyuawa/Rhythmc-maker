# UI 改造范围再次修订：特效时间轴专用

- 日期：2026-10-01
- 用户补充：时间轴仅用于特效编辑器菜单；其他菜单需要保留原来的逻辑，但视觉效果需要重构。
- 本记录修订此前“全局工作台/全量替换旧界面”的范围，作为后续实现规划的优先依据。
- Planner 边界：本轮仅分析与规划，不修改源码、不编译、不测试、不部署。

## 最终范围判断

RhythMC Maker 不采用“所有菜单统一改成时间轴工作台”的方案。Flashback 的核心视觉只应用于**特效编辑器菜单**，因为该菜单需要时间定位、事件轨道、播放头和特效事件编辑；其他菜单仍然按照原有功能逻辑工作，只重新设计视觉层、布局层和控件表现。

因此本次改造分成两个明确方向：

1. **特效编辑器：结构和视觉都重构**
   - 新增/重做 Flashback 风格时间轴编辑布局。
   - 保留现有特效数据、事件类型、时间计算和播放调用逻辑。
   - 时间轴只属于特效编辑器，不下沉为全局 Maker 框架。

2. **其他菜单：逻辑保留，视觉重构**
   - 保留原有菜单入口、业务方法、数据读写、校验、导航和操作结果。
   - 不保留旧的拥挤布局、旧卡片、旧间距、旧颜色和旧控件组合。
   - 通过新的统一主题、布局和控件绘制方式改造视觉，不改变菜单的功能语义。

## 必须保留的原有逻辑

除非用户后续明确要求删除，其他菜单必须继续保留：

- 谱面列表、谱面创建、谱面信息读取和保存。
- 导入/导出谱面及错误提示。
- 场景导入、场景编辑、场景重置、场景删除和确认流程。
- 播放设置、播放/暂停/停止和播放失败后的清理逻辑。
- 物品选择、资源选择、文件选择和输入校验。
- `.rmcc`、`.rmcd`、`.schem` 的读写语义。
- Beat、BPM 分段、offset、速度事件和音频同步规则。
- 现有菜单之间的打开、返回、取消、确认和快捷键语义。

“保留逻辑”不等于保留旧 Screen、旧 Owo 组件或旧布局。应提取/复用业务调用，把 UI 重新绘制。

## 特效编辑器新布局

### 目标构图

```text
┌────────────────────────────────────────────────────────────┐
│ 特效编辑器菜单栏：返回 | 保存 | 播放 | 撤销/重做 | 视图      │
├──────────────────────────────┬─────────────────────────────┤
│ 中央预览区                    │ 特效属性检查器              │
│ Minecraft 场景/特效预览       │ 当前事件、颜色、参数、目标  │
│                              │ 分组折叠、单独滚动            │
├──────────────────────────────┴─────────────────────────────┤
│ 播放控制 | Beat/时间标尺 | 播放头 | 特效事件轨道 | 缩放      │
└────────────────────────────────────────────────────────────┘
```

### 时间轴职责

- 仅显示特效编辑器相关轨道和事件。
- 以 Beat 作为主要编辑坐标；秒数只作为辅助显示。
- 支持播放头定位、水平滚动、缩放、事件选择、拖动、复制、删除和新增。
- 支持按可见范围绘制事件，不能把整张长谱面所有特效一次性创建成 UI 对象。
- 事件拖动应通过既有 Beat/BPM/offset 映射更新数据，不从显示秒数反向覆盖业务时间。
- 播放控制调用现有播放逻辑，不在时间轴组件内复制音频或服务端播放实现。
- 右侧检查器只展示当前选中特效的属性；未选中时展示特效编辑器级设置。

### 特效编辑器需要重构的视觉

- 参考 Flashback：顶部薄菜单、中央预览、底部时间轴、右侧紧凑检查器。
- 使用深灰/蓝灰背景、细边界线和少量蓝色交互高亮。
- 轨道、事件、播放头和选中状态要有清晰层级，避免大面积卡片包裹。
- 特效类型可用小图标/颜色区分，但必须保留文字标签和悬浮说明。
- 长属性表单只允许右侧检查器内部滚动，不与时间轴共享滚动状态。

## 其他菜单的视觉重构方向

其他菜单不使用时间轴，但使用与特效编辑器一致的视觉主题：

### 通用布局

- 保留原有菜单的功能分组和操作顺序，但重新安排留白、列宽和控件对齐。
- 避免所有内容堆成窄长纵向列表；按“主内容区 + 辅助操作区”或“列表 + 详情”组织。
- 页面宽度随窗口调整，不能继续依赖固定居中小面板作为唯一布局。
- 普通菜单使用清晰的顶部标题/返回区、内容区、底部操作区；不强行加入时间轴。
- 复杂设置可使用统一的自有模态窗口，但模态窗口只服务当前操作，不形成多层嵌套。

### 视觉规范

- 深色低对比背景、统一面板色、细分隔线、紧凑但不拥挤的控件。
- 统一按钮高度、输入框高度、下拉框样式、复选框状态和焦点高亮。
- 蓝色只表示主要操作、选中、播放、拖动或可交互状态。
- 错误、警告、成功状态使用稳定且可区分的颜色，不直接显示冗长异常路径。
- 中文字体和英文回退沿用当前已解决的字体加载基础，但字号层级与控件密度重新设计。
- 每个页面只保留必要的滚动容器，避免外层、内容区和业务区叠加滚动条。

## Owo-lib 迁移边界

Owo 仍然按逐步移除路线处理，但迁移目标需要按菜单分类：

1. 先建立不依赖 Owo 的统一主题、控件和页面容器。
2. 先迁移视觉问题最明显且使用频率高的普通菜单，保持其原有业务逻辑。
3. 单独建立特效编辑器新 Screen，不把旧 `EffectTrackScreen` 的布局当作基础；只接入其业务数据与操作语义。
4. 再迁移场景、谱面、导入导出、选择器和确认窗口等其他菜单。
5. 每个菜单迁移完成后，删除其旧 Owo 页面和专用组件引用。
6. 全部菜单迁移完成后，删除工程内 Owo UI 源码、`BaseOwoScreen` 判断、Owo 输入分支和旧 UI helper。

迁移期间可以暂时保留未迁移菜单的 Owo 实现，但不允许新菜单继续引入 Owo，也不允许把 Owo 作为最终特效时间轴实现。

## 不应发生的范围扩张

- 不为普通谱面列表、导入导出、场景设置等菜单强行增加时间轴。
- 不把特效编辑器的轨道模型改造成全局导航或全局数据结构。
- 不因重做视觉而修改 `.rmcc`、`.rmcd`、`.schem`、BPM 或播放业务规则。
- 不机械复制 Flashback 的所有功能，只借鉴其特效编辑器的空间布局、时间轴和视觉层级。
- 不要求普通菜单全部变成同一种页面；统一的是主题和控件语言，不是强行统一布局结构。
- 不以旧 Owo Screen 的组件树作为新 UI 的约束。

## 实施优先级

### 第一优先级：新主题与普通菜单视觉基础

- 建立统一颜色、字体、间距、按钮、输入框、下拉框、复选框、分组标题、滚动区和模态窗口样式。
- 选择一个普通高频菜单作为视觉重构样板，验证新主题不会改变原有逻辑。
- 新样板完成后，按菜单逐个替换旧视觉，不需要先完成全局时间轴框架。

### 第二优先级：特效编辑器独立重构

- 新建特效编辑器布局和时间轴组件。
- 接入已有特效数据与操作方法。
- 实现中央预览、右侧属性和底部时间轴的联动。
- 完成特效添加、选择、编辑、定位、复制、删除、保存和播放相关交互。

### 第三优先级：剩余菜单迁移与 Owo 清理

- 按功能流程迁移谱面、场景、导入导出、选择器、设置和确认菜单。
- 删除对应旧 Owo Screen 和控件。
- 最后移除 Owo 源码与输入耦合，做全量引用清理。

## 验收标准

### 特效编辑器

- 只有特效编辑器出现 Flashback 风格时间轴。
- 时间轴与中央预览、右侧属性检查器联动正常。
- 播放头、Beat 定位、BPM 分段和 offset 计算保持原有语义。
- 特效编辑功能完整，不需要回到旧 Owo 页面完成常见操作。
- 长特效轨道通过可见范围裁剪保持流畅。

### 其他菜单

- 原有菜单入口、按钮动作、校验、保存、取消、返回和错误处理保持一致。
- 视觉上不再是当前拥挤、丑陋的旧界面；布局、字体、颜色、间距和控件统一重构。
- 不出现时间轴或与菜单职责无关的复杂工作台元素。
- 页面在不同窗口尺寸和 GUI 缩放下不发生重叠、裁剪或多重滚动。

### 架构

- 新代码不再引入 Owo。
- 迁移完成的菜单不再引用 Owo 类型。
- 最终所有菜单由统一的 Maker 自有 UI 层渲染，Owo 源码和输入耦合删除。
- 业务逻辑、文件格式、播放和数据映射不因视觉重构发生无关改变。

## 交给实现方的任务清单

1. 按“特效编辑器 / 普通菜单”拆分现有 Screen 和业务调用清单。
2. 先实现统一视觉主题和普通菜单容器，不创建全局时间轴。
3. 选择一个普通菜单完成视觉重构，确认原逻辑无变化后推广。
4. 新建独立特效编辑器 Screen，加入 Flashback 风格时间轴、预览和检查器。
5. 将 `EffectTrackScreen` 的业务行为逐项接入新界面，但不复用旧布局和 Owo 组件树。
6. 逐个迁移其他菜单的视觉层，保留原有业务行为和导航语义。
7. 每组菜单迁移完成后清理其 Owo 引用，最终删除 Owo UI 源码和输入判断。
8. 由编译合作方负责构建和运行时验证；Planner 不负责执行这些操作。

## 本轮结论

最终 UI 策略为：**普通菜单保留原有逻辑、重构视觉；特效编辑器采用独立的 Flashback 风格时间轴界面；不把时间轴推广到其他菜单；Owo 仅在迁移期间短暂存在，最终仍计划移除。**
