# RhythMC 3.0 歌曲、谱面、场景分项总结

日期：2026-10-18

## 1. 歌曲信息如何保存

- Reborn 本地歌曲目录为 `Data/Charts/<songId>/`，其中 `manifest.yml` 承载歌曲展示与资源关联信息。
- 在线权威数据以 Backend 数据库为准；歌曲及难度相关表数据与资源包信息用于生成歌曲 manifest 投影，投影发布到 OSS 的 `Data/Charts/<songId>/manifest.yml`。
- Reborn 在线时获取活动谱面目录/展示数据并同步资源；离线时从本地上次同步的 manifest 和缓存继续加载。
- 音频不等于歌曲 manifest，也不内嵌在谱面 JSON；它属于对应歌曲资源包/资源资产。

## 2. 谱面如何保存

- Reborn 的运行时谱面按难度分文件保存，例如 `world.rmcc`、`nether.rmcc`、`end.rmcc`、`void.rmcc`；单个文件存该难度的 `meta`、`tracks`、`effects` 等数据。
- `.rmcc` 读取兼容 Zstandard JSON 与普通 JSON：Reborn 先尝试 Zstd，再回退普通 JSON。
- Charter V2 的 `.rmcd` 是可编辑草稿 ZIP，包含模型、操作记录/快照和资源索引，不是可直接游玩的 Reborn 谱面。
- Charter V2 编译器把草稿编译为 Reborn 兼容的 `manifest.yml`、各难度 `.rmcc` 及编译报告，产物写入本地 build 目录；编译本身不代表已经上传发布。

## 3. 场景（Arena）如何保存

- Arena 是独立资源，不存放在歌曲 `.rmcc` 中。几何由 `arena.schem` 保存；展示和注册配置由 `Data/Arenas/<arenaKey>/metadata.yml` 描述。
- Backend 的 Arena 数据决定活动目录和 metadata 投影；schematic 是单独的文件资产。两者必须同时正确，才能注册并实际加载场景。
- 谱面 `meta.initialArena` 保存的是 Arena key 引用。开局优先使用该 Arena；缺省时使用服务器默认 Arena。
- 播放中的 Arena effect 可切换运行时场景实例，但这属于运行时调用，不会因此改写 Arena 文件。

## 4. 音乐、材质等资源如何保存

- 音频与资源包资产由资源包/对象存储管道管理；歌曲 manifest 中的 `respack_sha1` 是资源包关联/版本线索，不是音频数据本身。
- Reborn 开局按 song id 请求所需资源包；资源就绪后才继续启动游戏。
- Backend 资源清单和文件 hash 用于资源校验、增量同步；游戏服本地文件夹是缓存，不是线上权威存储。

## 5. 从创作到游玩的调用链

1. Charter V2 编辑并保存 `.rmcd` 草稿。
2. 编译草稿，输出 `manifest.yml`、难度 `.rmcc` 和报告。
3. 通过管理/发布流程更新 Backend 数据与文件资产；Backend 生成 manifest/metadata 投影并发布到 OSS。
4. Reborn 在线同步活动目录与资源，按校验结果更新本地 `Data/Charts`、`Data/Arenas` 缓存；离线则沿用本地缓存。
5. Reborn 反序列化并注册歌曲、难度与 Arena。
6. 玩家选歌/选难度后创建 GameInstance；加载谱面、`initialArena` 对应的 Arena 与歌曲资源包，然后进入播放。

## 6. 需要特别区分的事项

- `.rmcd` 草稿 ≠ `.rmcc` 运行谱面。
- 本地编译成功 ≠ 线上发布成功。
- `manifest.yml` 是新版后端数据库生成的投影，不应与后端数据库权威数据混为一谈。
- Arena metadata ≠ Arena 几何；`metadata.yml` 和 `arena.schem` 缺一不可。
- 本次源码中 Converter 的 Arena 输出命名为 `manifest.yml`，而当前 Reborn/Backend 契约使用 `metadata.yml`，需检查转换适配。
- 未在提供的源码快照中确认 Charter V2 保存后自动上传并部署至 Reborn 的闭环；Frontend 社区歌曲 API 也不能直接视作制谱工程发布接口。

## 证据范围

结论来自本轮提供的 Reborn、Backend、Docs、Charter V2、Chart Converter 与 Frontend 源码 ZIP。未访问线上 OSS、管理端配置和运行中游戏服文件，因此实际部署状态仍需以服务器现场为准。本轮只做 Planner 总结，未修改工程源码、未编译、未部署。
