## 一、项目目标与工程边界

RhythMC Maker 是 Minecraft Fabric 客户端模组，负责谱面编辑、特效编辑、音频播放、场景编辑和预览。项目需要持续兼容 RhythMC 3.0 / Reborn 的谱面、特效与场景格式，同时保持 Maker 本地编辑格式和 Reborn 导出格式分离。

领域边界：

- `.rmcc` 是 RhythMC 运行时谱面格式；`.rmcd` 是编辑器草稿格式；`.schem` 是场景/竞技场结构数据。
- beat 是谱面计时域；仅在音频或传输边界转换毫秒。空间坐标、音符位置、beat、BPM、总 beat 数必须按明确转换规则互相校验。
- Maker 本地谱面可包含编辑器附属数据；Reborn 导出必须严格遵循 Reborn 定义，禁止将本地字段污染导出格式。
- 正式播放、滚动播放、特效编辑器预览和世界场景预览是不同链路；某个分派入口存在不代表播放能力已完成。
- 游戏层接口优先沿用项目已有 util、manager、client、common 封装；避免客户端与服务端职责混杂。

## 二、编译、版本与交付规则

- 编译前阅读工程 `AGENTS.md`；工程采用 Java 21、Gradle、Fabric 1.21.11，源码 UTF-8。
- 版本格式为 `a.b.c`：`a` 由用户决定；新增大功能递增 `b`；每次编译递增 `c`。
- 完成构建后需校验产物，备份旧 JAR 到 `bak`，部署到 PCL 的 RhythMC 3.0 `mods` 目录，并按任务要求提交、推送 GitHub。
- 提交只包含本任务文件；不要把既有 `AGENTS.md` 修改、其他功能改动或历史 `joint_maker` 记录混入提交。
- 必须区分静态/构建验证与游戏内真实运行验证；未在游戏运行中验证时不可声称运行验收完成。

## 三、历史需求与已确认决策

### 3.1 谱面格式、导入与导出

- 2.0 谱面是旧格式，导入后需要转换为当前 3.0/Reborn 语义，再转换为 Maker 本地可编辑格式；包括药水效果、场景、持续时间、音符位置和其他旧特效字段。
- 3.0/Reborn 导入应读取 Reborn 格式；导出时将本地谱面转换为 Reborn 规定格式，不修改其字段契约。
- 保留上传/选择文件的既有逻辑，只调整转换和保存逻辑。
- 2.0 音符时间以 tick 输入；结合用户输入 BPM 转成 beat，再使用分母 1–32 的近似分数，不得把 BPM 强行改成 1200。
- 创建谱面时总 beat 数必须从真实谱面数据推导，不能错误变成 1。
- 钻石块谱面坐标应为 `y=65`；不得在导入或播放映射时偏移到 `y=66`。
- 用户要求彻底移除 BPM 测量功能及组件，使 JAR 不包含该组件，但源码留有备份。

### 3.2 场景与本地存储

- 新本地谱面使用稳定、安全的 ID 作为谱面目录名；本地格式与 Reborn 导出结构严格分离。
- 本地谱面目录的布局、清单、音频和场景存储规则以用户确认的目录约定为准；音频暂存仍留在原位置（用户后来明确要求回退音频移动修改）。
- 旧结构必须兼容读取，并在首次成功加载或保存时迁移；迁移完成后删除对应旧格式文件，只删除确认属于该谱面的内容及空目录，不影响其他谱面。
- 场景文件保存 Reborn 对应格式；场景根据谱面中初始场景及实际引用的特效场景创建，按名称去重，不得因缺少 UUID 丢弃场景。
- 特效场景可有多个；无特效场景时不创建特效场景目录。场景元数据文件名为 `metadata.yml`。
- Maker 本地 `layout.json` 是制谱器附属数据，保留；Reborn 导出遵守 Reborn 的难度文件命名、清单和相对路径规则。
- 用户明确导出时才生成导出目录；导出目录使用时间戳 `谱面名称 - yyyyMMdd-HHmmss`，同一秒重复则追加序号。导出需包括音频，按原始扩展名写为 `audio.<ext>`，并由 Reborn 清单用相对路径引用。
- 新建世界不应再生成旧 `charts` 等结构；新建谱面不应额外制造重复场景目录；删除谱面需完整删除该谱面自己的目录。
- 2.0 导入场景优先采用制谱器内置场景覆盖；导入场景命名需保留谱面定义名称，不能被默认名覆盖。初始场景名沿用输入定义；特效场景默认命名序列从 `effect_arena_1` 起。
- 用户要求场景图标选择复用创建谱面时的曲绘选择逻辑。

### 3.3 Beat、轨道吸附与撤销

- 原称“Chunk”的编辑计量语义实际为 beat；UI、配置、命令等应改用 beat 术语，同时保留旧 chunk 名称作为兼容别名。
- 旧 chunk 配置键需兼容读取，统一按 beat 处理；保存写新键，不静默丢弃旧数据。名称变更不得改变旧有计算语义。
- 音符 `z`、beat、time 必须依当前布局/BPM 统一计算。方块坐标按方块中心处理，不能把整数方块索引直接当连续世界坐标。
- 吸附应实际创建目标位置音符、删除旧小数位置音符并持久化；完成后重新计算总 beat 数。修改每 beat 分数后应立即刷新吸附状态。
- 撤销需恢复被修改/删除音符，删除本次吸附新增的整数位置音符，同时保留吸附前已有整数位置音符；文件和客户端轨道必须同步。撤销过程有进度反馈、锁定操作，完成后明确提示。
- 普通编辑或 WorldEdit 改变谱面时应使旧撤销快照失效，避免错误恢复；客户端按钮状态和服务端持久化需同步。

### 3.4 特效编辑器、输入与文字预览

- 特效持续时间按 beat 分数拆为整数 `n` 与分数 `a/b` 输入；仅对原本就支持持续时间的事件新增此输入；新建时分母使用当前每 beat 分数。2.0 持续时间按 beat 转换为近似分数。
- 时间轴拖动滑块不改变单选/多选集合；Ctrl+A 仅在焦点位于时间轴时全选事件。
- 播放头快捷键：Shift+滚轮按 1 beat 移动，Alt+滚轮按 10 beat 移动；缩放后同步底部滑块并保持播放头可见。
- 输入框需足够宽以完整显示数字；Ctrl+左键在多选集合中切换单个事件；选中事件后 Backspace/Delete 快捷删除。
- 文字预览的 `&`/`§` 颜色码应符合 Minecraft 颜色映射（例如 `&c` 红色、`&f` 白色）；加粗、下划线、斜体、混淆和重置等样式按游戏语义显示。编辑器字体不支持的字符/样式可在文字预览处使用 MC 原生字体，但不影响其他 UI 字体。
- TextDisplay/TextDisplayEffect 的颜色、背景、阴影、不透明度、发光、变换和播放期更新需检查编辑器字段、序列化、运行时实体应用的完整链路；默认位置偏移为 `[0,1.5,0]`。

### 3.5 正式播放与特效语义

- 正式播放场景切换从本地对应场景读取 `.schem` 替换播放区域；播放结束回到初始场景。只有发生切换时才做回退清理，避免无意义操作。
- 场景编辑器应限制名称只包含 ASCII 字母、数字和下划线；初始场景默认 `initial_arena`，特效场景默认 `effect_arena` 加序号，但导入定义名优先。
- 天气特效必须实际改变播放天气；仅播放结束时恢复晴天，不强制重设世界时间。世界时间特效的播放行为须与特效语义一致。
- 隐藏音符只隐藏实体，不取消判定音；隐藏状态应在实体进入轨道/复用显示池之前应用，避免闪现。
- 隐藏范围按轨道与音符类型形成独立集合；未指定字段才表示通配。恢复只作用于对应选择集合。播放结束和场景切换时清理状态，并确保不同键的显示实体不会跨集合错误复用。
- 2.0 的 `VISIBLE` 等旧事件应保留可识别的显示/隐藏语义；场景切换事件也需兼容旧字段和新字段。
- 烟花位移、RGB 白色、特效播放生命周期、实际服务器实体/客户端显示和 MC 自身机制都要沿链路验证，不能仅确认编辑器能写入或事件能分派。
