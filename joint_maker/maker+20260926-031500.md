# RhythMC Maker 本轮性能修复记录

- 时间：2026-09-26 +08:00
- 任务：分析制谱器轨道中玩家完全空闲时最新版帧率远低于“场景调整到 x=600 后、特效编辑器加入前”的 0.1.0 历史版本，并修复可确认的空闲热路径。

## 对照与结论

1. 对照基线包：`bak/rhythmc-maker-0.1.0.jar.bak-playback-performance-20260919-215539`，其为特效编辑器加入前的 0.1.0 包；当前修复前版本为 1.3.7。
2. 客户端 HUD 每帧均调用 `ClientChartAccess.resolveActiveChart()`；旧实现会进一步调用 `ChartStorage.findByEditorSlot/findByDimensionId`，后者调用 `ChartStorage.list`，逐个读取并反序列化全部谱面 JSON。轨道闲置时该路径仍以帧率频率运行；谱面数量、音符/场景/特效数据增长后，I/O、JSON 解析和对象分配会直接挤占渲染帧预算。
3. 最新版为修复视距外旧展示实体新增了全轨道分块扫除。扫除及区块加载回调会检查大量区块；原逻辑即使该区块没有任何 `BlockDisplay`，也会先遍历整张谱面构造有效音符 tag 集合。该工作不需要玩家操作，仍会在清扫期间持续消耗整合服务器 CPU，并间接降低客户端 FPS。
4. 特效编辑器界面本身不会在未打开时持续渲染；其后复杂谱面数据和展示实体清扫机制会放大上述两条热路径，因此不是单一的“特效 UI 一直在跑”。

## 修改

- `src/main/java/cn/frkovo/rhythmcmaker/client/ClientChartAccess.java`
  - 缓存当前已解析的制谱器维度；玩家仍处于同一维度时直接复用 `activeChart`，不再在每个 HUD 帧重新扫描、读取并反序列化谱面文件。
  - `setActiveChart` 会主动失效维度缓存，切换或保存谱面后下次解析仍会读取最新数据。
- `src/main/java/cn/frkovo/rhythmcmaker/RhythmcMaker.java`
  - 旧展示实体区块清扫先取得该区块的 `BlockDisplay` 列表；列表为空立即返回，不再构造整张谱面的有效 note tag 集合。
  - 保留有展示实体区块的完整代次、旧 tag、跨谱面和无 tag 清理语义，不降低旧实体删除可靠性。
- `gradle.properties`
  - 版本：`1.3.7` → `1.3.8`。
