# RhythMC Maker 场景与初始场景关系结论

- 时间：2026-09-25 15:30:00 +08:00
- 结论：从 RhythMC 3.0 文件格式看，初始场景和播放中切换的场景没有不同的文件格式或目录格式，本质上都是 Arena；区别只来自谱面中的引用位置。

## 格式层面的区别

- 初始场景：由 `.rmcc.meta.initialArena` 引用；
- 切换场景：由 `effects[]` 中 `eventType: ARENA` 的 `properties.arena` 引用；
- 两者最终都指向 `Data/Arenas/<arena-key>/metadata.yml + arena.schem`。

因此导入时不应要求用户分别上传“初始场景文件”和“特效场景文件”。应统一导入 Arena 资源，再根据 `.rmcc` 引用自动判断其用途。

## 角色关系

同一个 Arena 可以同时：

- 作为初始场景；
- 作为播放中切换目标；
- 被多个难度或多个 ARENA effect 复用。

所以“初始/特效”应是绑定关系或引用角色，不应成为资源类型。

## 推荐 UI 调整

将入口统一为“导入场景/Arena”，导入后再显示引用关系：

```text
Arena: night
- 文件状态：完整
- 被 WORLD 作为初始场景使用
- 被 WORLD 第 32 拍 ARENA effect 使用
- 被 NETHER 第 64 拍 ARENA effect 使用
```

如果场景未被任何谱面引用，标记为“未使用 Arena”，而不是错误。

## 导入流程

1. 用户导入任意合法 Arena 目录；
2. Maker 保存 `metadata.yml + schematic`；
3. 导入或重新扫描 `.rmcc`；
4. 根据 `meta.initialArena` 和 `ARENA.properties.arena` 建立引用；
5. 仅在导出或播放前检查引用是否都能解析。

## 仍需要保留的语义

虽然文件类型相同，但 Maker 仍要区分引用角色，以便：

- 设置某个难度的默认开始场景；
- 显示第几拍发生场景切换；
- 检测初始场景缺失；
- 检测 ARENA effect 引用缺失；
- 重命名 Arena key 时同步修改所有引用。
