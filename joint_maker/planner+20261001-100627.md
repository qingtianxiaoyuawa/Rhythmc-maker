# 部署 UI 与 Flashback/Owo 风格差异再诊断

- 日期：2026-10-01
- 用户反馈：已部署界面明显仍是此前 Owo-lib 风格，与 Flashback 截图差异很大。
- 参考截图：`C:\Users\28585\AppData\Local\Temp\codex-clipboard-bb7aec22-5803-4ea4-b98f-53bffddd670e.png`
- 参考部署记录：`maker+20261001-094019.md`、`maker+20261001-095804.md`。
- Planner 边界：本轮只做诊断和规划，不修改源码、不编译、不测试、不部署。

## 结论

用户判断正确：已部署界面不是“Flashback 风格实现得不够像”，而是**仍然沿用了 Owo 风格的 UI 生成方式和视觉结构**。此前执行主要是扩大窗口、修改颜色、统一标题和重排部分页面，但没有真正切换到 Flashback 所代表的“扁平停靠式编辑器 UI”范式。

因此继续调整 Owo 页面里的颜色、边距、面板宽度或标题，无法解决根本差距。需要停止在旧 Owo 屏幕上做表面修补，将特效编辑器改为独立的 ImGui/docking-like 工作区；普通菜单也应使用同一套扁平控件绘制，而不是继续使用 Owo 的容器与组件。

## Flashback 截图的可见视觉语言

### 1. 扁平停靠面板，不是居中卡片表单

- 右侧面板从窗口边缘直接停靠，宽度稳定。
- 面板内部没有多层厚重边框和嵌套卡片。
- 主画面、顶部栏、右侧栏和底部时间轴通过位置与细分隔线分区，而不是用一层层蓝色描边包围。
- 界面内容贴近工作区边缘，空间利用率高。

### 2. 控件密度高但结构清楚

- 控件高度较小，标签、复选框、下拉框和数值输入按行排列。
- 分组使用细标题线或短分隔线，不使用大块标题卡片。
- 文字字号小而稳定，控件之间没有大面积空白。
- 选中和启用状态使用蓝色勾选/高亮，未选中状态保持低对比灰色。

### 3. 深灰单色系统

- 背景、停靠面板和输入控件只做有限的深浅层级。
- 颜色重点是低对比灰、深灰和少量蓝色状态色。
- 不使用 Owo 风格常见的蓝色描边大面板、独立卡片背景和明显的外框嵌套。

### 4. 右侧检查器是连续属性面板

- 右侧栏是一条连续的设置面板，内容按类别向下排列。
- 面板中的复选项、下拉框和数值控件视觉统一。
- 只有一个明确的滚动区域，不把每个类别包成独立大卡片。
- 当前截图中的“视觉/界面/世界/覆盖/其他”是检查器分组，不是多个独立 Screen。

### 5. 顶栏是应用级工具栏

- 顶部是薄菜单栏，承载文件、偏好设置、玩家列表、移动、渲染过滤、隐藏等全局动作。
- 不应在顶部放一个高度很大的标题卡片或重复显示多组工程信息。
- 主要工具和菜单应保持横向紧凑排列。

## 已部署 UI 的根本差异

根据用户提供的部署截图和最近执行记录，当前界面表现为：

- 多层蓝色边框和大块容器嵌套。
- 中央内容仍以 Owo/表单页面方式组织。
- 按钮和文字被放在大块纵向卡片中。
- 中文显示为问号，字体系统没有达到可用状态。
- 右侧连续检查器、顶部薄菜单和底部专业时间轴没有形成 Flashback 式工作区。
- 页面是“若干 UI 面板拼在一起”，而不是“一个持续编辑的停靠式工作台”。

这说明此前“统一普通菜单颜色和布局”的实现方向仍以 `RhythmcScreen`/Owo 页面为基础；即使页面变宽，仍然继承了旧 UI 的组件、边框、容器和布局语义。`maker+20261001-095804.md` 也记录了对多个 Owo 页面进行统一改造，而不是完成 Owo UI 范式替换。

## 为什么之前的方案没有达到目标

1. **把视觉重构理解成换颜色和间距**
   - Flashback 的关键不是深色颜色，而是停靠布局、扁平控件、连续检查器和应用级工作区。
   - 旧实现改变了面板尺寸，却没有改变页面组织方式。

2. **继续使用 Owo 页面作为基础**
   - Owo 的 `BaseOwoScreen`、`FlowLayout`、`Surface`、`panel` 等结构会自然生成嵌套容器和卡片式布局。
   - 在这些组件上继续修补，只会得到“深色 Owo UI”，不会得到 Flashback UI。

3. **没有先实现目标界面的最小骨架**
   - 正确顺序应是先看到薄顶栏、停靠侧栏、连续属性面板和时间轴，再逐步接入业务。
   - 当前实现先改造旧页面，再把若干区域塞进去，导致最终结构仍然像旧页面。

4. **构建成功被当作视觉完成**
   - 编译和 JAR 部署只能证明代码可构建。
   - 没有经过游戏内截图对比，就不能证明字体、缩放、区域比例、Framebuffer 和控件风格符合目标。

## 必须调整的实现方向

### 特效编辑器

- 停止继续扩展旧 `EffectTrackScreen`/Owo 容器。
- 新建独立的 ImGui 工作区 Screen，不继承 `BaseOwoScreen`。
- 使用固定的六区布局：薄顶栏、左侧特效库、中央预览、右侧连续检查器、底部时间轴、底部状态栏。
- 通过坐标区域、分割线和停靠关系组织界面，不通过多层 `FlowLayout` 面板组织。
- 控件使用统一的扁平绘制函数：行高、标签列、输入列、折叠标题、悬停/选中状态、单一滚动容器。
- 时间轴必须是真正的 Beat 标尺与事件轨道，不使用事件列表冒充时间轴。

### 普通菜单

- 保留原业务逻辑和入口，但新视觉不得继续由 Owo `FlowLayout`/`Surface` 生成。
- 使用与特效编辑器一致的主题、扁平控件和模态窗口。
- 普通菜单可以保持各自布局，但必须脱离“固定居中大卡片 + 嵌套蓝框 + 纵向按钮堆叠”的旧范式。
- 不给普通菜单增加时间轴；只共享主题和控件语言。

### 字体与运行时显示

- 中文问号是 P0 阻断项，不得进入视觉验收。
- 必须确认部署 JAR 实际加载的是有效 CJK 字体、glyph range 和回退字体。
- 必须在 Minecraft 实际 GUI 缩放下检查文字尺寸和控件尺寸，不能只检查 JAR 内资源存在。
- 字体加载失败时应有清晰日志和可用回退，但不能把问号当成可接受结果。

## 重新定义验收标准

### 结构验收

- 一眼看出是停靠式编辑器，而不是旧 Owo 表单。
- 顶部是薄菜单栏，不是大标题卡片。
- 右侧是连续属性检查器，不是多个嵌套面板。
- 控件通过细分隔线和分组标题组织，不出现重复厚边框。
- 特效编辑器底部时间轴真实存在且占据稳定区域。

### 视觉验收

- 中文全部可读，不出现问号。
- 面板颜色低对比、控件扁平、间距紧凑。
- 蓝色只用于交互状态，不作为所有面板的边框颜色。
- 对照 Flashback 截图，必须比较空间关系、控件行高、侧栏宽度和分隔方式，而不是只比较色调。

### 功能验收

- 特效库能够创建真实事件。
- 时间轴显示真实事件位置，播放头能够定位。
- 右侧属性与当前选中特效联动。
- 保存、播放、导入导出继续使用原有业务逻辑。
- 普通菜单逻辑不变，但视觉统一切换到新控件体系。

## 实现方下一步任务

1. 暂停对 Owo 页面继续做样式微调。
2. 输出并确认特效编辑器独立 ImGui 工作区的最小骨架。
3. 先实现薄顶栏、连续右侧检查器、扁平左侧库和真实底部时间轴的空数据版本。
4. 取得游戏内截图，确认结构已经脱离 Owo 风格后再接入业务。
5. 修复 CJK 字体和 GUI 缩放问题，重新截图确认中文可读。
6. 接入特效数据、属性编辑、时间轴操作和预览联动。
7. 普通菜单按相同控件系统逐个迁移，保留原有逻辑。
8. 最终移除 Owo 页面、组件、输入判断和工程内 Owo 源码。

## 本轮结论

用户指出的差异是架构层和视觉范式层的差异，不是细节调参问题。当前部署界面仍属于 Owo 风格的卡片/容器式 UI；Flashback 则是扁平、停靠、连续检查器和时间轴驱动的编辑器 UI。下一步必须先替换 UI 生成范式，再谈颜色、字体和间距微调。
