# Planner 方案记录：真实播放与统一谱面时间轴

- 日期：2026-09-26
- 用户修正：UI 必须实际接入 RhythMC 播放和轨道俯瞰图；特效放置轨道与 Track 轨道必须和谱面时间一一对应。
- 本轮仅规划，不修改源码、不编译、不部署。

## 核心原则

- 只允许一个权威播放时钟 `TransportClock`，播放按钮、音频、俯瞰图播放头、特效轨道、Track 轨道和音符高亮全部读取同一个时钟。
- `beat` 是谱面编辑的权威坐标；`seconds` 是由完整 BPM 时间轴派生的播放坐标。时间轴可以同时显示 Beat 和歌曲秒数，但不能为不同面板各自计算时间。
- offset 只在 TransportClock 的歌曲时间边界应用，不能让特效轨道和音符轨道产生不同偏移。
- 播放倍率只改变 transport 的时间推进速度，不改变事件的 beat、音符坐标或特效数据。

## 真实播放接入

当前 Maker 已有客户端音频启动时间、播放速率、起始 Chunk 和服务端 `rhythmc_play` 命令。建议抽象为：

`TransportClock { state, startBeat, currentSeconds, currentBeat, rate, seek(), play(), pause(), stop() }`

- 正式播放：继续调用现有 RhythMC 服务端播放命令和本地音频。
- 滚动/编辑预览：可以不生成正式判定实体，但必须复用相同 `startBeat`、BPM、offset、rate 和 `ChartTiming`。
- 暂停/拖动时间轴：先停止或暂停当前音频与服务端播放，再将 transport seek 到目标 beat；避免 GUI 自己移动播放头而实际音乐仍在旧位置。
- 播放头位置由 `currentBeat` 映射，不使用帧数累加。

## 真实俯瞰图

- 俯瞰图不使用抽象彩色条替代实际数据；应从当前谱面的播放场景/轨道结构读取真实方块和音符坐标。
- 推荐使用独立的 `WorldPreviewViewport`：复用当前编辑维度的区块/方块渲染，绑定一个预览相机，不改变玩家位置。
- 预览相机至少支持：俯视、斜俯视、跟随当前 Chunk、聚焦选中音符/特效对象、固定全谱范围。
- 播放时在实际俯瞰图上显示当前 beat 的播放头、当前 Chunk/分数、当前音符高亮和特效影响范围。
- 场景特效预览应调用与 RhythMC 运行时同构的预览层；不能把 Axiom/Flashback 的内部类直接当依赖。

## 统一轨道模型

时间轴根节点使用一个 `ChartTimelineModel`，所有轨道共享同一 beat 坐标：

- `NoteTrack`：从 chart.notes 映射音符起点、结束点、轨道位置。
- `RhythmcTrack`：映射每条运行时 Track 的 notes、speedEvents、X/Y/Z transform、rotation、scale 事件。
- `EffectTrack`：映射 chart.effects，每个事件使用 effect.beat；持续事件额外使用 duration/endBeat。
- `MarkerTrack`：BPM、offset、场景切换、段落标记和循环区间。

特效轨道和 Track 轨道不应各自拥有独立滚动位置；它们只是在同一时间轴下显示不同数据层。

## 一一对应规则

- 每个事件的原始 `beat` 保留为唯一编辑值。
- 时间轴像素位置：`x = beatToPixel(event.beat)`。
- 歌曲秒刻度：通过 `ChartTiming.beatToSeconds(beat)` 生成，不反向覆盖 beat。
- 播放头：`x = beatToPixel(TransportClock.currentBeat())`。
- 选中事件后，Track、特效、俯瞰图和参数面板同时定位到同一 beat。
- 点击时间轴空白处：先通过 `pixelToBeat` 得到 beat，再用 `ChartTiming.beatToSeconds` 定位播放。
- 变 BPM 情况下，Beat 网格保持等距的谱面编辑坐标；秒刻度按 BPM 分段变速显示，不能用固定 BPM 绘制秒尺。

## UI 分区建议

- 左侧资源栏：特效类型、Track 类型、预设；点击添加事件时默认插入当前播放头 beat。
- 中央上部：真实 Minecraft 俯瞰世界预览；播放头和选中事件联动。
- 中央下部：统一时间轴，分组显示音符、Track 参数、特效、BPM/Marker；每组可折叠但共享水平滚动和缩放。
- 右侧参数栏：编辑当前事件的 beat、持续时间、Track、位置、旋转、缩放、速度、颜色、文本和 easing。
- 底部传输栏：播放/暂停、停止、循环、当前 Beat/歌曲时间、倍速、吸附、撤销/重做。

## Axiom 与 Flashback 借鉴边界

- Axiom 借鉴实际世界视口、选中轮廓、Gizmo、工具栏、属性检查器和可停靠窗口。
- Flashback 借鉴时间轴、关键帧、播放头、预览相机、轨道分组和导出流程。
- 不直接调用 Axiom 或 Flashback 的内部 UI 类、ImGui Context、纹理或 Mixins；Maker 建立自己的 UI/渲染层。

## 推荐实现顺序

1. 抽象 `TransportClock`，让现有 Sidebar、滚动框和音频共用。
2. 抽象 `ChartTimelineModel`，统一 note/Track/effect/marker 的 beat 映射。
3. 先实现真实俯瞰图只读视口和播放头联动。
4. 将现有 `EffectTrackScreen` 改为统一时间轴，而不是单独的事件列表。
5. 加入 Track 速度、位移、旋转、缩放事件显示与参数编辑。
6. 最后加入世界内特效预览、Gizmo、关键帧插值和导出校验。

## 验收标准

- 从时间轴 Beat 12 播放时，音频、服务端播放、俯瞰图播放头、特效轨道和 Track 轨道均从 Beat 12 开始。
- 拖动播放头到带变 BPM 的事件后，显示的歌曲时间、音频位置和事件触发时间一致。
- 同一事件在俯瞰图、特效轨道、Track 轨道和右侧属性栏显示相同 beat，不能出现一帧/一拍偏移。
- 修改播放倍率只改变播放速度，不改变事件的 beat 和空间坐标。
