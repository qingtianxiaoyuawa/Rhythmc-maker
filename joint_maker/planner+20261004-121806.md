# RhythMC Maker 特效编辑器时间轴实现规划

- 日期：2026-10-04 12:18:06（Asia/Shanghai）
- 身份：Planner；本轮不修改源码、不编译、不测试、不部署。
- 当前工程基线：`1.5.38` 附近的 ImGui 特效编辑器与现有播放预览链路。

## 当前情况分析

当前 `EffectEditorImGuiView.drawTimeline()` 的结构是：

- 一个覆盖整个谱面的 `sliderFloat`。
- 一个 `Chunk/Sub-beat` 文本输入框。
- 一行静态 Beat 标尺文本。
- 按事件顺序绘制的 selectable 文本列表。

这套实现可以验证播放头和 seek 回调，但还不是参考图中的时间轴。主要缺口：

- 没有可缩放的时间窗口，长谱面下无法精确编辑。
- 没有左侧固定轨道标签和右侧可横向滚动的轨道区域。
- 没有事件块、关键帧菱形、曲线和持续时间可视化。
- 没有拖动事件块、拖动关键帧、框选和吸附。
- 只有浮点 Beat 视觉，没有清晰的 Chunk/Sub-beat 标尺层级。
- 拖动 slider 虽然调用 `seekAction`，但时间轴本身没有事务化的拖动提交、预览 seek 和释放鼠标后的最终同步。
- 播放时当前播放头会从 `RhythmcMakerClient.effectEditorCurrentBeat()` 回写，但暂停、拖动、播放、关闭之间缺少统一的时间轴状态对象。

## 总体架构

时间轴应拆成四层，不要继续把所有逻辑写在 `drawTimeline()`：

```text
TimelineState
    ↓
TimelineMapper（Chunk/Sub-beat ↔ Beat ↔ songTime ↔ 像素）
    ↓
TimelineModel（轨道、事件块、关键帧、可见区间）
    ↓
TimelineRenderer + TimelineInputController
```

### 1. TimelineState

保存纯客户端编辑状态：

- `playheadPosition`：内部使用高精度 Chunk/Sub-beat 位置。
- `playheadBeat`：由 mapper 得到，不作为独立时钟来源。
- `songTime`：由 `ChartTiming` 得到。
- `viewStart`、`viewEnd`：当前可视时间窗口。
- `pixelsPerChunk` 或等价缩放值。
- `horizontalScroll`。
- `selectedTrack`、`selectedEvent`、`selectedKeyframe`。
- `dragMode`、`dragStartMouseX`、`dragStartValue`。
- `isSeeking`、`isScrubbing`。
- `snapMode` 和 `snapDivision`。

播放时，`TimelineState` 不自行推进时间；每帧从统一预览播放状态读取当前 Beat，再映射到显示位置。

### 2. TimelineMapper

集中处理所有单位转换：

```text
Chunk/Sub-beat
    ↔ Beat
    ↔ ChartTiming.beatToSeconds / secondsToBeat
    ↔ 时间轴像素 X
```

推荐内部位置定义：

```text
absoluteChunkPosition = chunkIndex + intraChunkFraction
beat = absoluteChunkPosition
```

原因是当前工程已明确 `Beat = Chunk`；`divisionsPerChunk` 只用于 Chunk 内部的轨道方块/分数显示和世界空间细分，不得再次乘进起始 Beat 或播放时间。

显示示例：

```text
Chunk 1 + 5/8
Chunk 1 + 0.625
```

两者必须表示同一个内部位置。分子分母只是显示格式，内部保留 `double` 或定点值。

Mapper 还应提供：

- `formatPosition(position, divisions)`。
- `parsePosition(text)`。
- `snap(position, division)`。
- `beatToPixel(beat, view)`。
- `pixelToBeat(pixelX, view)`。
- `beatToSeconds(beat)`。
- `secondsToBeat(seconds)`。

所有顶部当前位置、检查器时间字段、时间轴标尺、事件块和 Camera 预览必须使用同一个 Mapper。

## 轨道模型

第一版不要直接把 `ChartManifest` 的所有字段硬编码到 ImGui 绘制中，建立只读/可写的时间轴投影模型：

```text
TimelineTrack
├── id
├── label
├── color
├── height
├── visible
├── locked
├── mute/solo（后续）
└── items

TimelineItem
├── kind: EVENT_BLOCK / KEYFRAME / CURVE_POINT
├── startBeat
├── endBeat
├── eventIndex
├── channelName
├── color
└── editable
```

建议首版轨道：

- 音符/节奏参考轨道：只读，用于对齐特效。
- 透明度轨道：读取动画 channel 或属性关键帧。
- 位移轨道：X/Y/Z 或组合显示。
- 旋转轨道：X/Y/Z 或组合显示。
- 缩放轨道：X/Y/Z 或组合显示。
- 特效轨道：每个 effect 绘制一个带名称的持续时间块。

现有 `workingEffects`、`animation.channels` 和 `EffectAnimationEvaluator` 仍作为数据源，不复制另一份长期谱面数据。轨道模型只在当前可见窗口或数据修订变化时重建。

## 时间轴布局

参考图的实现应采用固定轨道列 + 可滚动时间区：

```text
时间轴窗口
├── header：播放控制、当前位置、缩放、吸附
├── ruler：Chunk/Sub-beat 标尺
└── body
    ├── track label column（固定）
    └── timeline canvas（横向滚动）
```

建议尺寸：

- 左侧轨道标签列固定约 150–190 px。
- 标尺高度约 28–36 px。
- 普通轨道高度约 32–44 px。
- 曲线轨道高度约 70–100 px。
- 特效块轨道高度约 44–56 px。

ImGui 实现上建议使用 child window：

- `##timeline-labels`：只绘制轨道名称和锁定/隐藏按钮。
- `##timeline-content`：使用横向滚动绘制标尺、事件块、关键帧和播放头。
- 两者共享同一垂直滚动值；标签列不随水平滚动。

## 标尺与缩放

不要把整首 6 分钟谱面压缩到一个 slider。使用窗口化时间轴：

- `viewStart`、`viewEnd` 决定当前显示的 Chunk 范围。
- 鼠标滚轮配合 Ctrl 调整 `pixelsPerChunk`，以鼠标位置为缩放锚点。
- Shift+滚轮进行水平滚动。
- `Home` 聚焦开头，`End` 聚焦结尾，`F` 聚焦选中事件，双击标尺聚焦当前位置。
- 根据缩放级别显示不同标尺：
  - 远景：每 8/16 Chunk 显示主刻度。
  - 中景：每 1 Chunk 显示主刻度，内部显示 1/2、1/4。
  - 近景：显示 `1/8`、`1/16` 等 Sub-beat 网格。
- 标尺仍以 Chunk 作为用户概念，但 Beat/秒转换完全由 `ChartTiming` 提供。

## 事件块和关键帧

### 特效事件块

- `startBeat` 映射到左边界。
- `duration` 或结束 Beat 映射到右边界。
- 块颜色使用事件类型颜色。
- 块内显示简短名称，例如“标题显示”“烟花”“全息图”。
- 左右边缘可拖动改变开始位置和持续时间。
- 中间拖动改变开始位置，保留持续时间。
- 拖动结果实时更新检查器和预览，但在鼠标释放时执行一次正式修改提交。

### 关键帧

- 关键帧绘制为菱形或小圆点。
- 位置由关键帧 Beat 决定，纵坐标由所属 channel 决定。
- 点击关键帧选中并同步右侧检查器。
- 拖动关键帧只改变其 Beat，不改变数值；数值仍由检查器修改。
- 相邻关键帧顺序必须保持有效；必要时限制拖动范围或排序。
- 插值线第一版可以绘制折线，复杂贝塞尔控制点后续再加。

## 交互优先级

同一鼠标位置的命中优先级建议为：

1. 关键帧拖动点。
2. 事件块边缘调整点。
3. 事件块主体。
4. 标尺/空白区域播放头拖动。
5. 轨道标签按钮。

避免点击事件块同时误移动播放头。拖动过程中显示垂直参考线和当前 Chunk/Sub-beat 标签。

## 统一 Seek 设计

时间轴不应直接调用一个裸的 `Consumer<Double>` 后结束，而应使用明确的 seek 请求：

```text
TimelineSeekRequest
├── targetChunkPosition
├── targetBeat
├── targetSongTime
├── reason: SCRUB / EVENT_DRAG / KEYFRAME_DRAG / INPUT
└── commit: PREVIEW / FINAL
```

处理流程：

```text
像素 X
  ↓
pixelToChunkPosition
  ↓
吸附/保留小数
  ↓
TimelineMapper 得到 Beat
  ↓
ChartTiming 得到 songTime
  ↓
EffectEditorPreview.seek(request)
```

Seek 必须同步更新：

- ImGui 播放头。
- 音频播放位置。
- 服务端预览判定进度。
- 下一音符索引和已触发状态。
- Camera 动态 Z。
- 特效动画采样 Beat。
- 滚动音符预加载状态。

拖动过程可以使用节流的 preview seek；鼠标释放后必须执行一次 final seek。若当前处于播放中，seek 后继续播放；若当前暂停，seek 后保持暂停，但预览 Camera 和服务端状态必须停在目标位置。

## 与现有播放代码的衔接

现有接口已经提供了可复用的方向：

- `prepareEffectEditorPreview()`：只初始化预览资源。
- `toggleEffectEditorPlayback()`：启动/暂停预览。
- `seekEffectEditorPreview(double beat)`：当前 seek 入口。
- `effectEditorCurrentBeat()`：播放中读取当前时间。
- `effectEditorCurrentSongTime()`：当前音频时钟。
- `stopEffectEditorPreview()`：关闭编辑器时清理。

规划上不重写正式播放逻辑，只做两层调整：

1. 时间轴调用统一的 `TimelineSeekRequest`，由客户端预览控制器完成 Beat、秒、音频、服务端和 Camera 的同步。
2. `seekEffectEditorPreview` 只作为兼容入口，内部转发到统一控制器，避免 UI 继续直接操作多个变量。

当前实现的风险点是：暂停状态下 `seekEffectEditorPreview` 主要更新本地起始 Beat/秒并发送 prepare 命令；后续实现必须确认服务端预览会话也被更新到目标位置，而不是仅更新 UI 和客户端字段。

## 性能要求

- 时间轴渲染只绘制当前 `viewStart/viewEnd` 范围内的事件和关键帧。
- 不在每帧绘制时解析 JSON、执行完整保存或调用 `ChartStorage.find`。
- 轨道模型缓存按 `workingEffects` 修订号和视图窗口失效。
- 长谱面采用可见区间索引；不要每帧扫描数万音符寻找可绘制项。
- 拖动期间只更新相机预览和必要的可视对象，不重建整个世界场景。
- ImGui 控件 ID 必须稳定，避免每帧重建输入 buffer 导致光标和输入延迟。

## 实施阶段

1. 抽离 `TimelineState` 和 `TimelineMapper`，先替代现有 slider 的单位转换。
2. 实现固定轨道列、横向滚动时间区和多级标尺。
3. 将 effects 映射为特效事件块，支持选择和播放头定位。
4. 将 animation channels 映射为关键帧轨道。
5. 实现事件块和关键帧拖动、吸附、预览提交。
6. 将裸 seek 回调升级为统一 Seek 控制器。
7. 接入音频、服务端判定、Camera、特效采样的最终一致性验证。
8. 最后做长谱面可见区间优化和参考图视觉细化。

## 验收标准

- 时间轴不再是单个 slider + 文本列表，而是可缩放、多轨道、可滚动的编辑区域。
- 能以 Chunk/Sub-beat 显示和编辑 `1 + 5/8`、`1 + 0.5` 等位置。
- 事件块、关键帧和播放头可以选择、拖动和吸附。
- 拖动播放头后，音频、服务端判定、Camera Z、特效采样和 UI 播放头到达同一目标 Beat。
- 播放中拖动后继续播放，暂停时拖动后保持暂停。
- 保存不退出不停止播放，关闭编辑器才停止预览并清理 Camera。
- 6 分钟完整谱面下，时间轴只处理可见区间，不因绘制时间轴产生明显操作延迟。
- 不改变正式播放、判定音、音符坐标、轨道坐标和既有谱面兼容逻辑。
