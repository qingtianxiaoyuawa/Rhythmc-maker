# Planner 说明记录：Beat 如何决定音符播放时刻

- 日期：2026-09-26
- 核心结论：note.beat 不是直接的秒数，而是谱面拍位置。运行时先由 BPM 事件表将 beat 转为歌曲内时间，再与当前播放时间比较，到达或跨过该时刻时触发音符。

## 单 BPM

- 当 BPM 固定为 B、音符 beat 为 b、首 BPM 在 beat 0 时：`chartSeconds = b * 60 / B`。
- 示例：BPM=260、beat=56.5，谱面内时间约为 13.0384615 秒。

## 变 BPM

- BPM 事件按 beat 排序，并为每个事件计算从 beat 0 累积到该事件的时间。
- 对某音符，选择最后一个 `bpmEvent.beat <= note.beat` 的事件；其触发时间为：`eventStartSeconds + (note.beat - eventBeat) * 60 / eventBpm`。
- 这保证 BPM 改变后，Beat 不变，歌曲秒数按新段速度变化。

## offset

- 3.0 Reborn TimingManager 在 `beatToMillis` 的结果上加 offset；反算 beat 时先扣 offset。
- Maker 导入路径保存无 offset 的 `note.time = beatToSeconds(note.beat)`，实际播放比较时使用 `effectiveNoteTime = note.time + offsetMillis / 1000`。
- 所以 offset 改变音符相对歌曲开始的实际触发时刻，不应改写 note.beat。

## 运行时触发

- 播放器有单一歌曲时钟 `currentSongSeconds`，从开始时间和播放倍率计算，不能按渲染帧数推进。
- 每 tick/更新周期用 `currentSongSeconds` 与按上述规则得到的音符有效时间比较；当时间从小于该值跨到大于等于该值时，生成/判定/播放相应音符。
- 小数 beat 直接得到小数秒，因此能在拍内准确触发；服务器 tick 只能在约 50 ms 边界执行逻辑，客户端插值/预生成负责视觉连续性。

## 关系

`beat -> BPM timing -> chartSeconds -> + offset -> effective trigger time -> playback clock crossing -> note triggers`

- Chunk 和 divisionsPerChunk 只影响 Maker 编辑器的空间显示，不能决定音乐触发时刻。
