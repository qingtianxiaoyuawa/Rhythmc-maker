# 官方网页 BPM 输出 128 的机制

- 时间：2026-09-25 10:30:00 +08:00
- 结论：网页显示的 `128` 是前端对 Essentia 返回的原始 BPM 执行 `Math.round()` 后的整数显示值，不足以证明原始 BPM 精确等于 128。

## 代码链路

- `key-finder-59110acc.js`：音频转单声道、重采样到 `16000 Hz`，调用 `PercivalBpmEstimator`。
- Worker：`postMessage({feature:"bpm", value:B})`，其中 `B` 是 Essentia 返回的原始 BPM 对象。
- `AppBpmFinder-d9c5bd4e.js`：`i.bpm = Math.round(r.data.value.bpm * 1)`。
- 同一处的毫秒拍长使用原始值：`i.ms = Math.round(60000 / r.data.value.bpm)`。

## 含义

如果原始 BPM 落在约 `127.5..128.49` 的区间，JavaScript `Math.round()` 会显示为 `128`。网页界面不展示原始小数，因此用户看到的是格式化后的整数。

网页没有发现歌曲名称特判、测试点映射或“强制改成 128”的逻辑。它的优势主要来自 Essentia `PercivalBpmEstimator` 的检测算法，整数输出则是最后的显示处理。

## 对 Maker 的影响

Maker 应同时保存 `rawBpm` 与 `displayBpm`，避免把显示值误认为测量真值。若最终谱面使用整数 `128 BPM`，应在用户确认后用 `128` 重新计算拍长和 Offset；不能只改变显示文本。
