# ImGui 屏幕渲染目标修复

- 时间：2026-09-27 15:38:09
- 问题：所有 ImGui UI 只显示 Minecraft 的背景和直接由 DrawContext 绘制的物品；谱面信息中的床模型可见，说明 Screen 已进入，但 ImGui 画面没有保留到最终帧。
- 根因：项目在 Screen.render() 阶段调用通用 ImGuiImplGl3。该后端会强制 glBindFramebuffer(GL_FRAMEBUFFER, 0)，而 Minecraft 仍会继续输出其主渲染目标，导致 ImGui 的字体与控件在之后被覆盖。
- 修改：新增 MinecraftImGuiImplGl3，以项目锁定的 imgui-java 1.86.1 OpenGL3 后端为基础，仅移除其强制绑定默认 framebuffer 的操作；它因此向当前 Minecraft 渲染目标提交 ImGui 图元，同时保留原始的字体上传、裁剪、索引绘制及 OpenGL 状态备份/恢复逻辑。
- 修改：ImGuiRuntime 改用该后端，并在首次 draw-data 诊断中记录字体纹理 ID，便于后续核验。
- 修改文件：
  - src/main/java/cn/frkovo/rhythmcmaker/client/MinecraftImGuiImplGl3.java
  - src/main/java/cn/frkovo/rhythmcmaker/client/ImGuiRuntime.java
