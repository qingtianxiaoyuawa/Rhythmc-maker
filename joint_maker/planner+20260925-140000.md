# RhythMC Maker 3.0 谱面导入包设计方案

- 时间：2026-09-25 14:00:00 +08:00
- 工作类型：规划 3.0 谱面、歌曲、初始场景及 ARENA 特效场景导入

## 已确认的 3.0 文件契约

歌曲包位于 `Data/Charts/<song-folder>/`：

- `manifest.yml`：歌曲元信息；
- `world.rmcc`、`nether.rmcc`、`end.rmcc`、`void.rmcc`：可选难度文件；
- 音频文件通常由资源包按 `song_id` 派生为 `rhythmc:sounds.music.s<songId>`，外部导入时需要显式携带歌曲文件并建立映射。

场景位于 `Data/Arenas/<arena-key>/`：

- `metadata.yml`；
- `arena.schem` 或 metadata 中声明的 `.schem` 文件。

3.0 谱面 `meta.initialArena` 指向初始场景文件夹名；谱面 `effects` 中 `eventType: ARENA`、`properties.arena` 指向播放时切换的场景文件夹名。

## 推荐上传方式

首选单个压缩包，例如 `rhythmc3-package.zip` 或自定义 `.rmcp`（本质 ZIP）：

```text
rhythmc3-package/
  package.json
  song/
    manifest.yml
    audio/song.mp3
    world.rmcc
    nether.rmcc
    end.rmcc
    void.rmcc
  arenas/
    initial/
      metadata.yml
      arena.schem
    effect-night/
      metadata.yml
      arena.schem
  assets/
    cover.png                         # 可选，若资源包/图标系统需要
  checksums.sha256                    # 可选，导入时可校验
```

`package.json` 建议包含：

```json
{
  "format": "rhythmc-maker-package",
  "formatVersion": 1,
  "rhythmcVersion": "3.0",
  "songFolder": "song",
  "audio": "song/audio/song.mp3",
  "chartFiles": ["song/world.rmcc"],
  "initialArena": "initial",
  "arenas": ["initial", "effect-night"]
}
```

这里的 `initial`、`effect-night` 是包内 key；导入到游戏后应转换为全局唯一的小写 Arena key，不能假定可直接覆盖服务器已有场景。

## 导入界面建议

从创建谱面页新增“导入 3.0 谱面”按钮，进入 `ImportChartScreen`：

1. 选择一个 `.zip/.rmcp`；
2. 扫描并识别 `package.json`；没有 package.json 时按 `manifest.yml + *.rmcc` 自动识别；
3. 显示歌曲、音频、难度、初始场景、特效场景清单；
4. 逐项显示校验结果；
5. 选择导入难度和场景冲突处理策略；
6. 预览转换后的 manifest、谱面、场景映射；
7. 用户确认后以临时目录原子导入，失败则整体回滚。

可额外支持单文件导入，但不应作为主流程：

- 只选 `.rmcc`：缺歌曲、音频和场景时进入补充资源页面；
- 只选 `manifest.yml`：只能导入元数据；
- 只选 `.schem`：导入到场景库，不能自动绑定歌曲；
- 只选音频：走现有 BPM/Offset 测量流程。

## 导入映射

### 歌曲

- 读取 `manifest.yml` 的 `name/composer/icon/length/song_id/version`；
- 校验 `song_id`，若与本地已有 ID 冲突，生成新的本地 chart ID，但不要修改 `.rmcc` 内部内容，除非同步重写 `uid`；
- 复制音频到 Maker 的 chart audio 存储，使用安全生成的文件名；
- 保存源文件 SHA-256，防止同一歌曲重复导入。

### 难度

固定识别：

- `world.rmcc` → `WORLD`；
- `nether.rmcc` → `NETHER`；
- `end.rmcc` → `END`；
- `void.rmcc` → `VOID`。

读取 `.rmcc` 时：

- 先尝试 Zstd 解压，再回退纯 UTF-8 JSON；
- 校验顶层 `meta/tracks/effects`；
- 读取 `meta.offset/level/charters/bpms/initialArena`；
- 合并全部 tracks 的 notes；保留 track ID、变换事件、speedEvents；
- 保留 effects 原始 JSON，特别是 `ARENA`、`HIDE_NOTES`、`GLOW_COLOR` 和文本效果；未知 effect 不应静默丢弃，应标为“保留原始数据/当前 Maker 不可编辑”。

### 场景

- `meta.initialArena` 必须能映射到导入的 Arena key；
- 扫描所有 `ARENA` effect 的 `properties.arena`，自动收集所需场景；
- 若某个场景只在 effect 中引用而包内缺失，导入阻断或明确标记为缺失，不允许导入后播放时静默切空场景；
- 每个场景校验 metadata 的 `name` 与目录 key、`schematic` 文件是否存在、`.schem` 是否可读；
- `.schem` 暂存为二进制，不把 NBT 结构转换成 JSON；
- 导入场景时生成全局唯一 key，例如 `<songId>_<arenaKey>`，并同步重写 `initialArena` 与 `ARENA.properties.arena` 引用。

## 关键冲突策略

- 歌曲重复：按音频 SHA-256 + manifest 信息提示“覆盖/新建副本/取消”；默认新建副本。
- 难度重复：按难度覆盖或创建新难度，默认不覆盖。
- Arena key 重复：默认重命名并重写所有引用；不能直接覆盖公共场景。
- 不完整包：允许仅预览，不允许直接进入可播放状态。
- 路径安全：拒绝绝对路径、`..`、符号链接、超大文件和 ZIP 炸弹；所有解压路径必须落在临时目录内。

## 当前工程需要补齐的地方

当前 `Rhythmc3Exporter` 已能导出：

- `manifest.yml`；
- 一个难度 `.rmcc`；
- `scene/metadata.yml + arena.schem`；
- 音频文件。

但当前导出代码仍有重要限制：

1. `meta.initialArena` 没有写入 `.rmcc`；
2. `root.effects` 固定为空，无法导出 ARENA 或其他特效；
3. 只导出单个场景，不会扫描多个特效引用场景；
4. 场景目录使用 `scene/`，而正式 3.0 目录契约建议使用独立 Arena key 目录；
5. `ChartManifest` 当前没有持久化通用 effects、BPM 变化点、音频资源映射字段。

因此导入功能应先设计内部统一模型，再分别适配 Maker 存储和 3.0 导出，避免把 3.0 JSON 直接塞进当前简化的 `ChartManifest`。

## 推荐内部模型

```text
ImportedSong
  SongMetadata
  AudioAsset
  List<ImportedDifficulty>
  Map<ArenaKey, ImportedArena>

ImportedDifficulty
  difficulty
  meta
  List<Track>
  List<Effect>
  sourcePath

ImportedArena
  originalKey
  importedKey
  Metadata
  SchematicBytes
```

这样可以完整保留 3.0 数据，再按当前 Maker 可编辑能力投影为 ChartManifest；不可编辑字段放入 `rawRmcc` 或 sidecar JSON，重新导出时不丢失。
