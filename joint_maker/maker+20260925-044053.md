# RhythMC Maker 编译记录

## 本轮目标
- 在不改变已有功能逻辑的前提下优化性能。
- 优化首次播放、新建场景及其他高频路径卡顿。
- 修正部分菜单文字排版。
- 删除确认无调用的私有旧代码。

## 工作流程
1. 检查现有场景异步任务、播放会话和 timing/distance 计算。
2. 使用 Java 21 执行离线编译验证。
3. 修改后再次编译，并执行完整 `clean build --offline --no-daemon`。
4. 备份旧 JAR，强制替换部署 JAR，校验 SHA-256。
5. 使用 Java 21 `jar.exe` 检查部署包关键类和 `fabric.mod.json`。

## 主要修改
- `RhythmcMaker.java`
  - 播放会话复用 `ChartTiming.Prepared` 与 `PlaybackDistance.Prepared`，避免首次播放和每 tick 重复排序/构造 timing。
  - 特效排序和滚动播放改用会话缓存 timing。
  - 移除播放开始前对刚从磁盘读取的谱面再次同步保存，降低首次播放阻塞。
  - 新建/重置场景继续使用分 tick 清理任务，重置不再同步清理 128^3 区域。
  - 场景边界显示直接使用活动谱面 ID 与轨道宽度缓存，减少重复读取谱面文件。
  - 改轨道重排音符复用同一套 timing。
  - 删除确认无调用的 `buildEditorArea`、`copyEditorTemplate`、`isPlayerNoteBlock`、`legacyBuildEditorArea`，以及恒返回 0 的 `chartOffset`。
- `ChartTiming.java`
  - Prepared timing 增加累计秒数和二分查找，降低多 BPM 谱面转换开销。
- `PlaybackDistance.java`
  - 继续通过 Prepared profile 复用已排序动态 speedEvents。
- `ChartStorage.java`
  - 3.0 导入时复用 Prepared timing，不再为每个音符重复构造 BPM 表。
- `SceneEditStorage.java`
  - 增加基于文件修改时间/大小的短期缓存，并返回副本，避免场景边界和场景位置检查频繁解析 JSON。
- `PlaceholderScreen.java`
  - 修正显示、音量、轨道设置分支的排版缩进。
- `PlaybackSettingsScreen.java`
  - 长说明改为自动换行显示。
- `SceneEditScreen.java`
  - 新建场景按钮与主手物品图标说明分开显示，避免按钮文字过长。
