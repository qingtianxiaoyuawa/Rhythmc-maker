# 本轮诊断记录

## 用户问题
播放 TextDisplay 时，原本应为三行文字，但截图中出现沿斜线重复铺开的文字残影/多重几何。

## 当前代码事实
- `RhythmcMaker.java:2740` 每 Tick 调用 `updateTextDisplays`。
- `updateTextDisplays` 对 Track 同步的文字调用 `setTextDisplayPose`，该方法同时调用 `display.setPosition(...)` 和 `display.setTransformation(...)`。
- 创建/普通更新路径 `setTextDisplayTransform` 设置 `display.setInterpolationDuration(...)`；`TEXT_DISPLAY` 默认设置为 1，`LINEAR_TRANSFORMATION` 根据 duration 设置 0–59 tick。
- `TEXT_DISPLAY_SYNC_TRACK` 在每 Tick 更新位置和变换，但没有明确关闭旧的显示插值。
- `setTextDisplayPose` 的同步路径使用 Track pose 作为绝对相对位置，未加创建时保存的 `anchor`；因此同步后会丢失文字原始位置锚点。
- `createTextDisplay` 按 ID 缓存实体，理论上同一播放会话同一 ID 不应重复创建；但若 ID 不稳定、实体过期后再次触发或同一播放会话重复创建，则会出现多个实体。

## 诊断判断
截图中同一文字沿运动方向连续出现，最符合 Display Entity 插值/变换更新与位置更新不同步造成的渲染残影，次要可能是同一 ID 被重复创建后旧实体未被清理。它不像三行文本的换行解析错误：`contents` 已被拼成 `\n`，普通三行文字应只产生一个 TextDisplay 实体。

## 首要修复方向
1. 对 TextDisplay 播放更新关闭或严格控制插值：静态创建与每 Tick Track 同步先使用 `setInterpolationDuration(0)`；不要每 Tick 给同一实体重新设置非零插值时长。
2. 将位置、旋转、缩放作为一次完整 Pose 更新；不要让 `setPosition` 的实体位移与 Display transformation 插值分别运行。
3. 同步 Track 时恢复原始锚点：
   `最终位置 = TextDisplay 中心 + anchor + trackPose 位移`
   而不是只使用 `trackPose.x/y/z`。
4. Track 同步的旋转和缩放应与创建时的基础 rotation/scale 合成，而不是无条件覆盖基础值。
5. 每个播放会话、每个 TextDisplay ID 只允许一个实体；创建前检查缓存和世界中带有对应 ID 的实体，移除重复实体。
6. 停止播放时同时清理 `rhythmc_effect:<chartId>` 标签的 TEXT_DISPLAY，而不仅清理内存 Map，防止异常中断留下旧实体。

## 需要验证的诊断数据
- 播放期间 `textDisplays.size()`。
- 世界中 `rhythmc_effect:<chartId>` 标签的实体数量。
- 每个 ID 的实体 UUID 数量。
- 截图时对应事件是否包含 `TEXT_DISPLAY_SYNC_TRACK` 或 `LINEAR_TRANSFORMATION`。
- `duration` 是否很小，导致同一 ID 反复过期并重新创建。
- 同一 TextDisplay 是否在每 Tick 被设置非零 interpolation duration。

## 结论
当前最可能的根因是 TextDisplay 播放阶段持续更新位置/变换时仍保留非零显示插值，导致连续渲染出多重位置；同时代码缺少按 ID 的世界实体去重保护。应优先关闭播放同步插值、保持单实体，并修正 anchor 与 Track pose 的合成。当前仅完成诊断，没有修改源码、编译或部署。
