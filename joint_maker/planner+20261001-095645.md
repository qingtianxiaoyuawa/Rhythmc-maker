# 部署版 UI 与 Flashback 差距诊断

- 日期：2026-10-01
- 用户提供：部署产物运行截图，询问实际界面为何与 Flashback 差距很大。
- 参考执行记录：`maker+20261001-094019.md`。
- Planner 边界：只分析截图和记录并提出修订方案，不修改源码、不编译、不测试、不部署。

## 直接结论

当前部署界面和 Flashback 差距大，不是单纯颜色、字体或间距没调好，而是**实际交付仍是旧页面框架上的局部重排/信息卡片界面，没有实现构想草图中的特效编辑器工作台**。最新执行记录也明确承认时间轴仍复用事件列表作为交互入口、事件块拖动/复制/删除/播放头拖动尚未接入，而且没有启动 Minecraft 做鼠标、窗口缩放、Framebuffer 的运行时验证。

因此当前成果最多算布局原型或占位页，不能按目标草图视为已完成的特效编辑器 UI。构建成功只证明代码可编译和打包，不证明界面结构、渲染和交互达到参考要求。

## 截图中可直接确认的问题

1. **缺失构想图的主要工作区**
   - 没看到左侧特效分类/搜索/卡片库。
   - 没看到中央 Minecraft 预览画面。
   - 没看到右侧按当前选中特效显示的参数检查器。
   - 没看到 Beat 标尺、播放头、事件块和关键帧构成的底部时间轴。
   - 没看到完整的轨道控制、缩放和底部状态栏。

2. **仍是嵌套容器式旧 UI**
   - 截图里有多层边框和内嵌大面板。
   - 左右区域以大块卡片/按钮纵向堆叠，信息密度不符合目标草图。
   - 顶栏、主要编辑区和面板没有形成统一且清楚的六区布局。

3. **中文显示异常**
   - 多处中文显示为问号；截图里的少量正确中文属于叠加在画面上的 Minecraft 文本，不能证明 ImGui 界面字体正常。
   - 这会直接破坏可用性和视觉一致性，应作为独立的 P0 运行时阻断项，而不能留到最后装饰阶段。

4. **画面缩放/布局有异常迹象**
   - 内容表现为放大后的局部面板，多个控件和容器没有按整个窗口形成合理分区。
   - 仅凭截图无法确定具体是 ImGui framebuffer 尺寸、GUI 缩放、窗口布局尺寸还是预览合成问题；需要运行时尺寸/绘制数据证据，不应直接猜测根因。

5. **关键操作状态无法确认**
   - 截图没有证明特效卡片可新增事件、事件可被选中、检查器会随选择切换或播放头与预览同步。
   - 结合执行记录，撤销/播放按钮仍是状态提示，部分时间轴编辑功能未实现。

## 从执行记录得到的交付差异

`maker+20261001-094019.md` 记录：

- `RhythmcScreen` 被改成响应式宽屏，但仍属于通用旧屏幕外壳调整。
- `EffectTrackScreen` 被“重排”，但没有记录新的自有 ImGui Screen、独立组件系统或 Owo 脱离。
- 旧页面的业务数据和保存逻辑被保留，这是正确的；但 UI 外壳/组件树并未按目标草图彻底替换。
- 时间轴“复用现有事件列表作为稳定交互入口”，与目标草图的真实轨道时间轴不等价。
- 事件块拖动、复制、删除及播放头拖拽尚未接入。
- 撤销、播放按钮仍为状态提示。
- 没有 Minecraft 实际运行验证。

据此判断，执行偏差主要发生在**把“目标工作台重构”缩减成“现有屏幕内重新排版并加若干区域”**，其次是把可编译误当成 UI 验收完成。是否仍直接复用 Owo/旧组件树，需要源码核查才能最终确认；记录中的旧 `RhythmcScreen` 修改和当前截图的多层容器表现强烈提示旧结构仍在影响最终界面，但不应将其写成已证实的源码事实。

## 后续方案修正

### 1. 先停止以局部补丁方式继续堆叠

暂不继续微调旧面板的宽度、颜色或间距。应先按目标构想图建立真实的分区骨架，并由运行时截图确认：顶栏、左侧特效库、中央预览、右侧参数、底部时间轴和状态栏各自有清楚边界与空间。

### 2. 把“外观骨架”设为第一验收门

第一阶段只验收六区布局、全屏尺寸映射、字体、裁剪、面板比例和预览区域。此阶段不得宣称完整特效编辑器已完成。截图需与参考构想图并排对比，逐项核对区域是否存在、比例是否合理、文本是否可读。

### 3. 字体问题设为阻断项

- 验证实际部署 JAR 内使用的字体资源、字体加载日志、glyph range 和回退字体。
- 在目标游戏 GUI 缩放和窗口尺寸下测试中文标签、输入、下拉项、按钮、工具提示。
- 若 ImGui 字体资源仍无法提供所需 CJK 字形，应先修复资源/字体加载方案并取得新截图，再验收视觉。
- 不能用场景内 Minecraft 字体显示正常来替代 ImGui 字体验收。

### 4. 分离预览与 UI 绘制验证

检查 ImGui 显示尺寸、Minecraft scaled window 尺寸、framebuffer 像素尺寸和 viewport/scissor 是否一致。确认预览画面被放在中央预览区，而不是整屏/错误尺寸绘制；保留当前最终 framebuffer 合成时序。用实际运行截图和运行时日志验证，不能仅由构建通过推断。

### 5. 再完成真实时间轴和联动

- 时间标尺使用 Beat 与现有完整 BPM/offset 时间映射。
- 实现播放头定位、事件块布局/选中/拖动、增删改、复制和吸附。
- 右侧检查器绑定当前事件，编辑结果写回现有模型。
- 中央预览响应播放头和当前特效状态。
- 撤销/重做仅在有真实历史栈时显示为可用，播放控件必须调用真实播放服务；占位按钮不作为交付。

### 6. 普通菜单独立处理

普通菜单保留业务行为、入口和导航逻辑，只重做其视觉。不要为了匹配特效编辑器而给普通菜单增加时间轴或强行套用六区工作台。

### 7. Owo 移除目标继续有效

新特效编辑器不得继续依赖旧 Owo 页面布局。普通菜单可以按批次迁移，但每个完成迁移的菜单都应删除旧页面依赖；最终清理 Owo UI 源码和输入判断。不要把短期兼容当作“目标已完成”。

## 修订后的验收门槛

### Gate A：可视布局

- 运行时截图中可同时辨认六个目标区域。
- 中央预览占主面积；左右栏与底部时间轴比例接近构想图。
- 没有旧式层层嵌套的大面板或居中表单结构。
- 中文字符显示正确，字体大小和控件密度可读。
- 在目标 GUI 缩放、窗口分辨率和至少一种不同尺寸下无明显重叠/裁切。

### Gate B：特效编辑功能

- 特效库创建真实事件。
- 时间轴显示真实轨道和事件位置，而不是仅列出事件文本。
- 选择时间轴事件会更新右侧属性；编辑属性会写回同一模型。
- 播放头、Beat、BPM、offset 和预览位置一致。
- 保存后重新打开数据仍一致。

### Gate C：普通菜单与迁移

- 普通菜单业务行为与改造前一致，视觉统一重构。
- 特效编辑器不依赖旧 Owo 页面结构。
- 最终 Owo UI 类型、输入分支和源码引用清零。

## 给实现方的任务摘要

1. 把当前部署版标记为“布局/交互未验收的中间原型”，不要把它当成目标成品。
2. 依据构想图直接完成真实六区骨架，先提交目标游戏截图作为 Gate A 证据。
3. 优先解决中文字体与窗口/Framebuffer 尺寸问题；无清晰截图不进入视觉验收通过状态。
4. 用真实 Beat 时间轴替换事件列表式占位，实现播放头、事件和属性/预览联动。
5. 删除无动作实现的假撤销/播放等占位控件，或接通真实业务行为。
6. 保留其他菜单业务逻辑，仅重构视觉，不把时间轴扩散到其他菜单。
7. 继续逐步迁移并最终移除 Owo UI。
8. 由实现/编译合作方完成源码修改、构建、部署和运行时验收；Planner 只负责方案和验收条件。

## 本轮结论

部署版与 Flashback 差距大的根本原因是：当前交付没有达到构想草图定义的 UI 结构和交互范围，且未通过游戏内运行时视觉验收。主要表现为工作区缺项、旧式嵌套面板仍显著、时间轴和播放控制尚多为不完整/占位状态、中文字体显示异常。下一步应先按草图重建并验收实际六区布局，再开发交互，不应继续把旧 UI 的局部重排描述成目标界面完成。
