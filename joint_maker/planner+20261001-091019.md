## 目标界面定位

这张构想草图不再只是 Flashback 风格参考，而是 RhythMC Maker 特效编辑器的主要视觉和布局基准。实现方应优先按照草图的空间关系、信息层级和操作密度构建，不继续沿用当前拥挤的旧表单界面，也不把旧 Owo 页面作为视觉模板。

## 固定布局

### 1. 顶部工程栏

- 左侧显示 RhythMC Maker 标识。
- 中间提供当前谱面/工程选择、BPM 和当前 Beat 信息。
- 右侧提供撤销、重做、保存、播放/暂停、停止、设置等全局操作。
- 顶部栏保持窄高度，不放置大量参数表单。
- 当前谱面、BPM、当前 Beat 等信息需要调用现有数据逻辑，不建立第二套状态。

### 2. 左侧特效库

- 顶部使用“特效 / 轨道”分类标签。
- 提供特效搜索框。
- 以网格卡片或紧凑列表展示可添加的特效类型，例如：
  - 标题/消息
  - 明天消息
  - 文本显示
  - 天气与时间
  - 烟花
  - 全息图
  - 隐藏音符
  - 发光颜色
  - 场景切换
- 每个特效类型使用图标、颜色和中文名称区分。
- 点击或拖动特效类型后，在当前 Beat/轨道位置创建事件；具体数据创建逻辑复用现有特效模型。
- “轨道”标签用于显示/管理特效轨道，不把普通菜单的谱面轨道强行纳入此时间轴。

### 3. 中央预览区

- 占据编辑器最大面积，显示 Minecraft 场景和当前特效效果。
- 预览区顶部或边缘可提供选择、移动、旋转、缩放等工具按钮。
- 保留必要的变换辅助轴、选中框和对象控制柄，但不要遮挡主要场景。
- 预览渲染应沿用现有 Minecraft framebuffer/ImGui 绘制生命周期，不复制旧 Owo 页面或额外建立不必要的纹理链路。
- 预览区必须与播放头、当前选中特效和右侧参数实时联动。

### 4. 右侧特效参数检查器

- 顶部显示“特效参数设置”和当前特效类型。
- 根据特效类型显示对应参数，而不是所有特效都显示同一套表单。
- 通用字段包括：
  - 拍点/Beat
  - 持续时间/Beat
  - 所属轨道
- 文本类特效可显示文字内容、位置、旋转、缩放、透明度、背景颜色、发光颜色和缓动曲线。
- 颜色、向量、枚举、数值和文本输入使用统一控件规范。
- 右侧面板独立垂直滚动；不与中央预览或底部时间轴共享滚轮状态。
- 修改参数时直接更新现有特效对象和脏状态，不通过截图或临时副本绕过业务模型。
- 提供“添加关键帧”和“重置”操作，但是否对某个特效字段启用关键帧，要由现有数据模型能力决定，不能只做视觉按钮。

### 5. 底部特效时间轴

- 时间轴只属于特效编辑器。
- 左侧为轨道列表和轨道控制：特效、音符/音乐参考、透明度、位移、旋转、缩放等实际支持的轨道。
- 中间为 Beat 标尺、网格、事件块、关键帧、当前播放头和水平滚动条。
- 底部播放控制显示当前时间、总时长和播放操作。
- 支持时间轴缩放、播放头拖动、事件选择、移动、复制、删除和创建。
- 以 Beat 为主要编辑坐标；秒数只作为辅助显示。
- BPM 分段、offset 和速度事件必须使用现有统一时间映射，不能用单一 BPM 或帧数近似覆盖数据。
- 事件块按特效类型使用颜色和图标区分；选中事件使用明确高亮。
- 大量事件必须按可见范围裁剪绘制，禁止一次性生成所有时间轴实体/控件。

### 6. 底部状态栏

- 显示吸附网格、当前吸附分辨率、预览模式、当前场景和导出入口等状态。
- 状态栏只显示低频状态和快捷入口，不再堆放完整设置表单。
- 导出按钮继续调用现有导出逻辑，格式和文件语义不改变。

## 视觉规范

- 整体采用深蓝灰/黑色背景，面板之间使用细分隔线。
- 顶部栏、左侧库、右侧检查器和底部时间轴使用略有层级差异的深色面板。
- 蓝色用于主操作、选中、播放头、焦点和可交互高亮；特效事件可使用独立颜色分类。
- 控件高度、内边距、标签对齐和输入框宽度统一。
- 保留 Misans 中文字体加载基础，但重新确定字号层级和控件密度。
- 避免当前旧 UI 的大块嵌套卡片、固定窄窗口、重复边框和拥挤纵向表单。
- 所有区域应随窗口尺寸变化；中央预览优先保证空间，窄屏时左侧特效库可收起，右侧检查器可缩窄或临时隐藏。

## 逻辑保留范围

构想草图只改变特效编辑器的 UI 组织方式，不改变以下业务语义：

- 特效数据结构和已有特效类型。
- 特效 Beat、持续时间、offset、BPM 分段和播放时间映射。
- 特效保存、导入、导出以及与 `.rmcc`/`.rmcd` 的兼容规则。
- 现有预览、播放、场景切换和错误清理逻辑。
- 其他菜单的原有功能逻辑；其他菜单只进行视觉重构，不加入该时间轴。

## Owo-lib 处理

- 新特效编辑器不继承 `BaseOwoScreen`，不使用旧 `FlowLayout`、旧 Owo 控件或旧 `EffectTrackScreen` 的组件树。
- 新代码直接使用 Maker 自有 ImGui Screen、主题、布局和控件层。
- 其他菜单可在迁移期间短暂保留 Owo，但完成新视觉迁移后逐个删除。
- 最终删除工程内 Owo UI 源码、Owo 类型引用、`BaseOwoScreen` 输入判断以及只服务于旧 UI 的 helper。

## 给实现方的任务清单

1. 将本图作为特效编辑器的目标布局基准，先实现六区空壳，不先复刻旧页面。
2. 建立顶部工程栏、左侧特效库、中央预览、右侧检查器、底部时间轴和状态栏的独立布局状态。
3. 接入现有特效模型、Beat/BPM/offset 映射、保存和播放逻辑。
4. 实现特效库添加、事件选择、参数编辑、时间轴定位和预览联动。
5. 只在实际数据模型支持的范围内实现关键帧、缓动和变换轨道。
6. 对长轨道和大量事件使用视口裁剪，不创建不可见的全部 UI 对象。
7. 保持普通菜单逻辑不变，仅按统一主题重新设计视觉，不把时间轴推广出去。
8. 迁移完成后清理特效编辑器对应的 Owo UI，再继续迁移其他菜单。
9. 编译、运行和截图验收由编译合作方负责，Planner 不执行这些工作。

## 验收标准

- 特效编辑器整体空间关系与构想草图一致：顶部栏、左侧特效库、中央预览、右侧参数、底部时间轴和状态栏齐全。
- 添加特效、选择特效、修改参数、拖动事件、播放预览和保存均作用于现有业务模型。
- 时间轴只出现在特效编辑器，其他菜单没有时间轴。
- 普通菜单视觉统一重构，但其原有逻辑、导航、保存、导入导出和播放行为保持不变。
- 特效编辑器在不同窗口尺寸和 GUI 缩放下无面板重叠、内容裁切或滚动冲突。
- 中文字体、输入框、键盘编辑、鼠标拖动、滚轮焦点和快捷键行为正常。
- 新特效编辑器不依赖 Owo，最终工程完成 Owo 清理。

## 本轮结论

用户提供的构想草图正式确定为 RhythMC Maker 特效编辑器的目标界面。后续实现应优先复刻其信息架构和空间关系，而不是继续调整旧 UI。最终方案保持：**特效编辑器专用 Flashback 风格时间轴；其他菜单保留原逻辑并仅做视觉重构；旧 Owo UI 逐步移除。**
