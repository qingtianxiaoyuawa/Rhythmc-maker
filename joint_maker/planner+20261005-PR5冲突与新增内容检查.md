## 一、PR 新增和修改内容

### 1. `RhythmcMaker.java`

#### 1.1 特效预览播放改为复用已有判定会话

原逻辑在执行特效预览播放时先无条件：

```text
stopPlayback(...)
new ScrollJudgementSession(...)
```

PR 改为：

- 先从 `SCROLL_JUDGEMENT_SESSIONS` 取得当前玩家会话；
- 只有会话不存在、不是特效预览或世界不一致时，才停止旧播放并创建新会话；
- 复用会话后直接 `session.start(...)`；
- 播放开始时调用 `activateEffectPreviewPlayer(...)`。

意图是避免播放/拖动/重播时不断创建和销毁判定会话，减少状态断裂和重复初始化。

#### 1.2 新增特效预览玩家激活流程

新增 `activateEffectPreviewPlayer(...)`：

- 首次激活时保存玩家当前世界、位置和朝向；
- 设置 `state.anchorEnabled = true`；
- 立即调用 `ensureEffectPreviewPlayer(...)` 将玩家移动到预览锚点。

#### 1.3 玩家预览锚点由固定 X 改为判定线右墙坐标

`ensureEffectPreviewPlayer(...)` 的目标位置由：

```text
X = 0.0
Y = 72.0
Z = editorWorldZAtBeat(...)
```

改为：

```text
X = laneWallRightX(chart) + 0.5
Y = 72.0
Z = editorWorldZAtBeat(chart, beat)
```

并新增行为：

- 仅当 `anchorEnabled` 时允许移动玩家；
- 检查实际玩家位置、游戏模式和缓存位置是否都匹配；
- 不在 spectator 模式时切换到 `GameMode.SPECTATOR`；
- 传送时固定 yaw `-90`、pitch `90`。

#### 1.4 保留和恢复玩家位置，但强制恢复为创造模式

关闭特效预览时仍会：

- 恢复打开预览前的位置和朝向；
- 从 `EFFECT_PREVIEW_PLAYERS` 删除状态。

但 PR 无条件执行：

```text
player.changeGameMode(GameMode.CREATIVE)
```

这会覆盖玩家进入特效编辑器前的原游戏模式，是生命周期兼容风险。

#### 1.5 特效预览显示实体扩大可见范围

新增 `ensureEffectPreviewDisplayRange(DisplayEntity display)`，针对带有以下命令标签的实体设置统一 view range：

```text
rhythmc_preview
rhythmc_preview:*
rhythmc_note:*
rhythmc_effect:*
```

目的：避免 TextDisplay、BlockDisplay、音符或特效实体距离玩家较远时被客户端剔除。

#### 1.6 ScrollJudgementSession 增强预览状态

新增或强化：

- `effectPreview` 标志；
- `currentBeat`；
- `playing`；
- `start(...)` 时更新当前 Beat；
- `seekToBeat(...)` 时清理旧特效会话、重置音符索引和预览玩家位置；
- 特效会话清理时重置客户端时间、清理 TextDisplay、清理发光队伍并移除 BlockDisplay。

这使滚动判定音、音符和特效预览共用一个服务端会话容器，但仍需确认特效事件在 seek 后是否完整重建。

### 2. `RhythmcMakerClient.java`

#### 2.1 音频启动参数改变

PR 将音乐音量从 FFmpeg 音频滤镜中的：

```text
-af volume=...
```

改为 ffplay 参数：

```text
-volume <百分比>
```

播放速率滤镜单独保留；无速率滤镜时使用 `anull`。

同时将 ffplay 标准输出丢弃，并把 `audioStartedAtNanos` 作为本地音频起始时间。

#### 2.2 删除 ffplay 进度读取线程

删除：

- `audioProgressReader` 启动逻辑；
- `readAudioProgress(Process process)`；
- 读取 `out_time_ms` 的进度同步机制。

因此音频进度不再来自 ffplay 的 `-progress pipe:1`，而更依赖本地 `System.nanoTime()` 计算。

#### 2.3 保留特效播放结束时的服务端 seek

`finishPlayback(...)` 仍会在特效编辑器预览结束/停止时向服务端发送：

```text
rhythmc_effect_preview_seek <当前播放头>
```

这说明 PR 仍试图保持音频播放头、服务端判定会话和编辑器播放头之间的状态联系。

### 3. `CameraMixin.java`

特效编辑器相机锁定时，将相机旋转从：

```text
setRotation(-90.0f, 90.0f)
```

改为：

```text
setRotation(90.0f, 90.0f)
```

这是可见方向变化，不是纯重构；需要结合 Minecraft 的 yaw/pitch 语义和当前判定线方向验收。

## 二、冲突位置判断

### 冲突 1：`RhythmcMaker.java` 的特效预览会话生命周期

这是最主要的冲突面。

PR #5 修改了：

- `playEffectPreview(...)`；
- `ensureEffectPreviewPlayer(...)`；
- `restoreEffectPreviewPlayer(...)`；
- `ScrollJudgementSession`；
- 特效会话清理和 seek 路径。

这些区域与主线中已有的 TextDisplay 生命周期、对象池、显示实体创建/释放、矩阵状态重置和特效预览玩家状态直接重叠。不能直接整段选择 PR 或主线，否则可能出现：

- 预览会话能播放，但 TextDisplay 对象池释放路径丢失；
- seek 后音符被重置，特效实体没有按目标 Beat 重建；
- 服务端玩家位置已移动，但客户端 CameraMixin 仍使用另一套坐标；
- 正式播放的 `PlaybackSession` 和滚动预览的 `ScrollJudgementSession` 清理范围互相影响；
- 关闭编辑器后实体仍残留或玩家状态未恢复。

规划方向：以主线最新的实体生命周期和矩阵清理逻辑为基础，只吸收 PR 的会话复用、预览激活和位置同步部分。

### 冲突 2：玩家锚点坐标与 Maker 默认播放中心不一致

当前已确认 Maker 默认播放/判定框中心为：

```text
(200.5, 66.0, -1.0)
```

PR 的玩家预览锚点却是：

```text
X = laneWallRightX(chart) + 0.5
Y = 72.0
Z = editorWorldZAtBeat(chart, beat)
```

这不一定是错误，因为玩家视点可以位于判定框上方或侧方；但它不能被误认为 TextDisplay 或判定框中心。

需要在合并规划中明确三层坐标：

1. Maker 默认判定/播放中心：`(200.5, 66.0, -1.0)`；
2. 玩家特效预览视点锚点：PR 的 `laneWallRightX + 0.5, 72.0, 动态 Z`；
3. TextDisplay/音符/轨道/特效的局部矩阵坐标。

若直接把 PR 的玩家锚点作为 TextDisplay 生成点，会产生 Y 方向和 X 方向视觉偏移，导致紫色实体边界、判定框和文字显示不贴合。

### 冲突 3：相机朝向与玩家传送朝向定义不一致

PR 同时出现：

- 玩家传送 yaw `-90`、pitch `90`；
- CameraMixin 设置 yaw/pitch `90, 90`。

需要确认 `setRotation(yaw, pitch)` 的实际参数顺序，以及玩家实体、客户端相机、判定线前进方向是否一致。否则可能出现：

- 玩家实体朝向判定线，但 CameraMixin 反向；
- 音符 Z 轴流动方向与画面上下/前后方向相反；
- 只修改相机后正式播放和特效预览视角不一致。

这与此前 PR #4 的相机锁定、玩家跟踪逻辑属于同一冲突块。

### 冲突 4：音频时钟来源与当前同步修复方向冲突

PR 删除 ffplay `out_time_ms` 进度读取线程，改用本地启动时间推算进度。该方案可以减少一个进度读取线程和管道交互，但会改变同步模型：

```text
音频实际播放位置 -> ffplay progress
```

变为：

```text
本地启动时间 + 速率 -> 推算播放位置
```

这与用户此前反馈的音画不同步、滚动播放后延迟和不同 chunk 速度不同步问题存在直接风险。操作卡顿可能缓解，但不能据此证明音频、判定和白框已经同钟。

合并时必须保留一个唯一 `ChartTiming` 时钟，并明确：

- 音频 seek 起点；
- 服务端 `songTime/beat`；
- 客户端播放头；
- 玩家 Z 坐标；
- 特效事件触发时间。

不能只因为删除线程就认为同步问题解决。

### 冲突 5：关闭预览后的游戏模式恢复

PR 总是恢复为创造模式，不会恢复玩家进入预览前的真实游戏模式。

这与“关闭编辑器恢复原位置、原朝向、原状态”的生命周期要求不完整。规划上应保存并恢复：

- 原世界；
- 原 X/Y/Z；
- 原 yaw/pitch；
- 原游戏模式；
- 必要时原飞行、无敌或输入锁定状态。

### 冲突 6：实体显示范围调用点可能与主线实体创建路径冲突

PR 新增了 `ensureEffectPreviewDisplayRange(DisplayEntity)`，但仅有辅助方法并不等于所有 TextDisplay、BlockDisplay、Hologram 都会调用它。

需要核对主线中的：

- TextDisplay 创建；
- BlockDisplay 创建；
- 对象池复用；
- 轨道特效创建；
- 特效 seek 重建；
- 正式播放和预览播放分支。

如果只在部分创建点设置 view range，可能出现同一特效中部分实体可见、部分实体被剔除。

## 三、建议的人工合并顺序

1. 先以当前主线为基准确认 `RhythmcMaker.java` 的 TextDisplay/BlockDisplay 生命周期和对象池路径。
2. 将 PR 的 `playEffectPreview` 会话复用逻辑单独移植，不覆盖主线的实体清理和状态重置。
3. 将 `anchorEnabled` 和 `activateEffectPreviewPlayer` 接入统一的预览状态机。
4. 将玩家动态 Z 更新接入唯一 `ChartTiming` 时钟；X/Y 视为玩家视点锚点，不替代 `(200.5, 66.0, -1.0)` 默认判定中心。
5. 将显示范围设置放入所有预览显示实体的统一创建/复用入口，而不是依赖调用方记得调用。
6. 重新核对 CameraMixin 的 yaw/pitch 顺序，确认与玩家传送朝向和正式播放视角一致后再保留方向修改。
7. 音频部分先保留 PR 的进程输出丢弃优化思路，但不能在没有替代时钟校准策略的情况下直接删除唯一进度反馈来源。
8. 关闭预览时恢复原游戏模式，不能固定写死创造模式。
9. 用默认中心 `(200.5, 66.0, -1.0)`、玩家预览锚点和 TextDisplay 最终世界坐标分别验收，避免把三者混成一个坐标。

## 四、结论

PR #5 新增的核心不是 UI，而是特效预览的状态同步：

- 复用 `ScrollJudgementSession`；
- 让玩家跟随判定线动态 Z 移动；
- 使用 spectator 模式维持实体追踪；
- 扩大预览实体 view range；
- 调整 ffplay 音量和音频进度策略；
- 修改特效编辑器相机旋转方向。

PR 当前不能直接合并。最重要的冲突集中在 `RhythmcMaker.java` 的预览生命周期、`RhythmcMakerClient.java` 的音频时钟、`CameraMixin.java` 的视角方向，以及玩家锚点与 Maker 默认中心的坐标分层。

建议采用“主线生命周期 + PR 状态同步”的人工合并方案，而不是选择 Current 或 Incoming 的整段版本。
