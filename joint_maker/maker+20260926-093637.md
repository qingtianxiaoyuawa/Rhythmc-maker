# RhythMC Maker 工作记录

## 本轮需求
- 修复播放从所选起始 Chunk 后一段开始的问题。
- 滚动播放改为 Axiom 风格白色框线，并按 Chunk 内分数与歌曲时间实时移动。

## 工作流程
1. 阅读项目 `AGENTS.md`、`CONTEXT.md` 和最近一份 maker 记录；本轮未要求 planner 建议，因此未读取 planner 文件。
2. 核对编辑轨道坐标换算：Chunk 由 `divisionsPerChunk` 个格位组成，beat 到编辑坐标的分数位置为 `beat × divisionsPerChunk`。
3. 运行定向换算回归探针，确认旧逻辑会将 Chunk 2 映射到 beat 4（预期 beat 1），且 1/8 beat 时旧粒子框仍停留在原位置。
4. 修改服务端播放起点、本地音频起点及滚动模式渲染；执行 Java 21 定向编译、离线完整构建。
5. 旧部署 JAR 被占用，复制备份后强制覆盖部署；比较 SHA-256 并检查 JAR 条目。

## 修改文件
- `src/main/java/cn/frkovo/rhythmcmaker/RhythmcMaker.java`
  - 起始 beat 修正为 `startChunk - 1.0`，使播放从选中 Chunk 起点开始。
  - 移除服务端逐 tick 粒子白框。
- `src/main/java/cn/frkovo/rhythmcmaker/client/RhythmcMakerClient.java`
  - 缓存并统一复用本次播放的起始 Chunk，服务端命令与本地音频 seek 使用相同值。
  - 使用 Fabric `AFTER_ENTITIES` 世界渲染事件绘制白色半透明线条包围框，不新增 Axiom 运行时依赖。
  - 框的位置由音频启动时间、播放倍率、BPM 时间轴和每 Chunk 分数数实时计算。
