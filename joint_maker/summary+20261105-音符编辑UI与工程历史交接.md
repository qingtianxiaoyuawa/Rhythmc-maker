## 一、项目历史与工程教训

RhythMC Maker 是 Fabric 1.21.11 / Java 21 的客户端谱面编辑模组，负责谱面编辑、场景、特效预览和导入导出。长期工程目标是在优化性能和修复问题时保留谱面、音符、特效、轨道及场景的完整语义。

历史对话反复强调过以下风险：

1. **谱面数据丢失是最高级别回归。** 曾出现导入、保存或重进世界后音符、轨道、场景和特效消失；也曾出现 2.0 导入后 `.rmcc` 未写入 `track`、`effect`、`note` 等实际数据。涉及存档、缓存、自动保存、实体同步和导入迁移时，必须确认原数据未被清空、遗漏或只保留 UI 入口。
2. **优化不能改变功能。** 大谱面导入、打开写谱菜单、进入谱面维度、特效编辑、保存、播放和区块加载都要求兼顾性能；优化应避免全量重复扫描/重建，但不能通过删减音符或特效换取速度。
3. **草稿、运行谱面与世界实体需保持一致。** `.rmcd` 是编辑器草稿，`.rmcc` 是运行时谱面，`.schem` 是场景结构。自动保存需要沿用现有异步保存链路，避免只保存谱面 JSON 而遗漏展示实体映射，也避免全量遍历/重建所有音符。
4. **2.0 导入应迁移到 3.0 字段。** 不应依赖运行端长期兼容旧字段。2.0 隐藏音符缺少轨道定义，迁移后用 `tracks: []` 表示未指定轨道；3.0 原生 UI 仍保留轨道下拉选项。
5. **播放逻辑以 beat 为统一时间域。** 任意起播和 seek 时需恢复此前最后有效的持续状态；药水剩余时长按歌曲时间扣减；播放临时实体不应写入世界存档；seek、暂停、停止、隐藏和关闭预览时需清理对应状态。
6. **隐藏音符语义已确认。** `HIDE_NOTES` 同时指定音符类型和轨道时，Mod 的规则为类型或轨道任一命中即隐藏，Maker 预览必须保持一致；双条件不能误实现成“类型且轨道同时命中”。
7. **场景名称与身份分离。** `display-name` 用于用户显示；`name` 是稳定 ID，供 `.rmcc` 和效果引用。初始场景与普通/特效场景的导入、引用、删除和文件完整性需分别验证。
8. **发布流程需完整可核验。** 依照 `AGENTS.md` 读取规则、按版本语义递增、构建测试、备份旧包、部署新包、核验 JAR 元数据及哈希，并按工程既有 Git 流程提交。游戏仍占用 JAR 时不要强行结束进程或假称旧包已清理。

早期历史摘要记录过 `1.13.x` 阶段的播放生命周期、场景导入、隐藏音符迁移、路径脱敏和特效编辑器布局等工作；之后用户明确将版本设为 `2.0.0`。因此较早摘要中的 `1.13.52` 等版本只作为历史记录，不是当前版本依据。

## 二、音符编辑功能：用户确认的需求

### 工具与触发

- 编辑工具使用**原版旋风棒物品模型**，玩家看到的名称为“修改音符”。
- 不额外添加自定义 NBT 标签来标识工具；工具识别应由原版物品类型和项目认可的显示名称共同完成，不能把任意原版旋风棒都当作编辑工具。
- 只在谱面编辑维度、持有该工具并命中音符时触发；命中后打开对应音符的编辑菜单。非音符目标不应误开菜单，也不能影响其他正常编辑交互。
- 目标既包括谱面中的方块音符，也包括轨道上以 Block Display 等实体呈现的音符。用户实测已明确指出：之前存在方块右键无效、部分音符无响应、展示实体完全无法编辑的问题。

### UI 与字段

- 使用 ImGui 编辑菜单；依据音符相对屏幕的位置放在其另一侧：音符位于屏幕左侧时菜单放右侧，音符位于右侧时菜单放左侧。
- 菜单可修改位置 X、Y 和绝对时机 Beat；**不展示、不允许编辑 Z**。Beat 不是 chunk 值，也不是持续时间。
- Beat 的分数输入沿用已确认的格式 `n + a/b beat`：`n ≥ 0`、`1 ≤ b ≤ 32`、`0 ≤ a < b`。输入代表音符所在的绝对 beat。
- 菜单不提供轨道修改项。后续轨道修改另行设计。
- 输入有效值后即时更新画面与内存中的目标音符，并立即保存本地草稿；只处理发生变化的目标音符及对应展示实体，沿用当前草稿格式和现有异步保存队列。
- 后续实现加入了音符类型选择和粘合状态锁定/解除入口。类型编辑属于后续实现扩展，最终是否保留以用户最新确认和协作者交付为准；不要误把它当作最初明确的菜单必选字段。

### Hold 粘合与播放

- 右键钻石音符可粘合相邻 Hold。相邻定义：**同一轨道、三维欧氏距离 ≤ 1**，按传递连通搜索；可以一次扩展到多个相邻钻石音符。
- 搜索命中现有 Hold 组成员时，应把该组全部成员并入结果并继续搜索。保留每个成员音符、位置和 beat，只统一 `holdGroup`；不得为了显示成长条而删掉中间音符或位置。
- 粘合后的成员方块保留，并用连接视觉表示它们属于同组；不要跨轨道粘合。
- 需支持 Hold 的区间起止、统一 ChartTiming 更新、开始/持续/结束/取消/seek 状态转换，以及暂停、seek、隐藏特效、停止播放和关闭编辑器后的状态清理。
- Maker 内部可以把组区间显示为一个拉伸视觉实体；但与实际运行端对照时，运行端用 `holdGroup` 和 beat 顺序标注首/中/尾成员并决定判定音，不能把“长条渲染”误认为运行端本身也按一个几何实体处理。声音边界规则需继续以当前运行端版本核对。

## 三、音符编辑故障演进与当前结论

### 已发生的实测问题

用户实测反馈过：

1. 进入谱面维度得到的是原版旋风棒；右键无效果。
2. 音符编辑 UI 不显示。
3. 右键部分音符无效果；部分方块不能命中；轨道上的实体音符完全不能右键编辑。

上一轮初始方案把旋风棒只按物品类型发放/识别，并尝试分别依赖方块和实体右键回调。源码里确实有 `NoteEditScreen`，但这不能证明输入事件链路实际调用了它；服务端编辑器拦截也可能与客户端交互结果冲突。故该方案已经被实测否定，不能只通过改物品名或成功编译声称修复。

### 协作者当前实现方向

用户已另行委托协作者完成 UI 编写。当前工作区可见的实现组织包括：

- `client/NoteEditScreen.java`：ImGui 编辑窗口、Beat 分数控件、状态反馈、Hold 粘合状态显示及操作入口。
- `client/NoteTargetResolver.java`：基于准星当前命中结果解析音符；展示实体通过 `rhythmc_note:<chartId>:<noteId>` 标签识别；提供展示实体射线候选排序。
- `mixin/client/MinecraftClientMixin.java`：在客户端 `doItemUse` 输入路径尝试打开编辑器，并在 framebuffer 呈现后提交 ImGui 绘制数据。
- `mixin/client/ClientPlayNetworkHandlerMixin.java`：接收服务器 action-bar/overlay 操作结果并反馈到编辑窗口。
- `client/RhythmcMakerClient.java`：提供统一的 `tryOpenNoteEditor` 入口。

以上是当前代码结构摘要，不是运行成功结论。尤其需检查目标解析是否覆盖：实体真实命中、方块完整体积命中、展示实体无法被原生准星拾取时的射线命中、遮挡、多实体重叠、非整数坐标显示实体和普通方块误匹配。客户端触发后还需验证 ImGui 初始化、每帧绘制和最终 framebuffer render 回调确实完整闭环。

## 四、交给协作者的实测验收清单

### 工具与输入事件

- 进入编辑维度后快捷栏第六格显示旋风棒，名称恰为“修改音符”，没有额外自定义 NBT 标记。
- 持该工具右键 TAP/LOOK/HOLD/其他支持类型的方块音符，均打开对应音符而非相邻音符的菜单。
- 持该工具右键轨道 Block Display 音符，实体能够命中并打开正确菜单；原版准星无法直接选中时也验证项目射线选择路径。
- 在音符重叠、遮挡、靠近普通方块、非整数坐标及屏幕边缘时重复测试；不应误选、不应出现方块不能点或实体无响应。
- 非编辑维度、未手持工具或右键非音符时不弹出菜单、不触发误编辑；保留原有 Alt+右键播放起点和其他写谱功能。

### UI 与编辑持久性

- 菜单确实出现在游戏画面上，而不是只有 Screen 对象已创建；窗口始终完整处于屏幕范围。
- 目标处于屏幕左/右时，菜单分别在相反侧；视角改变、目标偏轴和不同分辨率下检查左右选择及边缘裁切。
- UI 只呈现用户确认的 X、Y、Beat 与适用时的粘合操作；Z 不可见。核对 X/Y 是绝对还是相对坐标及显示基准，避免 UI 标签与实际存储坐标语义不一致。
- 改动 X/Y/Beat 后画面立即更新，服务端目标音符及展示实体一致，本地草稿异步落盘；重新打开草稿/重进维度核对数据仍在，且没有重建或重写其他音符。
- 服务器拒绝无效编辑时，客户端不要永久停留在乐观更新后的错误状态；检查是否需要用服务端回包刷新目标音符。

### Hold 回归

- 同轨道、欧氏距离恰为 1 的钻石音符能连通；距离大于 1 或不同轨道不连通。
- 验证多段传递链、跨已有 Hold 组扩展、组成员 beat 顺序、相同 beat、只有两个成员及三个以上成员。
- 成员数、视觉起止长度、判定音与运行端行为分别核对；pause、seek、隐藏、stop、close 后无残留活动状态或实体。
- 粘合/解除/类型更新有清晰但短暂的成功失败反馈；粘合成员保护和解除后可编辑/破坏的行为与用户预期一致。
