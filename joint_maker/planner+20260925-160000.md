# 3.0 分文件导入功能完善方案

- 时间：2026-09-25 16:00:00 +08:00
- 工作类型：规划创建谱面菜单、3.0 分文件导入界面与资源绑定流程
- 当前边界：只规划，不修改源码，不编译；先实现 3.0，2.0 入口保留占位。

## 一、入口调整

在开始写谱的右键菜单“创建谱面”位置增加“导入谱面”按钮。按钮应与“创建谱面”使用相同宽度和垂直间距；若原菜单宽度不足，统一增大菜单内容宽度，不使用单独超长按钮，避免中文文字裁切。

点击“导入谱面”进入 `ImportVersionScreen`，显示：

- `导入 RhythMC 2.0 谱面`
- `导入 RhythMC 3.0 谱面`
- `返回`

2.0 按钮暂时进入“功能开发中”页面或保留占位，不应误进入 3.0 流程。

## 二、3.0 页面层级

```text
开始写谱右键菜单
└─ 导入谱面
   └─ 选择版本
      └─ 3.0 分文件导入主页
         ├─ 上传难度文件
         ├─ 上传谱面信息文件
         ├─ 上传歌曲文件
         ├─ 上传场景
         ├─ 当前资源状态
         ├─ 绑定/检查资源
         └─ 创建导入草稿
```

建议 3.0 页面类名：`ImportRhythmc3Screen`。

## 三、3.0 上传主页四个入口

### 1. 上传难度文件

支持：

- `world.rmcc` → WORLD/WD
- `nether.rmcc` → NETHER/NR
- `end.rmcc` → END/ED
- `void.rmcc` → VOID/VO

流程：

1. 选择 `.rmcc`；
2. 尝试 Zstd 解压，失败后读取纯 JSON；
3. 验证 `meta/tracks/effects`；
4. 从固定文件名推断难度，非标准文件名时弹出选择难度；
5. 读取 `meta.initialArena` 和所有 `ARENA` effect 引用；
6. 将结果加入当前导入草稿，不立即覆盖本地谱面。

同一难度重复上传时必须提示：`替换当前文件 / 保留两个副本 / 取消`，默认取消或要求确认。

### 2. 上传谱面信息文件

主要支持：`manifest.yml`。

读取：

- 歌曲名 `name`
- 作曲者 `composer`
- 图标 `icon`
- 时长 `length`
- 歌曲 ID `song_id`
- 版本 `version`
- 评论 `comments`
- 谱师别名 `player-alias`

导入后只创建歌曲信息草稿，不要求此时已有音频或难度文件。

### 3. 上传歌曲文件

复用当前 `AudioFileChooser` 和 `ClientChartAccess.stageAudio` 流程。

支持：`mp3/flac/wav/ogg/m4a/aac`。

导入后：

- 复制到 Maker 本地导入暂存区；
- 计算文件哈希；
- 显示文件名、格式、大小、时长；
- 可进行 BPM/Offset 测量；
- 允许替换或解除绑定。

### 4. 上传场景

进入独立页面 `ImportArenaListScreen`，不把初始场景和普通场景设计成两种资源类型。它们都是 Arena，初始/切换只是之后的引用角色。

页面初始显示两个固定入口：

```text
初始场景
新建场景
返回
```

## 四、场景页面设计

### 初始场景入口

点击“初始场景”进入 `ImportInitialArenaScreen`，显示：

```text
上传初始场景
上传初始场景信息
返回
```

含义：

- `上传初始场景`：选择完整场景目录，或选择 `.schem` 后补选信息文件；
- `上传初始场景信息`：选择 `metadata.yml`。

这里的“初始”只是绑定角色，底层仍保存为一个普通 `ArenaAsset`。如果 `.rmcc.meta.initialArena` 指向了其他名称，导入完成后应优先按谱面引用建立绑定，并提示用户确认，不要静默覆盖。

### 新建场景入口

点击“新建场景”后：

1. 创建一个新的场景资源节点；
2. 分配显示名称 `场景1`；
3. 将该节点插入“新建场景”按钮下方；
4. 再次点击“新建场景”创建 `场景2`、`场景3`。

重要规则：

- `场景<n>` 是 UI 显示名，不一定是最终 Arena key；
- n 从 1 开始；
- 删除场景后不复用旧编号，避免已有引用指向错误资源；
- 使用稳定内部 ID 保存场景，不能依赖列表位置；
- 重新进入页面时按已保存资源恢复按钮列表；
- 每个场景节点显示状态：`未上传 / 信息已上传 / 结构已上传 / 完整 / 有错误`。

点击 `场景<n>` 进入 `ImportArenaDetailScreen`，包含：

```text
上传场景<n>
上传场景<n>信息
重命名场景
删除场景
返回
```

其中：

- `上传场景<n>`：选择 `.schem` 文件，或完整场景文件夹；
- `上传场景<n>信息`：选择 `metadata.yml`；
- 完成两者后自动校验 `metadata.yml` 的 `schematic` 文件名。

## 五、建议优化：支持直接导入完整场景文件夹

用户提出的两个上传按钮可以保留，但应额外支持“一次选择场景文件夹”：

```text
scene-key/
├─ metadata.yml
└─ arena.schem
```

如果用户选择完整文件夹，自动完成：

- 场景信息导入；
- 结构文件导入；
- 元数据与结构文件名校验。

如果用户分别选择两个文件，则两个按钮分别完成同样的两部分导入。

## 六、资源状态与绑定

主页必须显示当前导入状态，而不是只显示按钮：

```text
谱面信息：已上传 / 未上传
歌曲文件：已上传 / 未上传
WORLD：已上传 / 未上传 / 校验失败
初始场景：完整 / 不完整 / 缺失
场景1：完整 / 不完整
```

导入 `.rmcc` 后自动扫描：

- `meta.initialArena`；
- `effects[].eventType == ARENA`；
- `effects[].properties.arena`。

建立引用列表：

```text
初始场景引用：initial
第 32 拍场景引用：night
第 64 拍场景引用：boss
```

如果资源没有与引用匹配，显示缺失，但允许保存导入草稿；进入编辑、试听或导出时再按严格程度阻止。

## 七、最终确认页

增加“检查并导入”按钮，进入确认页显示：

- 歌曲信息；
- 音频文件；
- 已上传的难度；
- 初始场景；
- 所有 `ARENA` effect 引用；
- 缺失或格式错误项；
- 将要生成的本地谱面名称。

确认后：

1. 生成本地导入草稿 ID；
2. 将音频、manifest、rmcc、Arena 文件复制到安全的暂存目录；
3. 建立歌曲、难度、Arena 的绑定关系；
4. 通过 `initialArena` 和 ARENA effect 检查；
5. 只有检查通过后才允许进入编辑器。

## 八、推荐内部数据结构

```text
Rhythmc3ImportDraft
  localId
  manifestAsset
  audioAsset
  difficulties: Map<Difficulty, DifficultyAsset>
  arenas: List<ArenaAsset>
  arenaReferences: List<ArenaReference>

ArenaAsset
  stableId
  displayName
  originalKey
  metadataPath
  schematicPath
  metadataUploaded
  schematicUploaded

ArenaReference
  difficulty
  type: INITIAL / EFFECT
  beat
  originalKey
  arenaStableId
```

## 九、可导入与可进入编辑条件

允许保存草稿：资源可以不完整。

允许进入编辑器：

- 至少有一个有效 `.rmcc`；
- 该难度 JSON 可解析；
- 歌曲信息可用；
- 音频存在，或用户明确选择外部资源模式；
- `initialArena` 和所有 `ARENA` 引用已绑定，或用户确认暂不加载场景。

允许导出：

- 所有引用 Arena 完整；
- metadata 与 schematic 匹配；
- Arena key 唯一；
- `.rmcc` 引用已同步；
- 歌曲和难度信息完整。
