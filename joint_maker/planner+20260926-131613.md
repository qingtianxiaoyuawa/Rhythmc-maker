# Planner 方案记录：以歌曲时间驱动 3.0 小数音符导入

- 日期：2026-09-26
- 用户确认：希望按歌曲时间放置音符；RhythMC 支持小数 note，后续 Maker 也会增加该功能，不需要强制转整数方块。

## 结论

- 可以使用歌曲时间作为导入/播放的精确校验依据，但不建议彻底替代 3.0 的 beat。
- 推荐模型：`beat` 是谱面权威位置，`timeSeconds` 是由 BPM 时间轴派生的播放时间；世界 Z 坐标由 beat 映射，支持小数坐标并使用 BlockDisplay。
- 对变 BPM 谱面，必须使用分段 BPM 时间轴完成 beat↔seconds 转换，不能使用 `beat * 60 / 首 BPM`。
- offset 属于播放时间边界修正，不应混入编辑器空间 Z 坐标；播放时再统一应用。

## 推荐导入流程

1. 读取 3.0 音符 `beat`，保持原始小数精度。
2. 使用完整 BPM 事件表计算 `note.time = beatToSeconds(beat)`。
3. 需要按歌曲时间定位时，用 `secondsToBeat(time)` 反算 beat，再用 `z = -3 - beat * divisionsPerChunk` 得到编辑器位置。
4. 不对 beat、time 或 z 做整数舍入；X/Y 也按 3.0 空间坐标语义保留小数。
5. 整数位置可使用普通方块，小数位置使用 BlockDisplay；两者共享同一份 note 数据和 beat/time。
6. 导入完成后用 `beat -> time -> beat` 做误差校验，验证变 BPM 和小数音符没有漂移。

## 为什么不能只存歌曲时间

- BPM 变化时，歌曲时间和 beat 的关系是分段函数；只存 time 会丢失谱面逻辑拍位置、speedEvents 对齐和编辑器分数定位语义。
- Maker 轨道的空间位置仍需要一个 beat 到世界距离的映射；使用 time 直接放置本质上仍要先通过 timing 反算 beat。
- 因此歌曲时间适合作为播放/音频边界，beat 适合作为谱面编辑权威值。
