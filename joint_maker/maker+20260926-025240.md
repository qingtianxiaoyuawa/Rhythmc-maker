# Maker 修复记录 - 20260926-025240

## 目标

修复制谱器轨道上的旧 `BlockDisplay` 无法在视距外完整删除的问题，并完成离线构建和部署验证。

## 证据与完整原因链

- 用户 F3 截图显示 `E: 0/268`：当前没有被渲染的实体，但客户端仍记录 268 个实体，符合远处或隐藏位置仍残留展示实体的现象。
- 原有 `ServerWorld.getEntitiesByType` 只能枚举已经进入服务器实体管理器的实体；未加载区块中的实体 NBT 不会被这次枚举删除。
- 2:17 版本的扫除逻辑以 `world.getChunk` 后立即删除为主，未保持区块到实体数据稳定；随后又把历史清理长度收缩到当前轨道，导致未及时进入实体管理器的远端实体失去后续强制扫除范围。
- 旧实体可能带有旧谱面 ID、旧标签格式或没有 `rhythmc_note:` 标签，原筛选只删除当前 chart ID 前缀的实体。
- 播放预览的对象池会把已回收 `BlockDisplay` 移到 `(200, -64, 0)`，但原停止播放逻辑只删除活跃表，不删除对象池；每次播放都可能永久累积隐藏实体。这是本轮发现的独立泄漏来源。
- 快速重复刷新会替换尚未完成的扫除任务、图表缓存或磁盘读取失败会阻断扫除，仍可作为运行时排查点；本轮保留日志异常路径，未对无关逻辑重构。

## 已修改

- `src/main/java/cn/frkovo/rhythmcmaker/RhythmcMaker.java`
  - 强制扫除时使用 `setChunkForced(..., true)` 持有远端 chunk。
  - 每个强制 chunk 在后续三个 tick 进行复核，最后释放强制加载，避免只在区块/实体加载的错误时机清理一次。
  - 不再在扫除结束后缩小持久化的历史清理长度和宽度；后续刷新继续覆盖已知最大轨道范围。
  - 当前谱面、异谱面、遗留无标签的轨道 `BlockDisplay` 都按轨道边界清理；播放区域 `x=200` 不在此范围，避免影响当前播放。
  - 停止播放时同时删除 `displays` 与 `displayPool` 中的实体；配置制谱世界时删除无活动会话的 `rhythmc_preview` 残留。
- `gradle.properties`
  - 版本由 `1.3.4` 更新为 `1.3.6`。
