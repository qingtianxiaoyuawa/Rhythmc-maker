## 二、历史功能理解与确认

### 轨道坐标规则

- 播放/编辑坐标原点规则为 `CHART_ORIGIN_Z = -2.5`。
- 方块 `z = -3` 的中心坐标是 `-2.5`，因此它代表第一个时间位置。
- 通过方块坐标反算 beat 时，使用方块中心 `blockZ + 0.5`。
- 当前服务端吸附目标规则为：小数 `z` 向较小整数方向吸附，例如 `-2.5 -> -3`。
- `PlaybackCoordinates.editorBeatAtBlockZ` 依据 `CHART_ORIGIN_Z`、方块中心和 `divisionsPerChunk` 反算 beat。
- `ChartTiming.beatToSeconds` 再依据 BPM/BPM 事件将 beat 转为 time。

### 吸附重复规则

- 当前活动谱面处理全部小数 `z` 音符。
- 吸附键使用 `x + y + 吸附后的 z + type`。
- 完全相同的键视为重复，保留 `chart.notes` 原列表中最早出现的音符。
- `type` 相同才视为重复；不同 type 即使位置相同也保留。
- 吸附操作只修改约定的 `z`、`beat`、`time` 三个字段，其他音符字段保持不变。
- 撤销只保留最近一次吸附记录。

### UI 和操作确认

- 第一层吸附菜单显示完整统计。
- 第二层最终确认页显示完整统计和警告，避免用户在最终确认时失去上下文。
- 没有需要吸附的音符时不进入第二层，确认按钮禁用并显示“没有需要吸附的音符”。
- 吸附过程中关闭菜单，显示“正在吸附中”，并在状态栏每秒更新进度。
- 吸附等待期间禁止编辑操作，但不锁定玩家移动和攻击。
- 完成后显示“轨道吸附完成”和结果统计。
- 撤销后保持在轨道吸附子菜单并刷新统计，便于立即检查。
- 修改每 Chunk 分数时，按最新 beat 和最新每 Chunk 分数重新计算音符坐标，不保持旧坐标。

## 三、我的关键决策

1. 将本轮问题定位为服务端数据状态问题，而不是只修复吸附菜单按钮。
2. 将撤销记录扩展为“吸附前音符 ID 集合 + 被修改音符快照 + 被删除音符快照”。
3. 撤销时按音符 ID 判断是否为吸附前存在的音符：
   - ID 在吸附前集合中：保留并按快照恢复。
   - ID 不在吸附前集合中：视为吸附后新增音符，撤销时删除。
4. 让普通放置、实际破坏、WorldEdit 同步和布局修改统一调用撤销失效逻辑。
5. 只在确实发生了音符变化时使撤销失效，避免仅点击破坏无关方块就错误清除撤销状态。
6. 新增服务端撤销失效通知集合，由客户端 tick 消费通知，只清理撤销按钮状态和吸附摘要缓存。
7. 修复谱面缓存：`cacheChart` 在已有缓存状态存在时显式更新 `state.chart`，避免保存新对象后后续读取旧对象。
8. 吸附完成和撤销完成都重新计算 `chart.totalBeats`，确保持久化数据的摘要字段与音符数据一致。
9. 版本从 `1.13.9` 递增到 `1.13.10`，按本次 BUG 修复使用 patch 版本递增。

## 四、我的关键理解错误与过程问题

1. **首次批量补丁错误处理换行。**
   - 临时 PowerShell 脚本把 `\r\n` 当作实际 CRLF，而源码实际使用 LF，导致脚本第一次没有修改源码。
   - 脚本还包含一个无效的客户端替换模式，执行到该处中止。
   - 后续通过检查 `rg` 结果和构建结果确认实际改动，再修正客户端调用。

2. **客户端服务调用对象一度写错。**
   - 初始补丁误写为 `ClientSceneAccess.consumeTrackSnapUndoInvalidation()`。
   - 实际服务端方法属于 `RhythmcMaker`，随后修正为：
     `RhythmcMaker.consumeTrackSnapUndoInvalidation(client.player.getUuid())`。

3. **早期只关注按钮状态，没有先完整建模撤销数据。**
   - 仅清除 `TRACK_SNAP_UNDOS` 不能解决“撤销后删除吸附后新增整数音符”的问题。
   - 根因是旧撤销记录没有保存吸附前的音符 ID 集合，后来改为保存原始 ID 集合。

4. **早期没有充分区分缓存对象和持久化对象。**
   - `computeIfAbsent` 只在第一次创建缓存时保存对象引用，后续传入新 `ChartManifest` 可能使缓存继续引用旧对象。
   - 这会造成“内存中看似修改成功，但后续读取或异步保存仍使用旧数据”的风险，后来补上了显式引用更新。

5. **没有在本轮完成游戏内交互验收。**
   - 已完成离线编译、产物校验和部署校验。
   - 尚未在实际 Minecraft 世界中逐项操作验证普通放置、普通破坏、WorldEdit、改分数、吸附、撤销和新增音符删除组合场景。
   - 因此不能把本次结果表述为已经完成完整运行时验收。
