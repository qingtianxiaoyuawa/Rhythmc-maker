## 共同 UI 架构

两者都不是以 Minecraft 原生 `Screen` 为核心的编辑器 UI，而是：

```text
Minecraft 渲染循环 / HUD Hook
  + Dear ImGui Context
  + GLFW 输入桥接
  + OpenGL/Blaze3D 自定义 ImGui 渲染器
  + 多个可独立开关、悬浮的编辑窗口
```

共同证据：

- Flashback：`editor/ui/ReplayUI`、`CustomImGuiImplGlfw`、`CustomImGuiImplGl3`；
- Axiom：`editor/EditorUI`、`CustomImGuiImplGlfw`、`CustomImGuiImplGl3`、`CustomImGuiRenderer`；
- 两者都有 `setupMainViewport`、输入/鼠标坐标转换、字体加载、`drawOverlay`、窗口焦点/悬浮判断等基础设施。

它们可以让玩家保持在 3D 世界中，同时叠加停靠面板、浮动窗口、拖拽控件与快捷键处理。

## Flashback：适合借鉴的内容

Flashback 的重心是回放、镜头和关键帧编辑：

- 中央控制器：`ReplayUI`；
- 时间编辑数据：`SavedTrack`、`SelectedKeyframes`、`CopiedKeyframes`；
- UI 窗口：`TimelineWindow`、`MainMenuBar`、`MovementWindow`、`PlayerListWindow`、`PreferencesWindow`、导出队列/截图窗口等；
- 具有相机移动模式：`Arcball`、`Pan`、`Rotate`；
- 使用窗口开关状态：`WindowOpenState`；
- 有独立的 ImGui GLFW 多视口桥接类，能够处理原生窗口创建、移动、尺寸、焦点、SwapBuffers 等。

对 Maker 特效编辑最值得借鉴：

```text
时间轴 + 多轨道
关键帧的选择/复制/粘贴/拖拽
右侧属性检查器
底部播放、循环、速度控制
中间保持 Minecraft 场景实时预览
```

## Axiom：适合借鉴的内容

Axiom 的重心是世界内空间编辑和工具化工作流：

- 中央控制器：`EditorUI`；
- 窗口分类：`EditorWindowType`；
- 窗口：`ToolsWindow`、`ToolOptionsWindow`、`PaletteWindow`、`HistoryWindow`、`StyleEditorWindow`、`WorldPropertiesWindow`、`BlueprintBrowserWindow` 等；
- UI 基础：`ImGuiHelper`、`StyleManager`、`BuiltinStyles`、`ViewManager`；
- 可复用交互模式：`SearchableCombo`、`PresetWidget`、`SelectBlockWidget`、`BlockStateWidget`、`TagListWidget`；
- 额外提供 `ContextMenuManager`、`KeyPressOverlay`、放置选项 overlay、历史记录和蓝图预览；
- 资源中有独立 GUI sprite（背景、slot、tab active/inactive、filter、return 等），但不应直接复制。

对 Maker 特效编辑最值得借鉴：

```text
左侧工具栏
可搜索的特效类型选择器
预设 / 收藏配置
属性面板
撤销/重做历史
世界内 Gizmo、选中高亮和预览 Overlay
右键上下文菜单
```

## 不能直接“引入”其 UI 的原因

1. 两者的 ImGui 包被重定位为不同命名空间：

```text
Flashback: imgui.moulberry90
Axiom:     imgui.moulberry92
```

不能把其内部 UI 类当作稳定公共 API 直接调用。

2. 二者都有自定义 GLFW/OpenGL 后端和输入、HUD、Screen Mixin；Maker 再接入其中之一会存在：

- 鼠标/键盘重复接管；
- ImGui Context 冲突；
- 渲染状态污染；
- GLFW 多视口窗口冲突；
- Minecraft/Blaze3D 版本更新后崩溃。

3. Axiom 的 `fabric.mod.json` 声明许可证为 `All Rights Reserved`，不能复制其代码、纹理或直接打包其 UI 实现。

4. Flashback JAR 的 `META-INF/LICENSE` 是某个打包依赖的 MIT 文本，不足以证明 Flashback 自身编辑器代码可被直接复制；需要以其源码仓库的实际许可证为准。即使可参考，也不要直接拷贝 JAR 内类或资源。

## 对 RhythMC Maker 的推荐方案

### 第一阶段：继续使用现有 Owo Screen

Maker 当前已使用 Owo UI。先实现自己的 `EffectEditorScreen`：

```text
左：特效轨道列表
中：按 beat 划分的滚动时间轴
右：特效属性表单
下：播放/暂停、循环、起始拍、撤销/重做
```

优点：集成风险低、依赖已存在、适合先完成导入 `.rmcc.effects` 的编辑与保存。

### 第二阶段：仅在需要专业时间轴时引入独立 ImGui

不要依赖 Flashback/Axiom 的内部类；选择一个明确授权、独立打包的 ImGui Java 依赖，自建：

```text
MakerEffectEditorUi
  ImGuiContext 生命周期
  Minecraft 输入桥接
  单一 Overlay Render Hook
  TimelinePanel
  TrackListPanel
  InspectorPanel
  PreviewControls
```

必须保证：

- Maker 只创建一个自身 ImGui context；
- 打开编辑器时才接管输入；
- 关闭编辑器时完整释放状态；
- 不启用 ImGui 多视口，除非明确需要独立原生窗口；
- 与 Flashback/Axiom 同时安装时不调用其内部包、类和 Mixins。

### 第三阶段：空间特效编辑

借鉴 Axiom 的工作流，而不是实现：

```text
选中特效实体
显示平移/旋转/缩放 Gizmo
使用右侧 Inspector 修改参数
写入 Effect keyframe
预览时生成临时 DisplayEntity
退出时清理临时实体
```

## 推荐优先级

1. 先完成 `.rmcc.effects` 的保真保存和列表查看。
2. 实现 Owo 版基础特效轨道编辑器。
3. 加入撤销/重做、特效预设、效果属性验证。
4. 加入世界内预览和选中高亮。
5. 最后评估是否需要独立 ImGui 时间轴。
