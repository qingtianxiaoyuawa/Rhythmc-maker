# RhythMC Maker 规划：参考 Malody 的自动 BPM 与偏移校准方案

- 记录类型：planner
- 时间：2026-09-25 00:55:08 +08:00
- 目标：自动测量 BPM 和对齐值，并最终写入 RhythMC 3.0 的**谱面偏移**。

## 设计原则

参考 Malody 的价值在于将：

`	ext
BPM（节拍周期）
歌曲与节拍网格的对齐（歌曲偏移）
`

视为独立问题；但 RhythMC Maker 最终不能保存 Malody 的歌曲偏移，而必须保存 RhythMC 3.0 的谱面偏移。

因此不要将“Malody offset 数值”直接加负号后写入 RhythMC。应统一通过一个物理中间量转换：

`	ext
firstDownbeatAudioMs
= 原始歌曲中、被定义为 RhythMC beat 0 的第一重拍实际音频时间
`

然后按 RhythMC 3.0 的时间模型：

`	ext
beatTimeMs(beat) = rhythmcChartOffsetMs + beat * (60000 / bpm)

rhythmcChartOffsetMs = firstDownbeatAudioMs
`

若未来导入 Malody .mc，先根据已验证的 Malody 播放公式把其歌曲 offset 还原为 irstDownbeatAudioMs，再写入 RhythMC。这样不会依赖字段名字或正负号猜测。

## 用户流程（Malody 风格，RhythMC 输出）

`	ext
导入音频
  -> [自动校准 BPM / 偏移]
  -> 分析歌曲
  -> 显示 BPM 候选、第一重拍建议、置信度
  -> 预听 4 小节：网格 + 节拍器 + 重拍标记
  -> 谱师微调或确认
  -> 应用为 RhythMC BPM + 谱面偏移
`

校准界面必须明确显示：

`	ext
BPM：180.00
RhythMC 谱面偏移：+483 ms
含义：RhythMC 的 beat 0 / 首音符网格位于歌曲 483 ms 处。
`

禁止使用没有参照系的“Offset：483”文案。

## 自动分析算法

### A. 音频预处理

- 使用实际 PCM 解码；建议 FFmpeg 输出单声道、22050Hz 或 44100Hz PCM。
- 跳过前导静音；寻找第一段节奏稳定且能量足够的 20–60 秒窗口。
- 提取 onset envelope：一期可复用能量差分，推荐升级为多频段 spectral flux。
- 额外提取低频 onset/kick envelope，用于判断小节第一重拍。

### B. BPM 候选

- 从 onset envelope 计算 tempogram/自相关，生成 Top 3–5 BPM 候选。
- 同时保留半拍、原拍、倍拍候选，例如 90 / 180 / 360（按 RhythMC 支持范围裁剪）。
- 不再执行“整十 BPM”或“4 BPM 网格”的强制取整；保留至少两位小数。
- 输出每个候选的周期、分数与置信度。

### C. 节拍网格相位

对每个 BPM 候选：

`	ext
T = 60000 / BPM
`

遍历候选相位 phase，使强 onset 最接近：

`	ext
phase + n * T
`

最大化加权对齐分数：

`	ext
score(phase) = Σ onsetStrength_i * kernel(distanceModulo(onsetTime_i, phase, T))
`

通过加权循环直方图得到初始 phase，再使用鲁棒拟合微调 BPM 与 phase。该步骤避免将歌曲开头的偶然音效误当作第一拍。

### D. 第一重拍（4/4）

在得到“每拍网格”后，比较四种小节相位：

`	ext
phase + 0T
phase + 1T
phase + 2T
phase + 3T
`

统计连续多个小节中每类位置的：

- 低频 onset/kick 强度；
- 总 onset 强度；
- 重音稳定性。

最高分的一类视为下拍（downbeat）。取歌曲时间大于等于 0 的最早下拍，得到：

`	ext
firstDownbeatAudioMs
`

### E. 映射为 RhythMC 谱面偏移

不保存 Malody 歌曲偏移。直接执行：

`	ext
rhythmcChartOffsetMs = firstDownbeatAudioMs
`

并在 RhythMC 的节拍网格预听中验证：

`	ext
歌曲第一重拍 == RhythMC beat 0
`

## 置信度与人工确认

自动结果必须是建议，不得直接覆盖谱面：

- 高：连续小节节拍和重拍都稳定；
- 中：BPM 稳定、但四拍中的第一拍不够明确；
- 低：BPM 候选接近、变速、无鼓、弱起或人声干扰明显。

确认 UI：

- 播放/暂停；
- 循环前 4 小节或选定的 4 小节；
- 节拍器与 beat 0/小节线闪烁；
- ±1 / ±10 / ±100 ms 调整 RhythMC 谱面偏移；
- 上一拍是第 1 拍 / 这一拍是第 1 拍 / 下一拍是第 1 拍，每次按一个 T 修正小节相位；
- “应用”与“取消”分离，取消不修改当前谱面。

## 模块建议

`	ext
AudioDecoder
  -> OnsetExtractor
  -> TempoCandidateFinder
  -> BeatPhaseEstimator
  -> DownbeatEstimator
  -> TimingCalibrationResult
  -> TimingCalibrationScreen
  -> ChartManifest.bpm + ChartManifest.offsetMillis
`

关键数据结构：

`java
record TempoCandidate(double bpm, double score) {}

record TimingCalibrationResult(
    List<TempoCandidate> candidates,
    double selectedBpm,
    long firstDownbeatAudioMs,
    long rhythmcChartOffsetMs,
    Confidence bpmConfidence,
    Confidence downbeatConfidence
) {}
`

## Malody 导入转换（后置）

若实现 .mc 导入：

`	ext
Malody songOffset
  -> MalodyTimingAdapter.audioTimeAtBeatZero(...)
  -> firstDownbeatAudioMs
  -> RhythMC chartOffsetMs
`

必须写单元测试验证 Malody 的实际播放公式。不要把 -malodyOffset 写死为全局转换规则；只有在该公式已被样例验证后，才将取反作为 adapter 内部实现细节。

## 一期验收

1. 导入固定 BPM、首拍清晰的歌曲后，展示多个 BPM 候选与置信度。
2. 选定候选后，自动给出 RhythMC 谱面偏移 建议。
3. 确认后，RhythMC beat 0 与歌曲第一重拍在预听中对齐。
4. 对弱起/无鼓/变速歌曲，不强制自动提交，显示低置信度并允许微调。
5. ChartManifest.offsetMillis 和导出的 RhythMC 3.0 meta.offset 与最终确认值一致。
6. Malody offset 不直接写入 RhythMC；未来导入经过显式 adapter 转换。
