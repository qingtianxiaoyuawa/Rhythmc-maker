## 当前界面与参考图的差距

当前 `EffectEditorImGuiView` 已经有顶部栏、左侧特效库、中间预览、右侧检查器和底部时间轴的基本分栏，但仍属于功能原型：

- 中间“世界预览”主要显示文字、相机坐标和状态，没有真正的场景视图容器与视觉工具层。
- 左侧特效库是纵向文本 selectable 列表，没有搜索、分类、图标卡片和紧凑网格。
- 底部时间轴主要是播放头、输入框和事件列表，不是参考图中的多轨道时间轴。
- 右侧检查器以通用文本和控件堆叠为主，没有按参数类型分组，也缺少视觉层级、曲线/关键帧和预览缩略图。
- 顶部栏缺少参考图中的项目选择、BPM/当前位置、撤销重做、播放组和设置分区。
- 当前布局在窄窗口下依赖最小宽高，可能出现面板挤压；需要建立可折叠和响应式布局。

## 目标布局

采用参考图的“顶部工具栏 + 左侧资源栏 + 中央场景视口 + 右侧属性栏 + 底部时间轴”结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ 项目/谱面 | BPM | 当前 Chunk/Sub-beat | 撤销 重做 保存 播放 设置 │
├──────────────┬──────────────────────────────┬───────────────┤
│ 工具条/特效库 │                              │ 特效参数检查器 │
│ 搜索/分类     │       Minecraft 场景视口     │ 关键帧/属性     │
│ 特效卡片      │       相机/辅助线/选中框      │ 小型预览        │
├──────────────┴──────────────────────────────┴───────────────┤
│ 播放控制 | Chunk 标尺 | 音符/透明度/位移/旋转/缩放/特效轨道      │
└──────────────────────────────────────────────────────────────┘
```

## 视觉规范

- 背景：深蓝灰，不使用纯黑；面板之间用细边界和轻微明度差区分。
- 主强调色：青色/蓝绿色，用于当前选中、播放状态、播放头和主按钮。
- 轨道颜色保持语义编码：音符蓝色、透明度青绿、位移橙色、旋转紫色、缩放蓝色、特效金色。
- 面板圆角和阴影克制，避免卡片套卡片；重复特效项目使用紧凑卡片即可。
- 顶部、左侧、右侧和时间轴使用固定停靠区域；中央视口填充剩余空间。
- 所有按钮使用图标 + 短标签或仅图标；悬停显示 tooltip。
- 文字优先使用简洁中文，避免把使用说明长句直接显示在主界面。
- 视口必须是视觉主焦点，不能被说明文字占据。

## 模块拆分

### 1. 顶部工具栏

分为四组：

- 项目组：RhythMC Maker、当前谱面下拉框、难度/场景。
- 时间组：BPM、当前 Chunk、Chunk 内分数、songTime。
- 编辑组：撤销、重做、保存状态。
- 播放组：跳到开头、播放/暂停、停止、跳到结尾、设置。

顶部显示值必须来自统一播放状态，不能自行计算第二套时间。

### 2. 左侧特效库

分为窄工具条和资源面板：

- 工具条：选择、移动、旋转、缩放、聚焦、吸附。
- 搜索框：按显示名和 eventType 过滤。
- 分类树：标题/消息、文字、天气/时间、粒子、全息图、音符、发光、场景。
- 特效卡片网格：图标、名称、简短类别色；点击新增到当前播放头。
- 未知事件单独显示为“只读事件”，不能在卡片区误改。

事件新增逻辑保留当前 `addEffect`，只替换选择器呈现方式。

### 3. 中央 Minecraft 场景视口

当前世界已经透出，但需要增加真正的视口层：

- 视口顶部显示当前相机 A/B、场景名、预览状态。
- 左上角保留工具按钮。
- 右上角显示视口最大化、网格、辅助线、相机锁定和显示/隐藏轨道。
- 场景中显示选中特效边界框、坐标轴、判定线、当前播放位置和目标标记。
- 右下角显示 X/Y/Z 坐标轴。
- 视口底部显示当前 Chunk/Sub-beat 和相机状态。
- 不在视口内放大段说明文字；状态使用短标签和 tooltip。

视口 UI 与实际 Minecraft 世界渲染分离：ImGui 只负责边框、辅助线和控件，真实场景仍由客户端渲染管线提供。

### 4. 右侧属性检查器

按层级分组，而不是把字段平铺：

- 事件头：图标、事件名称、eventType 下拉框、启用开关。
- 时间：Chunk、Chunk 内分数、Beat、持续时间、缓动曲线。
- 轨道：所属轨道、目标对象、触发条件。
- 变换：位置 X/Y/Z、旋转 X/Y/Z、缩放 X/Y/Z。
- 外观：文本、颜色、透明度、背景色、发光色。
- 动画：关键帧列表、插值方式、添加关键帧、重置。
- 底部：应用、重置、删除事件。

属性控件按类型统一：数字输入带步进、颜色使用色块与颜色选择器、枚举使用下拉框、向量使用三列紧凑输入。

### 5. 底部时间轴

这是与参考图差距最大的部分，需要从事件列表升级为轨道编辑器：

- 顶部播放控制和当前时间信息。
- 标尺基准使用 `Chunk + Chunk 内分数`，底层转换仍走 `ChartTiming`。
- 红色播放头贯穿标尺和所有轨道。
- 左侧固定轨道标签列，右侧为可横向滚动的轨道内容区。
- 第一阶段轨道：音符、透明度、位移、旋转、缩放、特效。
- 特效轨道显示可拖动事件块，而不是纯文本列表。
- 动画轨道显示关键帧菱形点和折线；暂不要求首版支持复杂贝塞尔编辑。
- 轨道支持锁定、静音/隐藏、折叠和独立显示。
- 时间轴拖动必须调用完整 seek：音频、服务端判定、Camera Z、特效采样和播放头同步更新。
- 保存不退出时不停止播放；关闭编辑器时按既有生命周期停止和恢复。

## 数据与交互边界

- UI 重构不能重新定义播放逻辑。
- 当前 `workingEffects`、保存、未知事件原样保留机制继续保留。
- 特效 UI 编辑只修改特效对象和相机轨道数据，不修改音符坐标和正式播放计算。
- 轨道显示可从现有 effects、animation.channels 和 ChartTiming 派生，不复制一套长期独立数据。
- 选中特效、拖动事件块、修改属性和添加关键帧都设置 dirty，并通过现有保存队列处理。
- 所有时间显示统一使用同一播放状态，避免顶部、时间轴和检查器各自显示不同数值。

## 实施阶段

1. 先重做 ImGui 主题、停靠布局、顶部工具栏和面板边界。
2. 将左侧特效库改为搜索/分类/卡片网格。
3. 将中间文字预览改为真实视口容器，接入相机 A/B 标记和辅助线。
4. 将右侧检查器改为分组折叠、类型化控件和关键帧区。
5. 将底部事件列表改为轨道标签、标尺、事件块和关键帧绘制。
6. 增加拖动事件块、拖动关键帧、缩放时间轴和吸附到 Chunk/Sub-beat。
7. 最后处理响应式布局、窄窗口折叠、tooltip、滚动条和性能优化。

## 性能要求

- 仅更新可见时间轴范围，不每帧遍历整张谱面绘制所有事件。
- 事件块和关键帧使用可见区间索引；大谱面只绘制窗口附近的内容。
- ImGui 绘制不能触发完整 JSON 解析、保存或场景重建。
- 视口辅助线使用轻量客户端绘制，不通过服务端 setBlockState 创建临时方块。
- 双虚拟相机仍按前一规划执行；首版 UI 只显示单主视口，可用小窗/切换查看第二视角。
- 参考图的双预览属于后续 framebuffer 阶段，不与第一轮 UI 重构绑定。

## 验收标准

- 界面结构在视觉上接近参考图：顶部工具栏、左特效库、中间视口、右检查器、底部多轨时间轴完整存在。
- 中央区域以 Minecraft 场景为主，不再被占位说明文字替代。
- 左侧可搜索、分类和添加特效，右侧可分组编辑属性。
- 底部能看到 Chunk 标尺、播放头、特效事件块和关键帧。
- 拖动时间轴或事件块时，音频、服务端判定、Camera 和特效状态统一 seek。
- 保存不退出不停止播放；真正关闭时停止预览并恢复状态。
- 大谱面下 UI 不因重绘时间轴而重新解析或保存完整谱面。
- 未知事件仍能显示并原样保存；旧谱面无新字段时界面正常工作。
