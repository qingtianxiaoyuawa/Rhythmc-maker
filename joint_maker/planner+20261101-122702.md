# RhythMC Maker 下一阶段编辑器建设规划

日期：2026-11-01

## 规划范围

下一阶段目标是完成三类编辑能力：

1. 完善场景编辑器。
2. 将现有特效编辑器提升为剪辑软件式工作区，并支持一键生成/应用预设。
3. 建设面向音符与轨道的独立编辑器。

本记录只定义产品边界、依赖、实施阶段、风险与验收；不代表功能已实现，不涉及源码修改、编译或测试。

## 当前基线（源码快照）

- 场景编辑目前由 `SceneEditScreen` 提供场景列表和基础元数据表单；场景结构的实际搭建仍依赖游戏世界中的编辑区域。`SceneEditStorage` 已负责场景元数据和 `.schem` 存取。因此目标是完善场景工作流、资源边界和可靠性，而不是从零创建场景系统。
- 特效编辑器已有 `EffectTrackScreen`、ImGui 视图、时间轴/轨道布局模型、参数编辑器、播放/暂停/重播/seek 和保存链路；布局数据与关键帧位置已有本地保存模型。用户所说的新特效编辑器应理解为重做信息架构和操作体验，同时复用已存在的播放时钟、参数 Schema、编解码和兼容逻辑。
- 音符编辑当前有 `NoteEditScreen` 单音符属性浮窗（X/Y/Beat）和 Hold 粘合命令，也有轨道播放/布局及 Hold 合并相关基础；尚不足以视作完整的音符轨道编排器。
- 旧规划已指出场景结构扫描/保存可能存在固定大体积工作量；音符播放规划要求优化不得改变正式播放、判定、特效触发语义，并需将长 Hold 按区间处理。这些属于实现约束，不应被编辑器重构绕过。

## 总体设计原则

1. **以现有谱面/特效/场景协议为权威。** 编辑器是对数据的可视化编辑层；不另造与 RhythMC 3.0 导出不兼容的播放协议。
2. **先定领域语义，再定 UI。** 先明确音符、Hold 区间、特效事件/关键帧、轨道、场景引用和预设的身份及持久化边界，避免三个编辑器各自发明重复字段。
3. **共享能力要小而实用。** 可共享选中状态、脏状态/保存反馈、撤销重做操作接口、时间格式化/Beat 转换和错误提示；不先建设庞大的通用编辑器框架，也不把与时间轴无关的场景编辑强行时间轴化。
4. **预览和正式播放区分清楚。** 编辑预览可 seek 和暂停，但不得无意触发正式判定或改变导出语义；场景/特效/音符编辑均应能从数据回到可验证的游戏内表现。
5. **先保证语义正确和可恢复，再追求操作密度。** 删除、批量变更、场景覆盖、预设应用等高影响操作要可撤销或明确确认；长耗时保存需有进度与失败恢复。

## 依赖关系与推荐顺序

```text
领域数据与持久化契约
        ├── 场景编辑器可靠性与场景资源工作流
        ├── 音符/轨道模型（尤其 Hold 区间、选区和 Beat 映射）
        └── 特效剪辑模型（事件片段、关键帧、轨道、场景引用）
                └── 剪辑式时间轴 UI 与预设系统
```

推荐阶段：

- **阶段 0：编辑器契约与公共底座**：审计并书面确认各自的数据边界、稳定 ID、保存入口、预览时钟来源、撤销/重做最小接口；确定场景、音符、特效数据的版本迁移与兼容策略。只抽取三个编辑器都会使用且已经出现重复的能力，不因“统一”而重写稳定播放链路。
- **阶段 1：场景编辑器完善**：先完善场景列表/详情/资源状态和结构编辑闭环；再处理结构选区/边界、保存性能、异步状态、失败恢复与场景预览；最后补齐场景与特效引用关系。它是后续特效预设中场景引用合法性的基础。
- **阶段 2：音符轨道编辑器**：先稳定 note 与 Hold 的可编辑模型、Beat 到时间/空间转换和同步保存，再实现网格与轨道视图、创建/选择/框选/移动/复制/删除、吸附与批量属性编辑，最后补齐 Hold 区间可视化、续接/拆分/调整长度以及试听/定位。
- **阶段 3：全新特效剪辑编辑器**：先确定剪辑事件和关键帧数据如何映射既有 RhythMC 特效 JSON；再实现剪辑软件式布局（预览、时间标尺/播放头、多轨道、属性 Inspector、素材/效果库），随后完善拖拽、裁切、复制、吸附、关键帧曲线和快捷操作；末尾交付预设库和批量应用/生成流程。
- **阶段 4：跨编辑器集成验收**：检查场景引用、特效预设、谱面保存/再载入、导出与正式播放的闭环；回归旧文件迁移和未知字段保留。

若用户要优先看到特效界面，可在阶段 0 后制作只读/交互原型验证布局；不建议先做完整特效 UI 再回头改变数据模型。

## 三个编辑器的交付范围

### 1. 场景编辑器

- 场景集合：创建、重命名、复制、删除、选择默认/初始场景；显示未保存、缺文件、引用中、保存中/失败等状态。
- 场景属性：稳定场景 ID 与展示名称分离；编辑范围/锚点/坐标基准/预览相机等字段时显示单位、约束与校验结果。字段必须以项目现有协议为准，未确认的相机或坐标字段不能先写入导出格式。
- 结构编辑闭环：明确选区边界及“保存结构/重载结构/恢复上次保存”的语义；保存前预览影响范围，避免固定扫描巨大体积；大结构采用分批/异步准备并在主线程安全应用游戏世界操作。
- 场景关系：展示哪些特效/预设引用场景；删除被引用场景时阻止或要求先处理引用，不静默留下失效 ID。
- 可视化：场景缩略图或简单预览、结构尺寸和坐标范围；不要求第一阶段实现复杂三维场景编辑器。

### 2. 剪辑式特效编辑器

- 主工作区：中央游戏预览，顶部播放控制/保存/撤销重做，时间标尺与播放头，多轨道剪辑区，侧边效果/素材库与属性 Inspector；支持缩放、滚动、选中态与快捷键，密度优先级低于清晰度。
- 时间模型：继续统一使用已有 ChartTiming/Beat 时钟；UI 显示 Beat/小节格式但内部和 seek 必须映射到同一时钟。时间轴拖动要真实 seek 预览，不得只动 UI 播放头。
- 事件/关键帧：支持事件片段和点事件的明确视觉差异；可编辑关键帧、插值/缓动（仅限底层协议支持项）；类型专有参数继续走现有参数 Schema 和 codec。未知或不支持事件必须保留并明确标记，不能保存时丢弃。
- 一键预设：从当前选中事件/片段或轨道选择“保存为预设”；预设可包含特效类型、参数、关键帧/持续时间及必要的场景引用，默认保存到 Maker 本地预设库，不污染 Reborn 导出 JSON。应用预设时提供插入位置、轨道目标、Beat 对齐方式、覆盖/追加策略预览；执行后生成可撤销的标准编辑操作。
- 预设校验：写入前执行字段 Schema 校验、类型迁移、场景引用检查、时间/轨道合法性校验；说明缺失资源/字段并允许取消，禁止静默填充错误默认值。

### 3. 音符轨道编辑器

- 编辑视图：以 Beat 网格横向排列，轨道/判定道纵向组织；一屏可读出 TAP/LOOK/DODGE 等点音符与 HOLD 起止区间，不将 Hold 展开成无界数量的独立实体。
- 基础操作：新增、选择、框选、多选移动、复制、删除、吸附、对齐、批量改类型/轨道/坐标；快捷键有可见提示。所有操作直接更新统一 chart 模型并能保存/重载。
- Hold：明确起点、终点、组 ID 和持续时长；支持拉伸、缩短、拆分、合并/续接，并保证导入/导出及正式播放所需 Hold 语义不变。若底层协议尚不能表示区间，应先补充兼容映射方案，不以 UI 假造完整 Hold 编辑能力。
- 编辑一致性：点击/拖动对应唯一 note ID；网格吸附精度与当前 subdivisionsPerBeat 一致；位置、Beat、音频时间和播放预览一致；批量操作可撤销，非法冲突给出原因。

## 里程碑验收

- **阶段 0**：存在各数据对象的字段/ID/生命周期映射表；确认哪些数据是导出协议、哪些仅本地 UI 状态；迁移策略和未知字段保留规则明确；没有改变正式播放逻辑的隐性改动。
- **场景编辑**：新建至保存、关闭重开、复制/重命名、恢复结构、删除被引用场景等链路可完成；保存失败可恢复；结构操作规模增长时不会执行固定大体积逐格扫描；坐标与范围可复核。
- **音符编辑**：使用真实谱面完成新增/移动/复制/删除/批量修改/撤销/保存/重开/导出；Hold 端点和组关系稳定；短谱与 6 分钟完整谱交互响应分别记录；不因总音符数增加而在 UI 每帧全量重建复杂控件。
- **特效编辑**：时间轴拖拽确实 seek 同一预览时钟；播放/暂停/seek/保存/关闭状态一致；事件参数和未知字段往返保存无丢失；预设创建、应用、撤销、重开、错误引用提示、RhythMC 3.0 导出回放形成闭环。
- **综合**：从编辑器保存后的项目重新进入、再次打开三个编辑器、导出/正式播放对比，确认没有数据漂移、音画/时间偏差、场景 ID 断链、重复事件或未保存状态误报。性能验收分别观察 UI 输入响应、客户端帧率和服务端 MSPT，不用单一 FPS 指标替代。

## 主要风险与防护

- **把 UI 完成误当作功能完成**：每项交互都必须落到统一模型、持久化和重载；按操作闭环验收，不接受入口/空壳。
- **剪辑模型与 3.0 JSON 语义不一致**：剪辑片段是编辑视图模型，保存时显式编解码为既有事件结构；本地编辑布局/预设与导出字段分开。
- **Beat、秒、空间 Z 多套时钟漂移**：统一 ChartTiming 转换入口；任何拖动/修改都验证 Beat、音频 seek、轨道位置对应一致。
- **Hold 语义被 UI 破坏**：把 Hold 区间作为一等编辑对象，同时维持既有导入/导出兼容与判定逻辑。
- **超大谱面卡顿**：模型增量更新，虚拟化时间轴/轨道项目，异步文件 I/O 与受控主线程世界操作；基于真实长谱做基准，严禁每帧全量扫描/重建。
- **场景保存覆盖或越界**：保存前预览范围，临时文件/安全替换和失败回滚；所有大结构任务显示进度并允许取消。
- **阶段范围膨胀**：每阶段先交付可用闭环，再扩展高级曲线、多相机、复杂三维场景等增强能力。

## 交给实施方的首轮任务建议

先完成阶段 0 的数据契约清单和阶段 1 的场景编辑器诊断设计，不立即同时开写三个 UI。首轮实施任务包应至少列出：受影响类/模块、模型字段及兼容策略、操作状态流、失败回滚方案、具体验收案例、长谱/大场景压力样本。完成基础契约后再依次拆分音符轨道与特效剪辑任务，避免多个大改造共享同一保存/播放边界而互相冲突。
