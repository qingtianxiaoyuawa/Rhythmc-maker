# 2026-10-05 - Maker 默认播放中心修正

## 用户确认
RhythMC Maker 当前默认播放/判定框中心为：

```text
X = 200.5
Y = 66.0
Z = -1.0
```

即：

```text
makerDefaultCenter = (200.5, 66.0, -1.0)
```

## 对既有规划的修正
此前规划中使用：

```text
gameCenterLoc = (200.5, 66.0, 1.0)
TEXT_DISPLAY_CENTER = (200.5, 66.0, -1.0)
```

这只能作为“假设存在一个位于 Z=1 的上游场景中心，再向 Z 负方向偏移 2 格”的推导模型，不能继续当作 Maker 当前实际默认中心。

当前应以用户确认的 Maker 实际默认坐标为权威基准：

```text
Maker 默认播放中心 = (200.5, 66.0, -1.0)
```

后续不能因为套用 Reborn 的 `screenCenterLoc = gameCenterLoc + (0, 0, -2)` 公式，而自动把 Maker 的场景中心反推为 `(200.5, 66.0, 1.0)`。只有在源码明确区分“游戏中心”和“TextDisplay/判定框中心”时，才允许建立该偏移关系。

## 坐标分层要求
后续实现或合并规划必须区分以下三类坐标：

1. **Maker 默认播放中心**
   - 固定基准：`(200.5, 66.0, -1.0)`。
   - 用于判定框、音符轨道和默认播放场景的视觉对齐。
   - 这是当前 Maker 的实际默认坐标，不是推导出来的中间坐标。

2. **initialPosition**
   - 仍表示正式播放/预览时玩家进入的播放场景位置。
   - 不能未经确认直接等同于 `(200.5, 66.0, -1.0)`。
   - 如果正式播放传送点与默认判定框中心存在玩家眼高、实体中心或平台偏移，必须在坐标换算层显式表示，不能隐式叠加。

3. **谱面、轨道和特效局部坐标**
   - 最终世界坐标应按统一坐标转换得到：

```text
最终世界位置
= Maker 播放场景原点
+ 谱面局部坐标
+ 轨道变换
+ 特效局部变换
```

   - `200.5 66 -1` 只作为播放场景基准加入一次。
   - TextDisplay 的局部 `position`、轨道位移和矩阵变换不能再次把该默认中心当作局部偏移叠加。

## 对 TextDisplay 的影响
- Maker 默认 TextDisplay 生成/对齐基准应先按 `(200.5, 66.0, -1.0)` 校准。
- 不应直接照搬 Reborn 的“游戏中心减 2 格”公式；应先确认 Maker 当前 TextDisplay 创建点、判定框中心、玩家视角点之间的实际偏移。
- TextDisplay 的最终显示位置仍需区分实体生成锚点与文字几何中心；若出现紫色边界不能贴合判定框，应分别检查实体生成点、显示宽高、Billboard/旋转、文本对齐和矩阵平移。
- 兼容 RhythMC 3.0 时，应比较两边的“最终世界坐标”，而不是只比较变量名或中间的 `gameCenterLoc`。

## 交给编译合作方的实施清单
1. 全局搜索 Maker 中默认播放中心、判定框中心、TextDisplay 生成点和初始传送点的定义。
2. 将默认判定/播放中心统一核对为 `(200.5, 66.0, -1.0)`。
3. 检查是否存在旧坐标 `(200.45, 65.8, -1.0)`、`(200.5, 66.0, 1.0)` 或其它近似值参与实体生成、轨道计算或相机绑定。
4. 将播放场景原点、玩家传送点和 TextDisplay 锚点拆成明确变量，禁止通过未记录的隐式偏移互相替代。
5. 以同一坐标基准验证音符、轨道、TextDisplay、Hologram 和特效矩阵的最终世界位置。
6. 验收重点：默认判定框中心、音符轨道中心、TextDisplay 紫色边界和正式播放视角在 `(200.5, 66.0, -1.0)` 基准下保持一致。
