# 多行补丁参数包装器修复记录

## 问题
当前 Windows `apply_patch.bat` 使用 `%*` 调用 `codex.exe --codex-run-as-apply-patch`。当 PowerShell 将多行补丁作为单个参数传入时，`cmd.exe` 的批处理参数展开会在换行处截断内容，导致 Codex 收到不完整补丁并报：
`Invalid patch: The last line of the patch must be '*** End Patch'`。

## 根因
- 该问题不是补丁格式错误。
- PowerShell 可将多行字符串作为一个 Windows argv 参数传递。
- 但 `.bat` 包装器必须经过 `cmd.exe`，`%*`/`%~1` 对嵌入 CR/LF 的参数不能安全保持完整内容。
- 只改为从 stdin 读取可以修复管道输入，但不能修复多行“参数”输入。

## 修复
在当前 Codex 临时包装目录中新增原生 `apply_patch.exe` 与 `applypatch.exe`：
`C:\Users\28585\.codex\tmp\arg0\codex-arg0hZvGDW`

原生转发器行为：
- 无参数：读取标准输入并传给 Codex；
- 一个参数：直接读取原生 argv 中的完整多行 PATCH 字符串；
- 使用 Windows 命令行引用规则重建子进程参数；
- 启动同目录 `.bat` 中声明的 `codex.exe --codex-run-as-apply-patch`；
- `.exe` 在 `PATHEXT` 中优先于 `.bat`，因此 `apply_patch` 自动优先使用新转发器。

## 验证
- PowerShell 多行变量作为参数：成功应用真实补丁，探针内容 `before` 变为 `argument-ok`。
- PowerShell here-string 管道：成功应用真实补丁，探针内容 `argument-ok` 变为 `pipeline-ok`。
- `Get-Command apply_patch` 与 `Get-Command applypatch` 均已解析到新增 `.exe`，不再使用 `.bat`。
- 临时探针文件已清理。

## 范围
- 未修改 RhythMC Maker 工程源码。
- 未编译或部署 RhythMC Maker JAR。
- 本次仅修复当前 Codex 会话的 Windows 补丁包装器。

## 注意
Codex 重新创建 `C:\Users\28585\.codex\tmp\arg0\...` 临时目录后，新目录仍可能只有 `.bat` 包装器；如发生此情况，需要重新部署同样的 `.exe` 转发器。
