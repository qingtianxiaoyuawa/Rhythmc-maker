# RhythMC Maker 崩溃修复规划

- 日期：2026-10-03 14:10:41（Asia/Shanghai）
- 规划身份：Planner；本轮不修改源码、不编译、不测试、不部署。

## 现象

- 错误报告：G:\BaiduNetdiskDownload\错误报告-2026-10-3_14.02.35.zip
- 崩溃发生在客户端运行期间，最终由 Render Thread 退出。
- 崩溃位置指向活动谱面刷新，而不是 Flashback、owo-lib、显卡或帧率问题。

## 已确认根因

- Gson 解析谱面 JSON 时抛出 JsonSyntaxException，底层为 EOFException: End of input。
- 解析位置：line 643117 column 7，路径为 $.notes[3446].rotationZ。
- 调用链：ChartStorage.find(ChartStorage.java:431) → ClientChartAccess.refreshActiveChartIfChanged(ClientChartAccess.java:98) → RhythmcMakerClient.lambda(RhythmcMakerClient.java:138) → ClientTickEvents.END_CLIENT_TICK。
- 结论：活动谱面文件在写入未完成、覆盖被中断或文件损坏后被客户端读取；JSON 在第 3447 个音符附近提前结束。异常未在活动谱面刷新边界被隔离，最终穿透到客户端 Tick 线程并导致崩溃。

## 实现任务

1. 定位崩溃时 hythmc_maker:charter 对应的活动谱面文件，检查其第 643117 行及 
otes[3446] 附近内容。
2. 优先从 .bak、历史副本或最近有效版本恢复该谱面；不要直接用不完整文件继续覆盖保存。
3. 将谱面保存改为原子替换流程：写入同目录临时文件，完成写入并关闭后再替换目标文件；失败时保留原文件。
4. 在活动谱面刷新入口捕获 JSON 语法/EOF/IO 解析失败，保留内存中的最后一个有效谱面，向用户报告可定位错误，不允许异常终止客户端 Tick。
5. 在新文件成为活动文件前执行完整 JSON 校验；校验失败不得替换现有有效文件。
6. 检查读取与保存是否存在并发窗口，确保刷新不会读取仍在写入的临时或目标文件。
7. 使用 D:\Program Files\PowerShell\7 执行实现方的编码敏感命令、编译与后续验证。

## 验收标准

- 损坏或截断的谱面不会再导致 Minecraft 客户端崩溃。
- 保存过程中被中断时，旧的有效谱面仍可读取，且不会生成半写入活动文件。
- 大谱面（至少超过 3,446 个音符）可完整保存、重新加载并通过 JSON 校验。
- 活动谱面刷新失败后，制谱器仍保持可操作，并能显示文件路径、行列或解析原因。
- 正常保存、刷新、切换谱面和重启客户端的既有逻辑不回退。
- 需要补充一个针对“截断 JSON + 活动谱面刷新”的回归验证；若现有架构无法直接测试刷新入口，必须在交付记录中说明测试缺口及替代验证方式。

## 风险与注意事项

- 不能只删除损坏谱面或简单吞掉异常；必须同时保证数据恢复路径和保存原子性。
- 不要把 Flashback 配置解析警告、可选 Mixin 缺失、Sodium NVIDIA workaround 或 Spark 关闭期异常误判为本次崩溃根因。
- 旧版本 1.5.24 曾被运行中的 javaw.exe 锁定；后续部署前必须确认实例已退出，避免同一 Mod ID 多版本同时加载。
- 实现方完成后需提供：恢复/损坏文件判定结果、改动文件、编译命令、回归验证结果及部署包哈希。
