# 参考官方源码实现 BPM 精确匹配方案

- 时间：2026-09-25 10:15:00 +08:00
- 参考文件：`G:\BaiduNetdiskDownload\key-finder-59110acc.js`、`AppBpmFinder-d9c5bd4e.js`、`006ef59a`

## 参考源码确认结果

官方 Worker 的流程是：

1. `AudioContext.decodeAudioData` 解码音频。
2. 立体声按左右声道逐样本平均为单声道。
3. 重采样到 `16000 Hz`，实现为按比例区间求平均。
4. 使用 Essentia WASM 的 `PercivalBpmEstimator`：
   `PercivalBpmEstimator(signal, 1024, 2048, 128, 128, 210, 50, 16000)`。
5. Worker 返回原始 BPM。
6. `AppBpmFinder` 显示时执行：`Math.round(rawBpm * 1)`，即四舍五入到整数。
7. 同时用原始 BPM 计算毫秒拍长：`Math.round(60000 / rawBpm)`。

参考源码没有发现按歌曲名称修正、强制吸附到用户测试点或额外取整前校正逻辑。

## 为什么当前结果无法完全等于测试点

当前 RhythMC Maker 使用了相同的采样率、帧大小和部分多频段思路，但核心检测器不是同一个 `PercivalBpmEstimator`，而是 Java 频谱通量 + 延迟相关搜索。因此 `129.3` 与测试点 `128` 的差异不是显示小数位问题，而是算法输入/特征/候选评分不同。

即使完全复刻官方算法，音频 BPM 仍可能存在半拍、倍拍和编曲定义差异；官方网页的“完全整数结果”主要来自界面显示取整，不代表原始估计精确等于该整数。

## 推荐方案 A：复刻官方结果

优先建议直接集成 `006ef59a` 对应的 Essentia WASM 和 Worker 处理流程，而不是继续手写近似算法：

- 将 WASM 作为 mod 资源放入项目资源目录，并通过 Java-WASM 运行时调用；或者
- 将官方算法移植为独立本地分析进程，由 Maker 调用并返回 JSON；或者
- 保留 Java 调度，但把音频预处理和 Percival 参数严格对齐。

必须严格一致：

- 单声道混音公式：`(left + right) / 2`；
- 重采样到 `16000 Hz`，不能只依赖另一种重采样器而不验证差异；
- 帧大小 `2048`、hop `1024`；
- BPM 范围 `50..210`；
- 参数 `minTempo=128`、`maxTempo=128` 等调用位置必须以 WASM 导出函数签名确认，不能仅凭包装函数名称猜测；
- 官方包装调用为 `PercivalBpmEstimator(..., 1024, 2048, 128, 128, 210, 50, 16000)`；
- UI 展示整数使用 `round(rawBpm)`，但内部谱面应保存原始 BPM 或明确的最终 BPM。

复刻后应增加回归测试：同一音频、同一解码 PCM、同一重采样 PCM，比较原始 BPM 和显示 BPM，而不是只比较最终整数。

## 推荐方案 B：针对测试点严格输出

如果用户的“测试点”是预先确定的官方标注值，例如 `128、110、100`，则应把它定义为测试真值，而不是让自动分析器猜测：

```text
rawBpm = 自动检测结果
candidateBpm = 官方算法/Java算法候选
finalBpm = 用户确认或测试点表中的 BPM
```

在校准界面显示：

- 原始检测值；
- 官方算法值（如果接入）；
- 测试点/用户确认值；
- 三者误差；
- 半拍、原速、倍速候选。

测试时验证 `finalBpm == expectedBpm`；自动测量只负责提供候选和相位/Offset，不应伪装成完全测量。

## 推荐方案 C：折中自动吸附

当没有测试点文件时：

1. 获取原始 BPM。
2. 生成原速、半速、倍速候选。
3. 在候选附近生成整数 BPM 候选。
4. 用跨整首歌曲的 onset 相位误差、4 拍小节一致性和分段稳定性评分。
5. 只有候选优势明显时才吸附到整数；否则保留原始值并要求确认。

不能使用简单 `round()` 作为唯一修正，因为 `129.3` 只能变成 `129`，不会合理变成 `128`；强行选择测试点会隐藏错误。

## 对 RhythMC Maker 的最终建议

- 若目标是“和参考网页显示一致”：优先移植/调用同一 Essentia `PercivalBpmEstimator`，最后按官方 `Math.round(rawBpm)` 显示。
- 若目标是“九首测试点全部严格相等”：新增测试点数据集/旁车文件，由测试点定义最终 BPM；自动算法只做检测和提示。
- 若目标是“新歌曲也尽量自动正确”：采用官方算法 + 原速/半速/倍速候选 + 分段稳定性评分 + 用户确认。
- 不建议歌曲名特判，也不建议将所有结果无条件四舍五入或强制改成预期值。
