## 一、项目目标

本阶段工作的总目标是把 RhythMC Maker 从“能够编辑和保存特效”推进到以下状态：

1. 与 RhythMC 3.0 / Reborn 的特效字段、参数语义和导出格式兼容。
2. 2.0 谱面导入后，旧特效可以转换为当前特效编辑器能够识别、编辑、保存和正式播放的结构。
3. 3.0 谱面导入后的特效可以进入当前编辑器，编辑后再次保存或导出时不丢字段、不重复嵌套、不导出 Maker 本地字段。
4. 正式播放链路可以正确执行切换场景、切换天气和隐藏音符。
5. 特效编辑器具备稳定的时间轴、轨道、UI、参数编辑、中文化和文字预览能力。
6. 所有修改都要经过 Java/Gradle 构建、部署、版本递增、备份和 Git 推送。

## 二、关键决策

### 2.1 播放中心与坐标

- RhythMC Maker 当前正式播放中心最初保留为 `200.5 66 -1`。
- 后续对 TextDisplay / 全息图相关位置进行单独修正：全息图和 TextDisplay 偏移中心使用 `200.5, 66, -1.5`。
- 场景播放区域是初始场景；只有真正执行过场景切换特效，结束播放时才需要回退初始场景，避免无意义的结束卡顿。
- 预览播放、滚动播放和正式播放是不同链路，不能因为修复正式播放而重构预览播放。
- 滚动播放不播放特效。
- 正式播放结束时清理 Title、药水效果、展示实体等所有播放状态。

### 2.2 场景与谱面生命周期

- 只有第一次创建谱面、首次导入谱面或新建场景时，才允许重置默认初始场景。
- 重复进入同一谱面不能重置玩家已经修改并保存的场景。
- 如果导入谱面同时提供完整的 `.schem` 和 `metadata.yml`，则视为完整场景导入，直接使用导入场景。
- 场景导入不完整时，不能算作成功导入场景；对应场景应回到默认场景。
- 初始场景是播放区域场景；特效场景从 `x=1000` 开始，每隔 `200` 格创建。
- 新建谱面会创建独立维度，场景编辑器和正式播放依赖该谱面维度。
- 场景选择只读取场景编辑器中已保存的场景，不识别无关目录或任意文件。
- 切换场景特效保留；只移除过时的“兼容旧名称”切换场景事件。
- 状态栏文字特效是 Maker 独有且不在谱面中使用的功能，按要求移除。

### 2.3 特效编辑器 UI

- 进入特效编辑器后不暂停游戏；世界继续运行，但玩家游戏操作被禁止。
- 不显示玩家快捷栏；状态栏 UI 按最终要求保留。
- 去除虚化效果，确保中间游戏预览画面清晰。
- 中间区域不放置额外游戏画面控件；四周区域由完全不透明的深色 UI 面板填满。
- UI 面板保留细边框和标题栏，不允许游戏画面从左右或下方 UI 漏出。
- 中间游戏画面可以保留黑屏区域，以维持比例均衡，不强制填满整个窗口。
- 时间轴和特效轨道列表统一滚动，避免左右区域错位。
- 时间轴左侧增加轨道滚动条，滚动时必须能够看到全部轨道。
- 时间轴滚轮和视角滚轮按鼠标位置区分：鼠标在时间轴区域时修改时间轴，否则修改视角。
- `Ctrl + 滚轮`用于时间轴缩放；普通滚轮用于时间轴上下滚动。
- 时间轴最小缩放单位是每 Chunk 分数。
- 中键拖动灵敏度降低；不再额外加入左键拖动游戏画面调整视角的修改。
- 初始高度最终确认为 `74`，最小 `72`，最大 `90`。

### 2.4 时间轴、Chunk 分数与吸附

- 实际播放和导出内部继续使用原始 Beat，防止导出到 RhythMC 3.0 时产生误差。
- 显示层使用 `chunk n + 分数/x`，其中 `x` 是每 Chunk 分数，`n` 必须为整数。
- 预览线也采用 Chunk 计时法，显示原始分母，不显示小数形式。
- 修改每 Chunk 分数时，锁定全部操作；完成后恢复旧值并解锁操作。
- 旧特效事件和旧关键帧不自动移动；只有拖动旧事件、创建新事件或新关键帧时，才按新位置吸附。
- 预览线只能吸附在整数位置。
- 同一轨道只允许一种特效类型；同一时间发生冲突时创建多条轨道。
- 右键时间轴事件显示菜单，支持新增特效、复制、删除；参数设置在右侧参数栏，不放在右键菜单中。
- 左键点击非播放起始点区域时取消特效选择，右侧显示“请选择特效”。
- 多选特效时，右侧显示“无法设置多个特效参数”，只允许复制和删除。
- 支持 `Ctrl+Z` 撤销和 `Ctrl+Y` 恢复；不可用时按钮灰化。

### 2.5 特效参数标准化

- 所有特效参数编辑栏移除中文后的英文键名和 Reborn 3.0 官方参数说明，保持 UI 简洁。
- 参数按 Reborn 3.0 语义整理，不新增 Reborn 没有的功能。
- 参数编辑器统一使用中文标签、清晰分组、适当留白，不能过度紧凑。
- Title、Hologram、Message、TextDisplay、TextDisplay Effect 等文字类特效增加输入预览。
- `message` 正式播放只向聊天发送消息内容，不显示来源。
- `&` 颜色代码接入文字播放链路；编辑器显示原始颜色代码，播放时应用并隐藏代码。此前导入自动删除颜色代码的逻辑必须移除。
- 支持的文字类效果包括 `MESSAGE`、`TEXT_DISPLAY`、`HOLOGRAM`、`TITLE` 等。
- Hologram ID 必须启用且不能为空；允许任意非空字符串；随机生成格式为 `H00001`，H 与 T 使用各自独立命名空间去重。
- TextDisplay ID 随机生成格式为 `T00001`；TextDisplay 与 Hologram 不共用编号空间。
- TextDisplay 旋转输入使用角度，保存时自动转换为弧度，最多保留 6 位小数并移除无意义的尾零。
- TextDisplay 跟随轨道的轨道 ID 使用谱面真实轨道 ID 的单选下拉菜单；无轨道时显示“暂无可用轨道”。
- `TEXT_DISPLAY_EFFECT` 的发光改为明确的可勾选“发光”选项，默认关闭。
- 药水效果使用中文下拉选择，保存和导出仍使用官方 ID。
- `CLEAR_EFFECT` 增加“全部药水效果”语义，并与具体药水效果互斥。
- 天气选项按当前 Reborn 兼容链路使用 `CLEAR`、`RAIN`、`THUNDER`。
- 隐藏音符支持音符类型和轨道多选；“全部轨道”与具体轨道互斥；“恢复显示”与隐藏选项互斥。
- FIREWORK 仅删除确认过的 `type` 和主标题/副标题下方多余的恢复默认按钮，其余参数保留；渐变颜色恢复默认必须逐项对应。
- TIME 是瞬时特效，删除整组持续时间参数。
- 全息图默认偏移为 `x=0,y=1.5,z=0`；烟花位置默认恢复为 `0,2,0`，颜色默认 `[255,255,255]`。

## 三、关键理解错误与纠正

### 3.1 将“有事件分派入口”误认为“正式播放已完成"

早期源码中已经存在：

```java
case "HIDE_NOTES" -> session.updateHiddenNotes(effect);
case "WEATHER" -> session.applyWeather(effect);
case "ARENA", "CHANGE_ARENA" -> session.applyArena(effect);
```

但这只能证明存在入口，不能证明功能完成。真正的问题在于：

- 导入后的字段可能位于 `properties`，播放代码却按顶层字段读取。
- 场景名称与场景绑定路径没有完全建立关联。
- 天气原先只按雨/风暴字符串判断，不能完整区分 `RAIN`、`THUNDER` 和 `CLEAR`。
- 2.0 旧格式的隐藏音符字段可能是数字、旧名称或不同键名。

纠正方式：统一导入迁移、导出规范化和播放读取层，而不是只增加一个 `case`。

### 3.2 混淆特效编辑器 UI 与世界场景

多次讨论中曾将“特效编辑器卡顿”与“场景特效/世界场景”混在一起。最终确认：

- 特效编辑器是 UI 界面。
- 卡顿主要来自 UI 数量、ImGui 控件和时间轴轨道数量，而不是场景数量。
- 特效编辑器预览播放不能等同于正式播放。
- 只有正式播放的场景、天气和隐藏音符按本轮需求补齐；不能借此重构预览系统。

### 3.3 混淆显示时间与实际播放时间

Chunk 分数模型只用于显示、吸附和编辑器交互；内部 Beat 仍是播放和导出的权威时间。若把 Chunk 显示值直接替代 Beat，会导致 BPM、偏移、导出和播放误差。

### 3.4 将 Maker 本地运行字段导出到官方文件

场景运行时需要本地 `arenaPath`，但该字段不是 RhythMC 3.0 官方特效参数。最终确定：

- `arenaPath` 只在 Maker 本地运行链路保留。
- 导出时必须移除 `arenaPath`。
- 同样原则适用于 `ensureEffectPreviewDisplayRange(display)` 等本地预览逻辑：只能在 Maker 内部存在，不能导出到 3.0 官方文件。

### 3.5 版本号和分支状态判断曾不一致

一次工作上下文中的工程版本显示为 `1.11.1`，但部署目录已有 `1.12.12`。最终以部署包和远端最新状态为基准，将本轮版本设为 `1.12.13`，避免版本倒退。

本地分支实际名称是 `master`，远端目标分支是 `main`。直接执行 `git push origin main` 曾失败，之后改用：

```text
git push origin HEAD:main
```

并先抓取远端、合并 `origin/main` 冲突后再推送。

5. 不能因为场景、轨道或 UI 数量多就随意重置玩家数据或场景。
6. 任何导入场景必须以 `.schem` 和 `metadata.yml` 两个完整文件为准。
7. 所有官方参数必须参考 Reborn，不能新增 Reborn 没有的内容。
8. Maker 本地字段只在 Maker 内部使用，导出时不得污染 RhythMC 3.0 文件。
9. 文字颜色代码编辑器中保留，播放时应用且不显示代码。
10. 文字、场景、天气、药水、隐藏音符等参数必须使用清晰的中文 UI。
11. ID 必须可靠去重：Hologram 使用 H 命名空间，TextDisplay 使用 T 命名空间。
12. 版本号必须递增；每次编译要自动备份、部署、提交和推送。
13. 编译不能偷懒，必须使用真实 Java 21 环境并验证完整构建。
14. 关键坐标、场景中心、Chunk 分数、负偏移、Beat 内部计时等语义不能凭猜测修改。
15. 用户明确要求“不提问”时，必须基于已有源码和工程记录做最优实现。
16. 用户处于特效参数标准化修改模式时，只按当前特效的确认要求执行；用户退出该模式后才恢复普通编译合作方式。
