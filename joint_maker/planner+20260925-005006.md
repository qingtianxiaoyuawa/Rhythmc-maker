# RhythMC Maker 规划说明：谱面偏移与歌曲偏移是否可直接取反

- 记录类型：planner
- 时间：2026-09-25 00:50:06 +08:00

## 结论

不能仅凭“RhythMC 是谱面偏移、Malody 是歌曲偏移”就无条件将数值取负。

只有以下条件同时满足时，才可使用：

`	ext
rhythmcChartOffset = -malodySongOffset
`

1. 两边使用同一首原始音频文件，且没有各自额外的音频裁剪、前置静音补偿或编码延迟补偿；
2. 两边的 beat 0 表示同一个音乐时刻；
3. 两边 BPM、拍号和 beat 网格原点一致；
4. 两边的 offset 都是“将某一时间轴整体平移”的有符号毫秒值；
5. 确认 Malody 的歌曲 offset 公式和 RhythMC 3.0 的谱面 offset 公式确实使用相反加法方向。

## 不能直接取反的常见情况

- Malody offset 实际含有音频 lead-in、preview 起点或解码器延迟补偿；
- RhythMC 3.0 offset 作用于判定时间而非纯视觉/播放网格；
- 任一工具会把负 offset 归一化为前置静音或移动第一个 BPM 事件；
- 两边起始拍不是同一拍，例如一个将弱起定义为 beat 0，另一个将第一强拍定义为 beat 0；
- 导入时发生了音频重新编码、裁剪或替换。

## 推荐验证方法

不要从字段名推导，使用一次可观测的基准测试：

1. 选取有清晰首拍瞬态的同一音频。
2. 在 Malody 中记录：offset 值、beat 0 的时间位置、下一拍位置。
3. 在 RhythMC 3.0 中输入候选值 -malodyOffset。
4. 比较至少连续 8 拍的网格与歌曲瞬态是否重合。
5. 若整段固定差值相反，则再用 +malodyOffset；若存在常量差，记录为独立的导入补偿，而不是污染通用正负转换。

## 导入架构建议

未来若支持 .mc 导入，应定义显式转换函数：

`	ext
RhythmcTiming convertMalodyTiming(MalodyTiming source, AudioCalibration calibration)
`

其中 AudioCalibration 可记录已验证的常量补偿。不要在 UI 文案、保存逻辑或 exporter 中散落 -offset。
