# RhythMC Maker 分文件导入设计

- 时间：2026-09-25 15:00:00 +08:00
- 结论：可以将所有 3.0 资源分开导入，但应采用“资源库 + 绑定关系”模型，而不是导入一个文件后立即创建完整谱面。

## 导入类型

1. 歌曲信息：`manifest.yml`
2. 难度谱面：`world.rmcc`、`nether.rmcc`、`end.rmcc`、`void.rmcc`
3. 场景：一个场景目录中的 `metadata.yml + arena.schem`
4. 音频：`mp3/flac/wav/ogg/m4a/aac`
5. 可选曲绘：图片文件

不建议把 `manifest.yml`、`.rmcc`、`.schem`、音频强行放在同一页面上传；每类文件独立校验并进入待绑定资源库。

## 推荐界面

在创建谱面右侧增加“导入 3.0 资源”，进入资源管理页，提供四个入口：

- 导入歌曲信息
- 导入难度谱面
- 导入场景
- 导入歌曲音频

另设“绑定为谱面”按钮，显示当前资源的关联状态：

```text
歌曲信息       已导入
音频           已绑定 song.mp3
WORLD 谱面     已绑定
初始场景       未设置
NETHER 谱面    未导入
```

## 分文件导入行为

### manifest.yml

- 读取 `name/composer/icon/length/song_id/version/comments/player-alias`；
- 建立一个歌曲资源记录；
- 如果没有音频或谱面，仍允许保存为草稿；
- `song_id` 只作为外部标识，导入到本地时生成内部 UUID；
- 不直接把 `manifest.yml` 当作完整可播放谱面。

### .rmcc

- 通过固定文件名识别难度：`world/nether/end/void`；
- 也允许用户手动选择难度，避免非标准文件名无法导入；
- 尝试 Zstd，失败则回退纯 JSON；
- 解析 `meta.initialArena`、`meta.bpms`、`meta.offset`、`tracks`、`effects`；
- 自动查找匹配歌曲：优先 `manifest.song_id`、`meta.uid` 的 songId 部分、文件哈希；无法匹配时进入“选择绑定歌曲”；
- `.rmcc` 可先单独保存，等待后续绑定音频和场景。

### 场景

推荐用户选择场景文件夹，而不是单独选择 `.schem`：

```text
arena-key/
├─ metadata.yml
└─ arena.schem
```

也可提供“先选 `metadata.yml`，再补选 schematic”的两步流程。

- 读取 metadata 的 `name/schematic/display-name/icon`；
- 校验声明的 schematic 文件存在；
- 保存为独立 Arena 资源；
- 不自动绑定为初始场景，除非用户确认；
- 绑定页中可设为某个难度的初始 Arena；
- 扫描 `.rmcc` 的 `ARENA.properties.arena`，将其与对应 Arena 绑定。

### 音频

- 导入后复制到本地音频库并计算 SHA-256；
- 优先按 `song_id`、文件名和用户选择绑定歌曲；
- 绑定后才进入 BPM/Offset 测量；
- 音频可以替换，但替换时提示 BPM、Offset 和时长可能需要重新测量；
- 同一音频哈希只保存一份，多个谱面可以引用。

## 绑定模型

内部不要只用当前简化的 `ChartManifest`，建议增加独立记录：

```text
SongAsset
  localId
  sourceSongId
  manifestPath
  audioAssetId
  coverAssetId

DifficultyAsset
  localId
  songAssetId
  difficulty
  sourcePath
  rawRmcc
  importedMeta

ArenaAsset
  localId
  originalKey
  importedKey
  metadataPath
  schematicPath

ChartBinding
  difficultyAssetId
  audioAssetId
  initialArenaId
  arenaEffectBindings
```

`arenaEffectBindings` 至少保存：

```text
beat
originalArenaKey
boundArenaId
```

这样即使文件分开导入，也能在之后重新绑定或替换资源。

## 自动匹配规则

优先级建议：

1. 用户手动选择；
2. 同一导入目录中的相对路径；
3. `song_id`；
4. `.rmcc.meta.uid` 的 songId 部分；
5. 音频 SHA-256；
6. 文件名/歌曲名模糊匹配。

自动匹配只能给出建议，不能静默绑定错误歌曲。

## 最终可播放条件

一个难度进入“可编辑”状态需要：

- `.rmcc` 已导入；
- 已绑定歌曲信息；
- 已绑定音频，或明确使用外部资源包音频；
- `meta.initialArena` 为空或已绑定有效 Arena；
- 所有 `ARENA` effect 引用均能找到有效 Arena；
- `.rmcc` JSON 结构有效。

一个难度进入“可导出”状态还需要：

- 所有 Arena key 已重命名为本地唯一 key；
- `.rmcc` 内 `initialArena` 和 `ARENA` 引用已同步重写；
- 导出目录能生成 `Data/Charts/<song>` 与 `Data/Arenas/<arena>`；
- 音频资源包映射已生成或用户确认仅导出交换资源。

## 推荐导入顺序

用户可以任意顺序导入，但界面建议：

1. 导入 `manifest.yml`；
2. 导入音频；
3. 导入一个或多个 `.rmcc`；
4. 导入初始场景和特效场景；
5. 在绑定页检查引用；
6. 进入 Maker 编辑或导出。

- 本次仅规划分文件导入，未修改源码，未编译。
