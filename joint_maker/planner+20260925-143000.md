# RhythMC Maker 当前 3.0 导出规范审查

- 时间：2026-09-25 14:30:00 +08:00
- 审查对象：`src/main/java/cn/frkovo/rhythmcmaker/chart/Rhythmc3Exporter.java`
- 结论：当前导出是“部分符合 3.0 数据字段”的单谱面交换目录，但**不符合可直接部署到 RhythMC 3.0 插件 `Data/Charts` + `Data/Arenas` 的完整包规范**。

## 已确认符合或可兼容的部分

1. `manifest.yml` 已包含 `name`、`composer`、`icon`、`alias`、`length`、`respack_sha1`、`description`、`song_id`、`version`、`comments`、`player-alias` 等主要字段。
2. `length` 写入 `durationSeconds * 1000`（毫秒）。文档文字存在“秒”的表述，但项目内已有 `converted/end-bpm174/manifest.yml` 也写入 `275500`，与当前导出器的毫秒行为一致，因此不判为错误。
3. `.rmcc` 顶层使用 `meta/tracks/effects`，并正确输出 `uid`、`offset`、`level`、`charters`、`comments`、`bpms`。
4. Track 中使用 `speedEvents`、全部 transform/rotate/scale event 数组、`notes`；现有转换器的实际输出也使用字段 `easing`，所以导出器使用 `easing` 与项目的真实转换产物相符。
5. Note 使用 `noteType`、`beat`、`pos`、`scale`、`rotation`，数据形状可兼容 3.0。
6. 场景使用 `metadata.yml + arena.schem`；Sponge schematic v2 的 `Version/Width/Height/Length/Palette/BlockData` 基本骨架已写出。

## 阻断“直接部署”的问题

1. 导出根目录结构错误。

当前：

```text
<export>/<song-name-id>/
  manifest.yml
  world|nether|end|void.rmcc
  song.mp3
  scene/
    metadata.yml
    arena.schem
```

3.0 插件期望：

```text
Data/Charts/<song-folder>/
  manifest.yml
  world|nether|end|void.rmcc
Data/Arenas/<arena-key>/
  metadata.yml
  arena.schem
```

当前的 `scene/` 是歌曲目录的子目录，插件不会把它识别为 `Data/Arenas/<key>` 场景。

2. `.rmcc.meta.initialArena` 没有写出。

当前 `writeChart()` 的 `meta` 中没有 `initialArena`。即使手动把 `scene/` 移到 `Data/Arenas`，谱面也不会引用该场景；初始场景行为无法保证正确。

3. 没有多场景/ARENA 特效支持。

当前固定：`root.add("effects", new JsonArray())`。因此无法导出 `ARENA` 切换场景特效，也无法携带特效引用的场景文件。

4. 音频仅被复制到歌曲导出目录。

插件正式播放依赖资源包 sound key（由 `song_id` 派生）及资源包生成/注册，而不是自动读取 Charts 目录下的 `song.mp3`。当前文件可以用于 Maker 交换包，但不能单独保证正式 3.0 服务端播放。

## 非阻断但需处理的兼容性问题

1. `manifest.yml` 写入 `base_bpm`、`tags`、`unlockSong`、`unlockWorld`、`unlockNether`、`unlockVoid`。现有 3.0 文档的基础 Song manifest 示例不要求这些字段；若解析器允许未知字段，它们通常无害，但不应把它们当作 3.0 必需字段。
2. 当前只导出单一难度文件；这对“导出当前难度”是合法的，因为 3.0 允许 1–4 个难度，但无法一键导出同曲多难度。
3. 当前 `.schem` 的结构骨架正确，但尚未由实际 WorldEdit/3.0 插件加载验证；`DataVersion = 0`、Offset 及制谱维度坐标转换需进行真实导入测试。
4. 当前没有生成压缩 Zstd `.rmcc`；3.0 解析器可回退纯 JSON，因此这不是阻断项。

## 修正优先级

P0：调整导出为完整包根目录，至少产生 `Data/Charts/<song>` 和 `Data/Arenas/<arena-key>`。
P0：在 `.rmcc.meta` 写入与 Arena 文件夹一致的小写 `initialArena`。
P0：导出后校验每个 `initialArena` 和每个 `ARENA.properties.arena` 都存在对应 Arena 目录。
P1：在内部模型中保存 effects 和多个 Arena，导出 `ARENA` 特效与相应 `.schem`。
P1：定义音频资源包构建/安装方式，输出音频映射或明确提示“仅交换包，需另行生成资源包”。
P2：为导出产物做实际 3.0 插件加载回归：读取场景、进入谱面、初始场景、场景切换、音频、四个难度。
