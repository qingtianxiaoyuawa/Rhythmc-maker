# 动态维度池修复记录

## 目标
检查并移除静态 `chart_slot_*` 维度池，使每个谱面与独立动态维度严格一一对应。

## 修改内容
- `ChartDimensionManager` 不再提供槽位分配、槽位解析和槽位世界识别 API。
- 每个谱面的维度 ID 强制由谱面 ID 通过稳定哈希派生：`chart_<normalized-id>_<sha256-prefix>`。
- 读取旧谱面时，如果 `dimensionId` 为空或与谱面 ID 不匹配，会自动纠正并写回，避免多个谱面共用维度。
- 客户端活动谱面解析只接受动态维度，不再回退到 `editorSlot`。
- 服务端编辑世界判定移除旧槽位世界路径；旧 `chart_slot_*` 世界不会再被当作当前谱面编辑维度使用。
- 复制谱面时清空旧 `dimensionId`，确保新谱面生成自己的动态维度。
- 删除 `editorSlot` 的运行时查找和模型字段；旧 JSON 字段会被 Gson 安全忽略。
- `findByDimensionId` 改为按谱面 ID 的规范动态维度 ID匹配，防止旧缓存字段造成错误绑定。

## 兼容与安全
- 保留已有谱面文件和谱面 ID，不删除谱面数据。
- 旧静态槽位世界不会被强制删除，避免误删存档；但不会再参与谱面绑定或编辑入口。
- 动态维度仍使用独立 registry key、持久化 CustomLevel 和虚空区块生成器。
- 编译通过，未发现因移除槽位 API 导致的 Java 编译错误。

## 验证
- `gradle compileJava --no-daemon`：成功。
- `gradle build --no-daemon`：成功。
- Fabric Loom remap、测试检查和 JAR 构建：成功。
- 自动部署：成功部署 `build/libs/rhythmc-maker-1.5.10.jar`。
- 源码扫描：未发现 `findByEditorSlot`、`assignSlot`、`slotOf`、`isSlotWorld`、`editorSlot` 的运行时引用。

## 结果
静态维度池已从运行时绑定链路移除；谱面进入、客户端活动谱面解析、预加载和复制流程均按谱面 ID 使用动态一一对应维度。
