# 1.13.45 特效编辑器大事件量优化

日期：2026-10-25

## 根因与修复

- 打开编辑器为每个特效事件寻找可用轨道时，旧实现逐条扫描已分配的位置。Tojita Sekai 样本中大量同拍 TEXT_DISPLAY_EFFECT/REMOVE 事件导致大量分轨，形成事件数与既有事件数、轨道数相乘的初始化开销。采用按轨道/节拍索引和类型节拍占用位图，保持同拍冲突、首个可用轨道及优先轨道语义不变。
- 首次生成时间轴时，旧实现针对每条轨道遍历全部事件，重复构造标记。改为单次按轨道分组，轨道内按 beat 排序。
- 每帧逐个检查整条轨道的所有标记并构造命中对象。改为二分定位可视起点，只绘制当前可视行和时间范围内的标记；拖动时不重复重建整张时间轴。
- 拖动轨道与检测重叠原先会复制轨道列表或扫描全部事件，改为直接查询轨道索引和节拍占用索引。

## 样本回归

- 样本 `Tojita Sekai.json` 共 52,772 个 effects：45,396 个 TRANSFORMATIONS、7,160 个 TEXT 等；折叠后的类型仍保留 38,236 个 TEXT_DISPLAY_EFFECT 和 7,160 个 TEXT_DISPLAY_REMOVE 事件。
- 修复前，同一布局模型处理实际顺序前 5,000 项耗时 12,185 ms；全量旧实现运行超过 30 秒超时。
- 修复后，全量 52,772 项、1,634 轨道，三次耗时为 445/453/573 ms。回归同时断言同轨无重叠、快照恢复、事件移动及位置数量完整。
- harness 使用事件次序与转换后的节拍分布；样本未携带目标存档使用的 BPM，因此样本时间转换在 benchmark 中采用 BPM 120，仅用于覆盖真实重复 tick/事件顺序的布局负载，不作为游戏内完整 GUI 性能数据。
