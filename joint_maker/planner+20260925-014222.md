## 官方格式确认

### RhythMC 3.0

官方目录结构：

`	ext
<song-folder>/
├── manifest.yml
├── world.rmcc
├── nether.rmcc
├── end.rmcc
└── void.rmcc
`

四个难度文件可选，至少需要一个。.rmcc 是 Zstd 压缩 UTF-8 JSON，解压失败时可回退纯 JSON。

manifest.yml 保存歌曲元信息；难度 .rmcc 保存：

- meta.offset
- meta.bpms[]
- meta.initialArena
- 	racks[]
- speedEvents
- 轨道变换/旋转/缩放事件
- 
otes[]
- ffects[]

3.0 官方谱面目录本身不保证包含音频；音频通常由资源包依据 song_id 和 espack_sha1 提供。为了在 Maker 中立即播放，建议导入包额外允许一个音频文件，或在导入后要求用户另选本地音频。

### RhythMC 2.0 旧格式

根据提供的 RhythMC-Chart-Converter：

`	ext
旧版歌曲目录/
├── metadata.yml
├── world.json
├── nether.json
├── end.json
└── void.json
`

旧版单难度 JSON：

`json
{
  "meta": {
    "charter": "...",
    "charter-alias": "...",

  },
  "frames": [
    {
      "judge-tick": 96,

`

旧版还可能需要外部 arena 与资源包文件：

`	ext

ArenaSchematics/*.schem
resource-packs/*.zip
`

## 导入入口建议

### UI

ChartListScreen 中新增“导入谱面”按钮，进入 ChartImportScreen：

1. 选择导入格式：RhythMC 2.0 / RhythMC 3.0 / 自动识别；
2. 选择一个 .zip 或谱面目录；
3. 若包内无音频，弹出“选择歌曲音频”；
4. 选择难度（导入多个难度时逐个生成 Maker 谱面，或先选一个）；
5. 显示导入报告：读取文件、转换内容、丢弃字段、警告；
6. 确认后写入本地 Maker 谱面。

优先支持 .zip，其次支持目录。目录导入需要文件夹选择器，不能假设普通文件选择器能返回目录。

### Maker 专用导入包建议

为了避免官方运行时目录缺音频，建议定义 Maker 可接受的 zip：

`	ext
song.zip
├── manifest.yml / metadata.yml
├── world.rmcc 或 world.json
├── audio/song.ogg       # 可选但推荐
├── arenas/              # 可选
│   ├── mansion.yml
│   └── mansion.schem
└── resourcepack/        # 可选，不应强制解析
`

3.0 官方包如果只有 manifest.yml + world.rmcc，导入后应要求另选音频；不能因为缺音频而拒绝导入谱面数据。

## RhythMC 3.0 导入方案

### 读取

新增独立 Rhythmc3Importer，职责为：

1. 安全解压 zip（防 Zip Slip、限制总大小和文件数）；
2. 定位 manifest.yml 与 world/nether/end/void.rmcc；
3. 用 YAML 解析 manifest；
4. 对 .rmcc 先尝试 Zstd 解压，失败再按 UTF-8 JSON 读取；
5. 校验 meta、tracks、notes、effects、bpms；
6. 生成完整内部 ChartDocument，不要直接丢到现有扁平 ChartManifest.notes。

### 需要补充/扩展的数据模型

建议把 ChartManifest 作为歌曲/难度元数据，把谱面主体拆成：

`	ext
ChartDocument
├── ChartManifest metadata
├── List<ChartTrack>
├── List<BpmEvent>
├── List<Effect>
└── SceneReference / initialArena
`

ChartNote 至少保留：trackId、noteType、beat、pos[3]、scale[3]、rotation[3]、holdGroup。

若一期暂时不能扩展完整编辑器，必须明确标记为“导入后只读/有限编辑”，不能静默丢弃事件。

## RhythMC 2.0 → 3.0 转换方案

优先复用官方 RhythMC-Chart-Converter 的语义，而不是重新猜测旧版格式。

### 1. 元数据

`	ext
metadata.yml.name       -> manifest.yml.name
metadata.yml.composer   -> manifest.yml.composer
metadata.yml.icon       -> manifest.yml.icon
metadata.yml.length     -> manifest.yml.length * 50 ms
metadata.yml.respack_sha1 -> manifest.yml.respack_sha1
`

生成新的 song_id/Maker 本地 UUID，不直接信任旧 ID。

### 2. 时间基准

官方转换器的基本映射是：

`	ext
旧版 1 tick = 50 ms
3.0 BPM = 1200
旧 judge-tick -> 3.0 beat
`

但不能只做 eat = judgeTick 就结束。旧版运行时会根据 low-speed 在生成时提前生成 FallingBlock；官方文档后续给出的精确转换为：

`	ext
rebornBeat = oldTick
           - (floor(20 / (flowSpeed * 1.02)) + 5)
           + (20 / flowSpeed)
`

因此导入器应提供两种模式：

- 兼容官方转换器：采用最新官方转换器/更新文档中的旧运行时反推算法；
- 仅结构导入：保留旧 tick 等效 beat，明确标记时间可能需要人工校准。

默认使用兼容模式，不要使用旧版示例中简单的 	ick = beat 作为最终准确时序。

### 3. Offset

旧版 offset 单位为 tick，转换为毫秒：

`	ext
oldOffsetMs = oldOffsetTicks * 50
`

但最新转换器更新文档明确指出旧版 offset 与 Reborn/RhythMC 3.0 方向相反：

`	ext
rhythmc3OffsetMs = -oldOffsetTicks * 50
`

这一规则必须集中在 LegacyTimingAdapter，并通过样例运行时验证；不要散落在 UI 或 note 转换逻辑中。

### 4. 音符类型

官方映射：

`	ext
NOTE_CLICK / NOTE_LEFT_CLICK / NOTE_RIGHT_CLICK -> TAP (0)
NOTE_LOOK                                      -> LOOK (1)
NOTE_HOLD                                      -> HOLD (2)
NOTE_DO_NOT_CLICK                              -> DODGE (3)
`

旧 HOLD 只有起始位置和 length，官方转换器会将其展开为多个相同 holdGroup 的节点；Maker 若支持完整 3.0 模型，应保留为一个 HOLD 语义或生成与 3.0 编辑器兼容的节点序列，不能只导入首节点。

### 5. 轨道与位置

旧版是 rames + notes，通常没有 3.0 多轨道结构。建议：

- 默认生成一个 	rack-0 / track id 0；
- 旧 pos[x,y] 映射为 3.0 pos[x,y,0]；
- 缺失 scale 使用 [1,1,1]；
- 缺失 otation 使用 [0,0,0]；
- holdGroup 为普通音符 -1；
- 生成完整默认的 speed/transform/rotate/scale 事件表，不能只写空数组，除非 3.0 反序列化器确认允许空表。

### 6. 旧效果

按官方转换器映射：

- HOLOGRAM -> HOLOGRAM
- REMOVEHOLOGRAM -> REMOVE_HOLOGRAM
- MESSAGE -> MESSAGE
- EFFECT -> EFFECT
- CLREFFECT -> CLEAR_EFFECT
- TIME -> TIME
- WEATHER -> WEATHER
- COLOR -> GLOW_COLOR
- ARENA -> ARENA
- VISIBLE -> HIDE_NOTES（逻辑取反）
- TEXT -> TEXT_DISPLAY
- TRANSFORMATIONS -> TEXT_DISPLAY_EFFECT
- SPEED、JUDGEDOT：无可靠 3.0 对应，导入报告中列为丢弃/需人工重做

### 7. 场景/Arena

旧版 initial-arena 只转换为 3.0 meta.initialArena 引用。场景本体不在 .rmcc 中：

- 旧 renas/*.yml 转为 3.0 arena 元数据；
- 对应 .schem 结构需要一起导入/复制；
- 若 Maker 仅导入谱面，不应伪造场景已经存在；
- 缺失 arena 时显示警告，不应悄悄改为默认场景。

## 导入后本地保存

导入不应覆盖原始文件。建议：

`	ext
rhythmc maker/
├── manifests/<newId>.json
├── charts/<newId>.rmcc 或内部 chart document
├── audio/<newId>.<ext>
├── imports/<timestamp>-source.zip
└── import-reports/<newId>.json
`

import-report 记录：源格式、源文件、目标难度、转换器版本、offset 换算、丢弃字段、警告、原始 hash。

## 一期验收标准

- 从 3.0 zip 导入 manifest.yml + world.rmcc，能选择难度并显示 BPM、谱面 offset、音符数量。
