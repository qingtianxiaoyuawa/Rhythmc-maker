# RhythMC Maker Flashback 风格 UI 改造规划

- 日期：2026-10-01
- Planner 职责：本轮仅完成 UI 分析与实现规划，不修改源码、不编译、不测试、不部署。
- 用户目标：将当前 RhythMC Maker 从拥挤的页面式 UI 改造成接近 Flashback 的 Minecraft 编辑器工作台 UI。
- 参考对象：`Flashback-0.39.10-for-MC1.21.11.jar` 与用户提供的三张 Flashback 截图。

## 项目与参考实现确认

- RhythMC Maker 当前 Minecraft 版本为 1.21.11，Fabric 客户端模组，现有 UI 同时使用 Owo UI 和自建 ImGui 运行时。
- 当前主要 UI 外壳位于 `src/main/java/cn/frkovo/rhythmcmaker/client/RhythmcScreen.java`。
- 当前页面通常通过 `BaseOwoScreen`、`FlowLayout`、固定宽度面板和显式垂直滚动容器组成，适合表单页，不适合持续编辑工作台。
- 当前 ImGui 运行时位于 `src/main/java/cn/frkovo/rhythmcmaker/client/ImGuiRuntime.java`，已经具备字体、输入、剪贴板、滚动和 Minecraft framebuffer 绘制基础。
- Flashback JAR 已确认是 Fabric 1.21.11 模组，包含自定义 ImGui 编辑器 UI、时间轴、导出设置、轨道和关键帧相关类；本规划只借鉴可见交互和布局原则，不复制其专有源码、资源或实现。

## 截图中应继承的设计特征

1. **工作台而不是弹窗集合**
   - 顶部是一条非常薄的全局菜单栏。
   - 中央区域始终保持场景/游戏画面作为主视觉焦点。
   - 右侧是固定宽度、可滚动的属性与显示控制栏。
   - 底部是常驻时间轴与轨道区。
   - 导出、设置等复杂操作才使用中央小型模态窗口。

2. **高信息密度但低视觉噪音**
   - 深灰/近黑背景，面板之间使用细边界和分隔线，而不是大量圆角卡片。
   - 控件高度统一，标签左对齐，复选框、下拉框、数字输入框使用同一视觉规范。
   - 只有选中、悬停、警告和播放状态使用高亮色。
   - 不让每个功能都拥有独立大面板；使用分组标题和细分隔线表达层级。

3. **分区可收起、内容按上下文显示**
   - 右侧面板按“界面、世界、覆盖、其他”等类别折叠。
   - 轨道行只显示必要的信息，详细参数放到右侧检查器。
   - 没有选中对象时，右侧显示场景/工程级属性；选中音符、特效、相机或场景对象后切换为对象属性。

4. **时间轴是主编辑区之一**
   - 底部时间尺、播放控制、当前时间指示线、轨道列表和关键帧/事件标记需要形成完整组件。
   - 时间轴不能再被普通表单页面包裹；它应当是固定在窗口底部的独立区域。
   - 时间轴高度、缩放和滚动应独立于右侧属性面板。

## 当前 UI 的根本问题判断

- 当前 `RhythmcScreen` 将不同功能都建模为独立 Owo 表单页，导致用户需要在多个页面之间跳转，无法形成“场景 + 时间轴 + 属性”的持续编辑上下文。
- `panel(int width)`、`panelFill()` 和固定页面尺寸会把内容压缩到中间窄面板；当中文、图片、长表单或滚动内容出现时，容易产生嵌套容器、重复边框和拥挤布局。
- 当前 UI 缺少统一的编辑器区域模型，工具栏、预览、检查器和时间轴之间没有稳定的空间关系。
- 当前 ImGui 运行时主要承担渲染与输入基础，尚未形成一套编辑器级布局组件、主题变量和面板生命周期。

## 推荐总体方案

### 方案结论

采用“**ImGui 编辑器工作台 + Owo 模态/辅助页面并存**”的渐进式方案：

- 新建一个主编辑器工作台屏幕，负责 Flashback 风格的顶部栏、中央预览、右侧检查器和底部时间轴。
- 保留 Owo UI 用于文件选择、导入、导出、创建谱面、确认删除等非持续编辑的模态页面。
- 不建议一次性把所有已有 Owo 页面重写成 ImGui；先重做用户每天持续使用的主 Maker 页面，再逐步迁移高频编辑面板。
- 不建议直接启用 ImGui 多视口或系统窗口；当前运行时已明确关闭 ViewportsEnable，应继续使用 Minecraft 窗口内的固定区域布局。

### 目标布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部菜单：文件 | 编辑 | 播放 | 场景 | 视图 | 导入/导出 | 帮助 │
├───────────────┬───────────────────────────────┬──────────────┤
│ 可选左侧资源栏 │        中央场景/游戏预览        │ 右侧检查器    │
│ 轨道/对象树     │                               │ 分组属性      │
│ 可收起          │                               │ 可滚动        │
├───────────────┴───────────────────────────────┴──────────────┤
│ 播放控制 | 时间尺 | 当前时间 | 缩放 | 相机/延时/特效轨道       │
│ 轨道列表                         关键帧与事件                 │
└──────────────────────────────────────────────────────────────┘
```

默认不显示左侧栏，优先把空间让给中央预览；用户点击“轨道/资源”后再展开左侧栏。这样更接近参考图中“中央画面 + 右侧控制 + 底部时间轴”的核心构图。

## UI 设计规范建议

### 尺寸

- 顶部菜单栏：20–24 px。
- 右侧检查器：260–310 px，窄屏时允许缩到 230 px；不使用固定居中小窗。
- 底部时间轴：默认 180–230 px，可拖拽调整到 140–360 px。
- 左侧资源/轨道栏：默认隐藏；展开宽度 190–240 px。
- 普通控件高度：20–24 px；紧凑时间轴控件：18–22 px。
- 面板内边距：6–8 px；同组控件间距：3–5 px；大组之间只使用 8–12 px 和分隔线。

### 颜色

- 背景：近黑蓝灰，例如 `#17181E`、`#202128`。
- 面板：比背景略亮的灰蓝，例如 `#252633`。
- 输入框/轨道：`#2B2C39`。
- 边界线：低对比度灰色，例如 `#555762`。
- 主高亮：Flashback 风格的蓝色，例如 `#168BE8`；只用于选中、播放、拖拽和确认按钮。
- 警告：琥珀色；错误：红色；成功状态：绿色。
- 避免当前大量高对比蓝色边框和大块卡片同时出现。

### 字体与文本

- 继续使用已内置的 Misans 字体与中文 glyph 范围。
- 统一字号层级：菜单/普通标签、分组标题、主标题三档即可。
- 不使用大标题占据编辑区域；场景标题、状态提示尽量放在顶部或预览覆盖层。
- 标签宽度固定或按列对齐，数值输入与下拉框尽量右对齐，避免中文标签和控件互相挤压。

## 模块化实现拆分

### Phase 1：工作台外壳

目标：先改变整体构图，不改变谱面、场景和特效业务逻辑。

建议新增或重构的职责：

- `EditorWorkspaceScreen`：主编辑器屏幕生命周期、区域尺寸和输入焦点。
- `EditorTheme`：颜色、间距、字号、边框和控件状态的集中定义。
- `EditorLayoutState`：顶部栏、左侧栏、右侧栏、时间轴的显隐与尺寸。
- `EditorPanel` 或等价轻量面板绘制工具：统一面板标题、折叠箭头、边框和滚动区域。

涉及现有入口：

- `RhythmcScreen.java`：保留通用 Owo 辅助页面能力，不再承担主工作台布局。
- `ImGuiRuntime.java`：提供每帧绘制上下文、字体与输入，不把业务状态塞进运行时。
- `RhythmcMakerClient.java`：主入口切换到新的工作台屏幕，保留 HUD/sidebar 逻辑。

验收：打开 Maker 后直接看到完整工作台；中央预览占最大面积；右侧和底部区域稳定存在；没有多层嵌套大卡片。

### Phase 2：顶部菜单与全局工具栏

内容：

- 文件：新建、打开、保存、另存为、导入、导出。
- 编辑：撤销、重做、复制、粘贴、删除。
- 播放：播放/暂停、停止、从当前时间播放、循环。
- 视图：显示/隐藏右侧检查器、左侧栏、时间轴、网格和辅助线。
- 场景：场景切换、场景编辑、重置场景。

实现原则：

- 菜单栏只展示动作，不塞入长表单。
- 复杂配置打开现有 Owo 模态页面或新的紧凑 ImGui 模态窗口。
- 菜单项需要复用现有命令方法，不能在 UI 层重复实现保存、播放和导出逻辑。

### Phase 3：中央预览区

内容：

- 复用现有 Minecraft framebuffer/场景渲染结果。
- 在预览区覆盖当前时间、播放状态、选中对象和必要的辅助线。
- 预览区默认无厚重边框，只保留细边界。
- 空场景或未加载谱面时显示轻量空状态，不使用大块错误卡片。

注意：

- 预览区与 ImGui 绘制顺序必须继续遵守当前已修复的 Minecraft 最终 framebuffer 合成顺序。
- 不把预览截图复制成 UI 纹理再绘制，优先沿用现有 framebuffer 方案，避免性能和同步问题。

### Phase 4：右侧检查器

分三类上下文：

1. **工程/谱面属性**：谱面名称、作者、BPM、offset、音频、播放设置。
2. **选中对象属性**：音符、特效、相机点、场景对象、轨道事件。
3. **视图/世界属性**：天气、时间、雾、粒子、实体、渲染辅助线等。

交互：

- 使用折叠分组；同一时间只展开最相关的组。
- 数值使用紧凑输入框，单位直接显示在右侧，不重复写进标签。
- 颜色、物品、音频等复杂值使用小型选择器或模态窗口，不在右侧堆叠全部选项。
- 右侧内容必须只有一个明确的垂直滚动容器，禁止外层窗口、内容 child、业务页同时滚动。

### Phase 5：底部时间轴

建议拆成独立组件：

- `TimelineToolbar`：播放控制、当前时间、BPM/拍号显示、时间轴缩放。
- `TimelineRuler`：秒/Beat 刻度、网格、播放头。
- `TrackList`：相机、延时、音符、特效、场景等轨道。
- `TimelineCanvas`：关键帧、音符点、特效事件和选区绘制。
- `TimelineSelectionModel`：选择、框选、拖动、复制、删除。

重要数据规则：

- 时间轴内部主坐标使用 Beat，与现有谱面模型保持一致。
- 显示秒数只作为辅助标尺；BPM 分段、offset 和速度事件必须通过现有统一时间映射计算。
- 时间轴拖拽、缩放和播放头移动不能通过帧数推导音频时间。
- 仅在用户明确修改数据时触发保存/脏状态更新，拖动过程避免每帧完整保存整张谱面。

### Phase 6：逐步迁移现有页面

优先级：

1. 主谱面编辑页面和时间轴。
2. 音符/特效选中后的右侧属性。
3. 场景/相机轨道。
4. 播放设置和导出窗口。
5. 创建、导入、文件选择、删除确认等低频页面保持 Owo。

## 现有功能复用要求

- 不重写 `ClientChartAccess`、播放会话、谱面序列化、场景存储和导入导出业务。
- UI 层只调用现有命令/访问器，避免形成第二套谱面状态。
- 保持 `.rmcc`、`.rmcd`、`.schem` 的语义不变。
- 保持 beat 作为编辑时间域，毫秒仅在音频和播放边界使用。
- 保留已有输入修复：中文 codepoint、剪贴板、Ctrl+A/C/V/X、Backspace、Delete、按键重复和修饰键同步。
- 保留当前 framebuffer 合成修复、ImGui 字体资源和单一滚动容器原则。

## 不建议的方案

- 不建议把 Flashback 的整套类直接反编译复制到 Maker。
- 不建议继续在 `PlaceholderScreen` 中无限增加纵向表单来模拟工作台。
- 不建议所有面板都使用固定居中宽度；工作台必须跟随窗口尺寸调整。
- 不建议第一阶段同时重构业务模型、时间轴算法和 UI 渲染；先建立稳定布局与视觉系统。
- 不建议启用多个 ImGui viewport、操作系统级子窗口或依赖外部 UI 库。
- 不建议用大量图标替代中文标签；首版应优先保证功能可理解。

## 实现方任务清单

1. 检查当前 Maker 主界面入口和已有业务操作映射，列出可直接复用的播放、保存、导入、导出、场景和轨道方法。
2. 新增工作台屏幕与布局状态对象，先实现顶部栏、中央预览、右侧检查器和底部时间轴空壳。
3. 新增统一主题常量与基础面板/折叠组/控件绘制函数，删除主工作台对旧 `panel()` 嵌套卡片的依赖。
4. 将现有页面中的谱面、特效、场景和相机信息接入右侧检查器，不修改底层数据结构。
5. 将现有音符/特效/相机/延时列表接入底部轨道显示，先完成只读定位，再增加选择和编辑。
6. 接入菜单动作和现有 Owo 模态页面，确保菜单不会重复创建业务逻辑。
7. 加入窗口尺寸变化、窄屏降级、面板折叠、时间轴缩放和滚轮焦点处理。
8. 在实现完成后由编译合作方执行构建、启动游戏和截图验收；Planner 不承担这些执行工作。

## 验收标准

### 视觉

- 第一眼构图接近 Flashback：薄顶部栏、中央预览、右侧检查器、底部时间轴。
- 主区域不再是多个纵向堆叠的大卡片。
- 右侧控件紧凑、分组清晰，长内容只有一个滚动条。
- 中文和英文清晰，字号层级稳定，控件不互相挤压。
- 窗口缩放后不出现明显裁剪、重叠或空白失衡。

### 交互

- 播放、暂停、停止、拖动播放头和从当前时间播放保持原有语义。
- 右侧修改选中对象会更新现有模型，保存、导出和撤销边界明确。
- 时间轴滚轮只作用于时间轴；右侧滚轮只作用于检查器；预览区保留 Minecraft 相机/鼠标行为。
- 面板隐藏/展开不会丢失选中对象和播放状态。
- 复杂设置仍可通过现有导入、导出和确认窗口完成。

### 性能与稳定性

- 每帧 UI 绘制不执行完整谱面序列化、磁盘读写或昂贵的实体扫描。
- 时间轴渲染对远离视口的事件进行可见区域裁剪。
- 长谱面不因一次性创建全部时间轴标记而卡顿；必要时采用采样、分页或视口裁剪。
- ImGui frame、Minecraft framebuffer 和输入转发的现有生命周期不被破坏。

## 建议执行顺序

1. 先只实现工作台四区域空壳和主题，不接复杂业务。
2. 接入现有播放控制与时间状态，验证主布局和输入焦点。
3. 接入只读时间轴与右侧只读检查器，确认信息层级。
4. 接入对象选择、属性编辑和保存脏状态。
5. 最后迁移导出/设置等模态交互和高级可见性选项。

## 本轮结论

当前最合适的方向不是继续微调 Owo 页面间距，而是建立一个独立的编辑器工作台外壳。Flashback 的核心可借鉴点是空间分区、持续预览、常驻时间轴和上下文检查器；颜色、字体和控件视觉可复用其简洁暗色风格，但业务模型、文件格式、播放链路和 Minecraft 渲染边界必须保持 RhythMC Maker 自身实现。
