# 补丁包装器修复记录

## 问题
PowerShell 管道输入补丁时，当前 `apply_patch.bat` 只使用 `%*` 转发命令行参数，没有读取标准输入，导致 Codex 报错：`--codex-run-as-apply-patch requires a UTF-8 PATCH argument`。

## 修复
修改 Codex 临时补丁包装器：
- 无命令行参数时，使用 PowerShell `[Console]::In.ReadToEnd()` 读取管道中的 UTF-8 补丁，再以单个 PATCH 参数传递给 `codex.exe --codex-run-as-apply-patch`。
- 有命令行参数时，保持原来的参数转发行为。
- 同步修复 `apply_patch.bat` 和 `applypatch.bat`。

## 验证
- PowerShell here-string 管道输入实际补丁：通过，文件从 `before` 更新为 `after`，再更新为 `final`。
- 原有直接 PATCH 参数调用：通过，文件从 `final` 更新为 `argument`。
- 临时探针文件已清理。
- 未修改 RhythMC Maker 工程源码。
- 未编译或部署 JAR；本次修复仅涉及本地 Codex 补丁包装器。

## 注意
该包装器位于当前 Codex 会话的临时目录：
`C:\Users\28585\.codex\tmp\arg0\codex-arg0lnHhzZ`
如果 Codex 会话重建并生成新的 `arg0` 目录，需要将同样的 stdin 兼容逻辑同步到新包装器。
